# Contract: 계정 관리 API (초안)

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-10-07 | **상태**: `가안`

> 화면(React)과 서버가 주고받는 **요청과 응답의 약속**입니다. 주소, 필드 이름, 상태 코드는 모두 `가안`이고, 팀의 `API 명세서` 단계에서 다른 기능과 함께 맞춥니다.
> 화면에 보여 줄 문구는 [`docs/상세/02-계정관리.md`](../../../docs/상세/02-계정관리.md)의 `안내 문구` 표를 **그대로** 씁니다. 같은 규칙을 쓰는 닉네임·비밀번호 문구는 [`docs/상세/01-인증-인가.md`](../../../docs/상세/01-인증-인가.md)의 `안내 문구` 표에서 그대로 가져왔고 `(상세/01)`로 표시했습니다. (문구를 바꾸면 그 표를 먼저 고칩니다.) 두 표 어디에도 없는 문구는 `※`로 표시했습니다.
> 공통 약속(요청 모양, CSRF, 오류 모양, `401 UNAUTHENTICATED`)은 [`001`의 계약](../../001-member-signup-login/contracts/auth-api.md)을 그대로 따르고 여기서는 다른 점만 적습니다.

## 공통 약속

### 요청

- 본문은 JSON(`Content-Type: application/json`)이다.
- **변경 요청(PATCH, POST)** 은 CSRF 토큰을 헤더에 싣는다. 토큰은 `001`의 `GET /api/auth/csrf`로 받는다. (NF-11: 비밀번호 변경 같은 동작이 다른 사이트의 요청으로 실행되지 않게)
- 이 문서의 모든 주소는 **로그인해야** 부를 수 있다.
- **주소에 회원 번호가 없다.** 서버는 세션의 회원(`users_id`)만 다룬다. 그래서 다른 회원의 마이페이지를 부를 방법이 없다. (FR-002, research B-1)
- **비밀번호(현재, 새, 확인, 탈퇴)는 응답과 로그에 넣지 않는다.** 오류 응답에도 입력값을 되돌려 주지 않는다. (NF-01)

### 로그인하지 않았을 때 (모든 주소 공통)

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 401 | `UNAUTHENTICATED` | ※ 로그인이 필요합니다 (`001`에서 이미 `※`로 둔 문구) | FR-002 |

화면은 `001` 계약 9의 약속대로 하려던 화면을 기억하고 로그인 창을 띄운 뒤, 로그인하면 돌아온다. 비밀번호를 바꾼 뒤 **다른 기기**에서 온 요청과 **탈퇴한 뒤**의 요청도 이 응답을 받는다. (FR-020, FR-027)

### 오류 응답 (공통 모양)

`001`과 같다. `code`(영문 이름), `message`(화면에 그대로 보여 줄 한글 문구), `fieldErrors`(칸마다 어긴 규칙). 서버 내부 정보는 넣지 않는다. (NF-06)

### 요청 검사 순서 (가안)

1. 로그인했는지 (`401`)
2. 형식 검사 (비어 있음, 길이, 허용 글자, 확인 일치) — 비밀번호를 **비교하기 전에** 한다. 형식이 틀린 요청은 실패 횟수에 넣지 않는다
3. 상태 검사 (잠금)
4. 비밀번호 비교 (틀리면 실패 횟수 `+1`)
5. 중복·같은 값 검사
6. 처리

## 1. `GET /api/account` — 내 정보 보기

| 항목 | 내용 |
|---|---|
| 연결 | FR-001 ~ FR-004, FR-012 |
| 요청 | 없음 |
| 성공 | `200` (아래) |

```json
{
  "email": "a@b.com",
  "nickname": "철수",
  "intro": "",
  "joinedAt": "2026-10-07T09:00:00+09:00",
  "blog": { "id": 1 }
}
```

- `joinedAt`은 `users.created_at`이다. 화면이 날짜로 보여 준다. (FR-004)
- `intro`가 비어 있으면 빈 문자열로 준다. (가안)
- `blog.id`는 "내 블로그" 바로가기용이다. 블로그 주소의 모양은 `003`의 계약이 정하면 그것으로 바꾼다. (FR-003)
- 프로필 사진 필드는 없다. (FR-012)

## 2. `PATCH /api/account/profile` — 내 정보 저장

| 항목 | 내용 |
|---|---|
| 연결 | FR-005 ~ FR-010, FR-029 |
| 요청 | `{ "nickname": "철수", "intro": "안녕하세요" }` |
| 성공 | `200` — `{ "message": "저장했습니다", "nickname": "철수", "intro": "안녕하세요" }` |

**동작**

1. 두 칸을 서버가 검사한다. 닉네임은 `001`과 같은 규칙, 소개는 0~100자. (FR-007, FR-008)
2. 닉네임 중복은 **탈퇴하지 않은 다른 회원** 중에서 소문자로 비교한다. 내 닉네임 그대로는 중복이 아니다. (FR-007)
3. `users`의 `nickname`, `intro`만 고친다. **`email`이 요청에 들어 있어도 무시한다.** (FR-005)
4. 값이 지금과 같아도 오류로 보지 않고 `200`을 준다. 저장 버튼을 잠그는 것은 화면의 일이다. (FR-009)
5. 성공하면 화면은 바뀐 값을 내 정보에 보여 주고, 위쪽에 보이는 닉네임을 위해 `GET /api/auth/me`를 다시 부른다.

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | (칸마다 `fieldErrors`로 아래 문구) | FR-007, FR-008, FR-010 |
| 409 | `NICKNAME_ALREADY_USED` | 이미 사용 중인 닉네임입니다 (상세/01) | FR-007 |

`VALIDATION_FAILED`의 칸별 문구:

| `field` | `message` |
|---|---|
| `nickname` | 닉네임은 한글, 영문, 숫자로 2~10자여야 합니다 (상세/01) |
| `intro` | ※ 소개는 100자 이하로 입력해 주세요 |

> `intro` 문구는 `안내 문구` 표에 없는 **새 문구**입니다. 필요하면 `상세/02` 표에 먼저 더합니다. (가안)

`NICKNAME_ALREADY_USED`도 `fieldErrors`에 `nickname` 칸으로 넣어서 칸 아래에 보이게 한다. (FR-010)

## 3. `POST /api/account/password` — 비밀번호 변경

| 항목 | 내용 |
|---|---|
| 연결 | FR-013 ~ FR-020, FR-029 |
| 요청 | `{ "currentPassword": "…", "newPassword": "…", "newPasswordConfirm": "…" }` |
| 성공 | `200` — `{ "message": "비밀번호를 변경했습니다" }` |

**동작**

1. 세 칸이 모두 있는지, 새 비밀번호가 규칙에 맞는지, 확인과 같은지 검사한다. (FR-013, FR-015, FR-017)
2. 계정이 잠겨 있으면 비밀번호를 비교하지 않고 거절한다. 남은 시간을 알려 준다. (FR-018)
3. 현재 비밀번호를 저장된 해시와 비교한다. 틀리면 **로그인 실패와 같은 칸**의 횟수를 올리고, 5회째에 10분 동안 잠근다. (FR-014, FR-018) 맞으면 횟수를 0으로 할지는 `research.md` D-4.
4. 새 비밀번호가 현재 비밀번호와 같으면 거절한다. (FR-016)
5. 새 비밀번호를 BCrypt 해시로 저장한다. (CF-01-8, NF-01)
6. **지금 세션을 뺀** 내 세션을 모두 지운다. 지금 기기는 로그인이 유지된다. (FR-020)
7. (`D-6`에서 넣기로 하면) 가입 이메일로 알림 메일을 보낸다. 실패해도 변경은 되돌리지 않는다. (FR-021)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | (칸마다 `fieldErrors`로 아래 문구) | FR-013, FR-015, FR-017 |
| 400 | `CURRENT_PASSWORD_MISMATCH` | 현재 비밀번호가 올바르지 않습니다 | FR-014 |
| 400 | `PASSWORD_SAME_AS_CURRENT` | 현재 비밀번호와 다른 값을 입력해 주세요 | FR-016 |
| 423 | `ACCOUNT_LOCKED` | 로그인 시도가 5회 실패해 잠겼습니다. {N}분 뒤에 다시 시도해 주세요 (상세/01. 이 상황에 맞는 문구는 `research.md` D-3에서 정함) | FR-018 |

- **`CURRENT_PASSWORD_MISMATCH`는 `401`이 아니다.** `401`은 "로그인하지 않았음"이라 화면이 로그인 창을 띄우기 때문이다. (research B-2)
- `CURRENT_PASSWORD_MISMATCH`는 `fieldErrors`에 `currentPassword` 칸으로, `PASSWORD_SAME_AS_CURRENT`는 `newPassword` 칸으로 넣는다.
- `ACCOUNT_LOCKED`에는 남은 시간(초)을 `retryAfterSeconds`로 함께 준다. 화면이 `{N}`을 올림한 분으로 보여 준다. (`001`과 같음) **5번째로 틀린 그 요청의 응답**도 이것이다.
- 응답에는 몇 번 더 틀리면 잠기는지를 넣지 않는다. (CF-02-8과 같은 취지)

`VALIDATION_FAILED`의 칸별 문구:

| `field` | 상황 | `message` |
|---|---|---|
| `currentPassword` | 비어 있음 | ※ 현재 비밀번호를 입력해 주세요 |
| `newPassword` | 비어 있음 또는 규칙 위반 | 비밀번호는 영문, 숫자, 특수문자를 포함해 8~20자로 입력해 주세요 (상세/01) |
| `newPasswordConfirm` | 비어 있음 또는 다름 | 비밀번호가 일치하지 않습니다 (상세/01) |

## 4. `POST /api/account/withdrawal` — 회원 탈퇴

| 항목 | 내용 |
|---|---|
| 연결 | FR-022 ~ FR-029 |
| 요청 | `{ "password": "…", "agreed": true }` |
| 성공 | `200` — `{ "message": "탈퇴가 완료되었습니다" }` + 세션 쿠키 만료 |

**동작**

1. 화면은 안내(되돌릴 수 없음, 삭제되는 것, 남는 것)를 보여 주고, 체크해야 `탈퇴하기`를 누를 수 있게 하며, 누르면 "정말 탈퇴하시겠습니까? 이 작업은 되돌릴 수 없습니다"를 묻는다. **확인했을 때만 이 요청을 보낸다.** 취소하면 아무 요청도 보내지 않는다. (FR-023, FR-025, FR-026)
2. 서버는 `password`가 있는지, `agreed`가 참인지 검사한다. (FR-025의 보조)
3. 잠겨 있으면 비교하지 않고 거절한다. (FR-018, FR-022)
4. 비밀번호를 비교한다. 틀리면 3번 계약과 **같은 칸**의 횟수를 올린다. (FR-022)
5. 한 트랜잭션으로 내 블로그·글·분류·내 블로그 안의 댓글·좋아요를 지우고, 다른 사람 글에 단 댓글은 남기고, 회원 줄에 탈퇴 표시를 하며 **개인정보를 알아볼 수 없게 바꾼다**(이메일, 비밀번호, 닉네임, 소개). 순서는 [data-model.md](../data-model.md) 3. (FR-024, FR-030)
6. 내 세션을 **모두** 지우고 쿠키를 만료시킨다. (FR-027)
7. 화면은 첫 화면으로 가서 응답의 문구 "탈퇴가 완료되었습니다"를 보여 준다. (FR-027)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | `password` 칸: ※ 비밀번호를 입력해 주세요 / `agreed` 칸: ※ 탈퇴 안내를 확인해 주세요 | FR-022, FR-025 |
| 400 | `CURRENT_PASSWORD_MISMATCH` | 현재 비밀번호가 올바르지 않습니다 | FR-022 |
| 423 | `ACCOUNT_LOCKED` | 로그인 시도가 5회 실패해 잠겼습니다. {N}분 뒤에 다시 시도해 주세요 (상세/01. 이 상황에 맞는 문구는 `research.md` D-3에서 정함) | FR-022 |
| 409 | `WITHDRAWAL_CONFLICT` | ※ 잠시 뒤 다시 시도해 주세요 (탈퇴하는 동안 다른 기기에서 글을 쓴 경우 등, `research.md` R-3) | FR-024 |

- 비밀번호가 틀리면 **아무것도 지우지 않는다.** (SC-003)
- 같은 탈퇴 요청이 두 번 오면 두 번째는 이미 세션이 없으므로 `401`이다.
- 탈퇴한 사람이 같은 이메일·닉네임으로 다시 가입하는 것은 `001`의 가입 계약 그대로다. 중복 검사가 탈퇴하지 않은 회원만 보므로 가입된다. (FR-028)
