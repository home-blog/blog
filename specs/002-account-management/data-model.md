# Data Model: 계정 관리 (마이페이지)

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-10-07

> 명세의 `Key Entities`(회원, 로그인 상태, 탈퇴 후 남는 댓글)를 **어디에 어떤 모양으로 저장하고, 탈퇴 때 무엇을 하는지** 정리합니다. 모든 내용은 `가안`입니다.
> 이 기능은 **새 표를 만들지 않습니다.** 팀 공통 ERD의 표를 읽고 고치고 지울 뿐입니다. 팀 ERD는 합의 없이 고치지 않으므로, ERD에 없거나 명세와 부딪히는 곳은 `⚠`로 표시하고 **팀에 요청할 것**으로 적었습니다.
> ERD 문법에는 MySQL(`COMMENT`)과 PostgreSQL(`TIMESTAMPTZ`)이 섞여 있습니다. 실제 DDL은 구현할 때 PostgreSQL 기준으로 정리합니다. (`001`과 같음)

> **2026-10-08 정리**: 팀 공통 ERD에는 기본 기능만 요청하기로 했다. 이 문서에서 ⚠로 표시한 것 중 **팀에 요청하는 것은 [`ERD-변경-요청.md`](../../docs/3-설계/ERD-변경-요청.md)의 T-1 ~ T-3뿐**이고, 나머지 칸·인덱스·표 추가는 **내 확장(E-1 ~ E-6)** 으로 내 저장소에서 더한다. 본문의 "팀에 요청"은 이 기준으로 읽는다.

## 한눈에 보기

| 명세의 개념 | 저장 위치 | 이 기능이 하는 일 | 종류 |
|---|---|---|---|
| 회원 | PostgreSQL `users` | 읽기, 닉네임·소개·비밀번호·실패 횟수 고치기, 탈퇴 표시 | 팀 ERD에 있음 (⚠ `001`의 요청이 반영돼야 함) |
| 로그인 상태 | PostgreSQL 세션 표 (프레임워크가 만듦) | 회원 기준으로 찾아 지우기 | 팀 ERD 밖 (`001` data-model 4) |
| 탈퇴 후 남는 댓글 | PostgreSQL `comment` | 그대로 둔다 (작성자 표시는 `D-1`) | 팀 ERD에 있음 (⚠ `D-1`에 따라) |
| 탈퇴로 지우는 것 | `blog`, `category`, `post`, `comment`, `post_like`, `post_tag`, `post_image`, `post_report`, `comment_report`, `blog_daily_stat` | 한 묶음으로 지우기 | 팀 ERD에 있음 (규칙은 `003`, `005`, `006`) |

## 1. 회원 — PostgreSQL `users`

| 칸 | 팀 ERD의 지금 모양 | 이 기능에서 | 관련 FR |
|---|---|---|---|
| `users_id` | BIGINT, 자동 증가, 기본키 | 세션의 이름표. **요청에서 받지 않고 세션에서만** 꺼낸다 | FR-002, FR-029 |
| `email` | VARCHAR(255), NOT NULL, UNIQUE | **읽기만** 한다. 고치는 코드가 없다. ⚠ 탈퇴하지 않은 회원에게만 중복 불가(`001` D-4, 팀 ERD 반영 대기) | FR-004, FR-005, FR-028 |
| `password` | VARCHAR(255), NOT NULL, `BCrypt 해시` | 비밀번호 변경 때 **새 해시로 바꾼다.** 원문은 어디에도 남기지 않는다 | FR-014 ~ 017, FR-022 |
| `nickname` | VARCHAR(20), NOT NULL, UNIQUE | 내 정보 수정 때 바꾼다. 2~10자는 서버가 검사. ⚠ 소문자 비교 + 탈퇴하지 않은 회원에게만 중복 불가(`001` D-4) | FR-004, FR-006, FR-007 |
| `intro` | VARCHAR(100), NULL | 내 정보 수정 때 바꾼다. 0~100자. 비우면 `NULL` (가안). 칸 크기가 명세(100자)와 같다 | FR-004, FR-006, FR-008 |
| `created_at` | TIMESTAMPTZ, NOT NULL | **가입일**로 보여 준다 | FR-004 |
| `deleted_at` | TIMESTAMPTZ, NULL (soft delete) | 탈퇴할 때 탈퇴 시각을 넣는다. 값이 있으면 로그인·중복 검사·마이페이지 대상에서 빠진다 | FR-024, FR-027, FR-028 |
| `failed_login_count` | **없음 ⚠** (`001` D-3에서 추가 요청) | 비밀번호 변경·탈퇴에서 틀리면 **로그인 실패와 같은 칸에** `+1` | FR-018, FR-022 |
| `locked_until` | **없음 ⚠** (`001` D-3에서 추가 요청) | 5회째에 `지금 + 10분`. 잠긴 동안 비밀번호 변경·탈퇴도 막는다 | FR-018, FR-022 |

**프로필 사진 칸은 없다.** 이번 범위에서 만들지 않는다. (FR-012)

### 중복 불가 규칙 (⚠ `001` D-4 결정, 팀 ERD 반영 대기)

- 닉네임: 소문자로 바꾼 값이 같은 **탈퇴하지 않은** 회원은 둘 이상 없다. 닉네임을 바꿀 때 **내 줄은 비교에서 뺀다.** (내 닉네임 그대로, 대소문자만 바꾼 닉네임은 중복이 아니다)
- 이메일: 바꾸지 않으므로 이 기능에서 새로 검사할 것이 없다. 탈퇴한 줄은 규칙에서 빠지므로 **같은 이메일로 다시 가입**할 수 있다. (FR-028)
- DB 규칙이 마지막 방어선이다. 동시에 두 사람이 같은 닉네임으로 바꿔도 한 건만 성공한다. (SC-002)

### 검증 규칙 (서버가 검사, FR-029)

| 입력 | 규칙 | FR |
|---|---|---|
| 닉네임 | 필수. 2~10자, 한글·영문·숫자만. 공백·특수문자 불가. 다른 회원과 중복 불가(대소문자 무시, 나는 제외) | FR-007 |
| 소개 | 0~100자 (글자 단위로 센다, research B-4). 비워도 된다 | FR-008 |
| 이메일 | 받지 않는다 (와도 무시) | FR-005 |
| 현재 비밀번호 | 필수. 저장된 해시와 같아야 한다 | FR-013, FR-014 |
| 새 비밀번호 | 필수. 영문·숫자·특수문자 각 1개 이상, 8~20자, 공백 불가, 허용 특수문자 `! @ # $ % ^ & * ( ) _ + - =`. 현재 비밀번호와 달라야 한다 | FR-013, FR-015, FR-016 |
| 새 비밀번호 확인 | 필수. 새 비밀번호와 같을 것 | FR-013, FR-017 |
| 탈퇴 비밀번호 | 필수. 저장된 해시와 같아야 한다 | FR-022 |
| 탈퇴 안내 확인 (`agreed`) | 참이어야 한다 (화면 검사의 보조) | FR-025 |

값의 길이와 횟수는 [plan.md](plan.md)의 `설정값 목록`에서 바꿀 수 있게 한다. (NF-08)

### 비밀번호 확인 실패와 잠금의 상태 변화 (FR-018, FR-022, SC-006)

`001`의 로그인 잠금 그림과 **같은 칸, 같은 규칙**이다. 다른 점은 "틀림"이 로그인, 비밀번호 변경, 탈퇴 **세 곳에서** 생긴다는 것뿐이다.

```
정상(0회) ──틀림(로그인·변경·탈퇴 어디서든)──▶ 1~4회 ──5번째 틀림──▶ 잠김(locked_until = 지금 + 10분)
    ▲                                           │                         │
    ├──── 로그인 성공 ─────────────────────────┘                         │
    ├──── 비밀번호 변경·탈퇴에서 맞게 입력 (D-4 추천안일 때) ────────────┤ (1~4회에서)
    │                                                                     │
    └──────── 10분이 지난 뒤 다음 시도 때 0으로 되돌림 ◀──────────────────┘
```

- 잠긴 동안은 로그인, 비밀번호 변경, 탈퇴 모두 **비밀번호를 비교하지 않고** 거절하고 남은 시간을 알린다. 이 동안의 시도는 잠금 시간을 늘리지 않는다. (`001`과 같은 해석)
- 잠겨도 **이미 로그인한 세션은 끊지 않는다.** (research R-8)
- `+1`은 DB에서 바로 올린다. 동시에 여러 번 틀려도 정확히 센다. (`001`과 같음)

## 2. 로그인 상태 — PostgreSQL 세션 표

- 표의 모양은 `001` data-model 4와 같다. 이름표(principal)가 `users_id`라서 **"이 회원의 세션 목록"** 을 찾을 수 있다. (research R-2: 구현 때 확인)

| 언제 | 무엇을 지우나 | 남기는 것 | 관련 FR |
|---|---|---|---|
| 비밀번호 변경 성공 | 이름표가 내 `users_id`인 세션 중 **지금 요청의 세션이 아닌 것** 모두 | 지금 세션 (만든 시각과 마지막 사용 시각도 그대로 → 7일·30일 규칙이 이어진다) | FR-020, SC-005 |
| 탈퇴 성공 | 이름표가 내 `users_id`인 세션 **모두** (지금 세션 포함) + 쿠키 만료 | 없음 | FR-027 |

- 지워진 세션으로 온 요청은 로그인하지 않은 것과 같아서 `401 UNAUTHENTICATED`를 받는다. (`001` 약속)
- 세션에는 계속 `users_id`만 있다. 닉네임을 바꿔도 세션을 고칠 일이 없다.

## 3. 탈퇴 — 표마다 하는 일 (FR-024, SC-007)

> 팀 ERD에는 "부모를 지우면 자식도 자동으로 지움(ON DELETE CASCADE)"이 **없습니다.** 그래서 **자식부터** 지웁니다. 모두 **한 트랜잭션**이고, 하나라도 실패하면 전부 취소합니다. (research B-6)
> 아래에서 "내 블로그" = `blog.users_id`가 나인 블로그(한 회원에 하나, `blog.users_id` UNIQUE). "내 글" = 내 블로그의 분류에 속한 글.

| 순서 | 표 | 무엇을 | 명세에서 | 비고 |
|---|---|---|---|---|
| 1 | `post_like` | **내가 누른 좋아요** 모두 | 삭제되는 것: 좋아요 | 다른 사람 글에 누른 것 포함 |
| 2 | `comment_report` | 내 글에 달린 댓글에 대한 신고 | (글 삭제의 결과) | `D-5` |
| 3 | `comment` | 내 글에 달린 댓글 **모두** (내가 쓴 것 + 다른 사람이 쓴 것). 답글(`parent_id`)이 있으므로 답글부터 | 삭제되는 것: 내 블로그 안의 내 댓글 | 다른 사람 댓글도 지워진다 (research R-4, CF-05-15) |
| 4 | `post_like` | 내 글에 다른 사람이 누른 좋아요 | (글 삭제의 결과) | CF-05-15 |
| 5 | `post_tag` | 내 글의 태그 연결 | (글 삭제의 결과) | 태그(`tag`) 자체는 남는다 |
| 6 | `post_image` | 내 글의 이미지 기록 | (글 삭제의 결과) | 파일은 트랜잭션 뒤에 지운다 (research R-7) |
| 7 | `post_report` | 내 글에 대한 신고 | (글 삭제의 결과) | `D-5` |
| 8 | `post` | 내 글 모두 (공개·비공개 모두) | 삭제되는 것: 글 | |
| 9 | `category` | 내 블로그의 분류 모두 (`미분류` 포함) | 삭제되는 것: 분류 | |
| 10 | `blog_daily_stat` | 내 블로그의 일별 통계 | (블로그 삭제의 결과) | `006` |
| 11 | `blog` | 내 블로그 | 삭제되는 것: 내 블로그 | CF-04-4 |
| 12 | `users` | `deleted_at = 지금` (줄은 남긴다). `email` = `deleted-{users_id}@deleted.invalid`, `password` = `!deleted`(맞을 수 없는 값), `nickname` = `탈퇴한사용자{users_id}`, `intro` = NULL | — | `D-1`, `D-2`, FR-030 |
| 13 | 세션 표 | 내 세션 모두 | FR-027 | 위 2번 |

**남기는 것**

| 표 | 무엇을 | 명세에서 | 비고 |
|---|---|---|---|
| `comment` | **다른 사람 글에 단 내 댓글** | 남는 것 | 작성자 표시: `D-1` |
| `post_report`, `comment_report` | **내가 한 신고** | (명세에 없음) | `D-5` 추천안 A일 때 |
| `topic`, `tag` | 공용 목록 | — | 지우지 않는다 |

- 탈퇴 전에 비밀번호 확인(1장의 잠금 규칙)이 먼저 통과해야 한다. 틀리면 아무것도 지우지 않는다. (SC-003)
- 조회수·방문자 중복 방지처럼 Redis에 시간 제한으로 남는 값(`006`)은 저절로 사라지므로 지우지 않는다.

### ⚠ 팀 ERD와 맞춰야 하는 것

| 무엇 | ERD의 지금 모양 | 필요한 것 | 근거 | 요청 |
|---|---|---|---|---|
| 실패 횟수·잠금 칸 | `users`에 없음 | `failed_login_count`, `locked_until` | FR-018, `001` D-3 | `001`에서 이미 요청하기로 함 |
| 이메일·닉네임 중복 불가 | 전체 `UNIQUE`, 대소문자 구분 | 탈퇴하지 않은 회원에게만, 소문자 비교 | FR-007, FR-028, `001` D-4 | `001`에서 이미 요청하기로 함 |
| 남는 댓글의 작성자 | `comment.users_id` NOT NULL | `D-1`이 A면 **변경 없음**. B·C면 NULL 허용으로 변경 | FR-024, CF-18-6 | `D-1` 결정 뒤 |
| 자동 연쇄 삭제 | 없음 | 없어도 된다 (코드가 순서대로 지움). 팀이 원하면 추가 검토 | FR-024 | 요청하지 않음 (가안) |
| `상세/02` `구현 방식`과의 차이 | "작성자 칸을 비워 둔다" | `D-1` 결과에 맞게 고친다. 또 그 표의 삭제 목록에 **좋아요**가 빠져 있다(CF-15-18에는 있음) | CF-15-18 | 문서 수정 (팀 ERD 아님) |

> 참고 (이 기능의 범위 밖, `005`에서 확인): ERD의 `comment`에는 `users_id`, `post_id`에 `UNIQUE(users_id, post_id)` 주석이 있습니다. 이대로라면 한 회원이 한 글에 댓글을 하나만 달 수 있습니다. `005`의 plan에서 확인할 일이지만, `D-1`의 B를 고르면 이 규칙과도 같이 맞춰야 합니다.

### 탈퇴와 재가입의 상태 변화 (FR-027, FR-028, SC-008)

```
활동 중(deleted_at 비어 있음) ──탈퇴(비밀번호 확인 + 체크 + 최종 확인)──▶ 탈퇴함(deleted_at 있음)
        │                                                                     │
        │ 로그인·마이페이지·중복 검사의 대상                                  │ 로그인 불가, 중복 검사에서 빠짐
        │                                                                     │ 다른 사람 글의 댓글만 남음 ("탈퇴한 사용자")
        ▼                                                                     ▼
                         같은 이메일·닉네임으로 가입 ──▶ 새 회원 줄 (새 users_id, 이전 데이터와 연결 없음)
```

- 탈퇴는 되돌리지 않는다. "탈퇴함"에서 "활동 중"으로 가는 길은 없다.
- 새 계정과 옛 데이터는 `users_id`가 달라서 이어지지 않는다. 다만 옛 댓글의 작성자를 **닉네임으로** 보여 주면 새 계정과 헷갈리므로, 반드시 탈퇴 여부로 "탈퇴한 사용자"를 표시한다. (research D-1)
