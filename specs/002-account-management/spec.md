## User Scenarios & Testing *(mandatory)*

### User Story 1 - 마이페이지에서 내 정보 보고 고치기 (Priority: P1)

로그인한 회원이 마이페이지에서 내 이메일, 닉네임, 소개, 가입일을 보고, 닉네임과 소개를 고친다. 내 블로그로 바로 갈 수도 있다. 로그인하지 않은 사람이나 다른 회원은 내 마이페이지를 볼 수 없다.

```
마이페이지 열기 → 내 정보(이메일·닉네임·소개·가입일) 확인
→ 닉네임·소개 고치기 → 저장 → "저장했습니다"
```

**Why this priority**: 비밀번호 변경과 회원 탈퇴도 모두 마이페이지에서 시작한다. 로그인한 회원이 "내 계정"을 확인하고 관리하는 출발점이다.

**Independent Test**: 로그인한 회원이 마이페이지를 열어 내 정보가 보이는지, 소개를 고쳐 저장하면 "저장했습니다"가 보이는지, 로그아웃한 상태에서는 마이페이지 대신 로그인 창이 뜨는지 확인한다. 이것만으로 "내 정보를 보고 고칠 수 있다"는 가치가 전달된다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원일 때, **When** 마이페이지를 열면, **Then** 내 정보(이메일, 닉네임, 소개, 가입일), 비밀번호 변경, 회원 탈퇴, 내 블로그 바로가기가 보이고 프로필 사진을 올리는 칸은 없다.
2. **Given** 로그인하지 않았을 때, **When** 마이페이지를 누르면, **Then** 로그인 창이 뜨고, 로그인하면 마이페이지로 돌아간다.
3. **Given** 로그인한 회원일 때, **When** 다른 회원의 마이페이지를 보려고 하면(화면을 거치지 않은 요청 포함), **Then** 볼 수 없다.
4. **Given** 내 정보를 보고 있을 때, **When** 이메일을 고치려고 하면, **Then** 이메일은 바꿀 수 없다.
5. **Given** 닉네임과 소개가 규칙을 지켰을 때, **When** 저장하면, **Then** "저장했습니다"가 보이고 바뀐 값이 내 정보에 나타난다.
6. **Given** 아무것도 고치지 않았을 때, **When** 저장 버튼을 보면, **Then** 저장 버튼은 눌리지 않는다.
7. **Given** 닉네임을 그대로 두고 소개만 고쳤을 때, **When** 저장하면, **Then** 내 닉네임은 중복으로 보지 않아 저장된다.
8. **Given** 다른 회원이 쓰는 닉네임으로 바꾸거나 소개를 100자보다 길게 썼을 때, **When** 저장하면, **Then** 이유가 그 칸 아래에 보이고 저장되지 않는다.
9. **Given** 닉네임이나 소개를 고치던 중일 때, **When** 저장하지 않고 다른 화면으로 가려고 하면, **Then** "저장하지 않은 내용이 있습니다. 나갈까요?"를 묻는다.
10. **Given** 마이페이지를 보고 있을 때, **When** "내 블로그"를 누르면, **Then** 내 블로그 화면으로 이동한다.

### User Story 2 - 비밀번호 변경 (Priority: P1)

로그인한 회원이 현재 비밀번호를 확인한 뒤 새 비밀번호로 바꾼다. 바꾸면 지금 쓰는 기기는 로그인이 유지되고, 다른 모든 기기는 로그인이 끊긴다.

```
현재 비밀번호 입력 → 새 비밀번호·새 비밀번호 확인 입력 → 변경
→ "비밀번호를 변경했습니다"
```

**Why this priority**: 비밀번호가 남에게 알려졌을 수 있다고 느낄 때 회원이 스스로 계정을 지킬 수 있는 가장 기본적인 방법이다. 다른 기기의 로그인까지 끊어야 효과가 있다.

**Independent Test**: 로그인한 회원이 현재 비밀번호를 맞게, 새 비밀번호를 규칙에 맞게 입력해 바꾼 뒤 새 비밀번호로만 로그인되는지, 두 기기에서 로그인해 둔 상태에서 한 기기에서 바꾸면 다른 기기가 로그아웃되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 현재 비밀번호를 맞게 입력하고 새 비밀번호와 확인이 규칙을 지켰을 때, **When** 변경하면, **Then** "비밀번호를 변경했습니다"가 보이고, 이후 로그인은 새 비밀번호로만 된다.
2. **Given** 현재 비밀번호를 틀리게 입력했을 때, **When** 변경하면, **Then** "현재 비밀번호가 올바르지 않습니다"가 보이고 비밀번호는 바뀌지 않는다.
3. **Given** 새 비밀번호가 현재 비밀번호와 같을 때, **When** 변경하면, **Then** "현재 비밀번호와 다른 값을 입력해 주세요"가 보이고 비밀번호는 바뀌지 않는다.
4. **Given** 새 비밀번호가 비밀번호 규칙을 어겼거나 새 비밀번호 확인과 다를 때, **When** 변경하면, **Then** 이유가 칸 아래에 보이고 비밀번호는 바뀌지 않는다.
5. **Given** 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인 중 하나라도 비어 있을 때, **When** 변경하려고 하면, **Then** 변경되지 않는다.
6. **Given** 같은 계정으로 두 기기에서 로그인해 있을 때, **When** 한 기기에서 비밀번호를 바꾸면, **Then** 바꾼 기기는 로그인이 유지되고, 다른 기기는 다음 요청에서 다시 로그인하도록 안내한다.
7. **Given** 로그인 실패가 이미 쌓여 있는 계정일 때, **When** 비밀번호 변경에서 현재 비밀번호를 틀려 로그인 실패와 합친 연속 횟수가 5회가 되면, **Then** 계정이 10분 동안 잠긴다.

### User Story 3 - 회원 탈퇴 (Priority: P2)

로그인한 회원이 비밀번호를 다시 입력하고, 삭제되는 것과 남는 것을 안내받은 뒤, 두 번의 확인을 거쳐 탈퇴한다. 탈퇴하면 바로 로그아웃되고, 원하면 같은 이메일과 닉네임으로 다시 가입할 수 있다.

```
탈퇴 안내(삭제되는 것·남는 것) 읽고 체크 · 비밀번호 입력 → 탈퇴하기
→ "정말 탈퇴하시겠습니까?" 최종 확인 → "탈퇴가 완료되었습니다"
```

**Why this priority**: 서비스를 쓰는 데 꼭 필요한 기능은 아니지만, 회원이 서비스를 떠날 수 있어야 한다. 되돌릴 수 없는 작업이라 P1(내 정보, 비밀번호 변경)이 끝난 뒤에 더한다.

**Independent Test**: 로그인한 회원이 안내를 읽고 체크한 뒤 비밀번호를 입력해 탈퇴하고, 로그아웃되는지, 내 블로그와 글이 사라지는지, 다른 사람 글에 단 댓글이 "탈퇴한 사용자"로 남는지, 같은 이메일로 다시 가입되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이 탈퇴 화면을 열었을 때, **When** 화면을 보면, **Then** 되돌릴 수 없다는 것, 삭제되는 것(내 블로그, 글, 분류, 내가 쓴 댓글 중 내 블로그 안의 것, 좋아요), 남는 것(다른 사람 글에 단 댓글, 작성자는 "탈퇴한 사용자"로 표시)이 보인다.
2. **Given** 안내를 읽었다는 체크를 하지 않았을 때, **When** `탈퇴하기`를 누르려고 하면, **Then** 눌리지 않는다.
3. **Given** 안내를 읽었다는 체크를 하고 비밀번호를 맞게 입력했을 때, **When** `탈퇴하기`를 누르면, **Then** "정말 탈퇴하시겠습니까? 이 작업은 되돌릴 수 없습니다"를 한 번 더 묻는다.
4. **Given** 최종 확인을 묻고 있을 때, **When** 확인하면, **Then** 바로 로그아웃되고 첫 화면에서 "탈퇴가 완료되었습니다"가 보인다.
5. **Given** 최종 확인을 묻고 있을 때, **When** 취소하면, **Then** 탈퇴되지 않고 계정은 그대로다.
6. **Given** 비밀번호를 틀리게 입력했을 때, **When** 탈퇴하려고 하면(화면을 거치지 않은 요청 포함), **Then** "현재 비밀번호가 올바르지 않습니다"가 보이고 탈퇴되지 않으며, 틀린 횟수는 로그인 실패 횟수와 합산된다.
7. **Given** 내 블로그, 글, 분류가 있고 다른 사람 글에 단 댓글이 있는 회원일 때, **When** 탈퇴하면, **Then** 내 블로그, 글, 분류, 내가 쓴 댓글 중 내 블로그 안의 것, 좋아요는 삭제되고, 다른 사람 글에 단 댓글은 남으며 작성자가 "탈퇴한 사용자"로 표시된다.
8. **Given** 탈퇴한 사람일 때, **When** 같은 이메일과 닉네임으로 가입하면, **Then** 새 계정으로 가입되고 이전 데이터는 복구되지 않는다.

### User Story 4 - 비밀번호 변경 알림 메일 (선택) (Priority: P3)

비밀번호가 바뀌면 가입 이메일로 알려 주어, 본인이 바꾸지 않았을 때 알아챌 수 있게 한다. 이 기능을 넣을지는 아직 정하지 않았다.

**Why this priority**: 있으면 좋은 보조 장치이고 없어도 비밀번호 변경은 동작한다. 선택 항목이라 가장 마지막에 둔다.

**Independent Test**: 이 기능을 넣기로 한 경우, 비밀번호를 바꾼 뒤 가입 이메일로 알림 메일이 오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이 기능을 넣기로 했을 때, **When** 비밀번호가 바뀌면, **Then** 가입 이메일로 비밀번호가 바뀌었다는 알림이 간다.

---

### Edge Cases

- 로그인하지 않고 **마이페이지 주소로 바로 들어가면?** → 로그인 창을 띄운다. 로그인하면 마이페이지로 돌아간다. (CF-15-2, CF-16-1)
- **다른 회원의 마이페이지 주소로 들어가면?** → 볼 수 없다. (CF-15-2)
- 닉네임을 **그대로 두고 소개만 고치면?** → 내 닉네임은 중복이 아니므로 저장된다. (CF-15-5)
- **다른 회원이 쓰는 닉네임**(영문 대소문자만 달라도 같은 것)으로 바꾸면? → 이유를 칸 아래에 보여 주고 저장하지 않는다.
- 소개를 **비우면?** → 0자도 되므로 저장된다. 100자보다 길면 칸 아래에 알리고 저장하지 않는다.
- 고친 것을 **원래 값으로 되돌리면?** → 바뀐 것이 없는 것이므로 저장 버튼이 눌리지 않는다.
- **이메일을 바꾸고 싶으면?** → 이메일은 로그인 아이디 역할이라 바꿀 수 없다.
- **프로필 사진**은? → 이번 범위에서는 만들지 않는다.
- 새 비밀번호를 **현재 비밀번호와 같게** 쓰면? → "현재 비밀번호와 다른 값을 입력해 주세요"를 보여 준다.
- **현재 비밀번호를 연속 5회 틀리면?** → 로그인에서와 같이 10분 동안 잠근다. 비밀번호 변경과 탈퇴에서 틀린 횟수도 로그인 실패 횟수와 합산한다.
- **잠긴 동안** 올바른 현재 비밀번호를 넣으면? → 비밀번호 변경도 탈퇴도 진행되지 않고, 남은 시간을 안내한다.
- 비밀번호를 바꾼 뒤 **다른 기기에서 쓰고 있었다면?** → 그 기기는 다음 요청에서 다시 로그인하도록 안내한다. 바꾼 기기는 로그인이 유지된다.
- 탈퇴할 때 **안내를 읽었다는 체크를 하지 않으면?** → `탈퇴하기`가 눌리지 않는다.
- **최종 확인에서 취소하면?** → 탈퇴되지 않는다.
- **탈퇴한 사람이 다른 사람 글에 단 댓글**은? → 남고, 작성자는 "탈퇴한 사용자"로 표시한다.
- **탈퇴한 뒤 다시 가입하면?** → 새 계정이며 이전 데이터는 복구할 수 없다.

## Requirements *(mandatory)*

### Functional Requirements

**마이페이지 구성과 접근**

- **FR-001**: 마이페이지는 **내 정보**, **비밀번호 변경**, **회원 탈퇴**, **내 블로그 바로가기**로 구성한다. (CF-15-1)
- **FR-002**: 마이페이지는 로그인한 본인만 볼 수 있다. 로그인하지 않았으면 회원 전용 기능과 같이 로그인 창을 띄우고, 로그인하면 하려던 화면으로 돌아간다. 다른 회원의 마이페이지는 볼 수 없다. (CF-15-2, CF-16-1)
- **FR-003**: "내 블로그"를 누르면 내 블로그 화면으로 이동한다. (CF-15-9)

**내 정보 보기와 수정**

- **FR-004**: 내 정보에는 이메일, 닉네임, 소개, 가입일을 보여 준다. (CF-15-3)
- **FR-005**: 이메일은 로그인 아이디 역할이라 바꿀 수 없다. (CF-15-4)
- **FR-006**: 닉네임과 소개를 바꿀 수 있다. (CF-15-5)
- **FR-007**: 바꾸는 닉네임은 가입할 때와 같은 규칙을 따른다. 2~10자이고 한글, 영문, 숫자만 쓸 수 있으며, 공백과 특수문자는 쓸 수 없고, 다른 회원과 같은 닉네임은 쓸 수 없다. 영문 대소문자는 같은 것으로 본다. 다만 내 닉네임 그대로는 중복이 아니다. (CF-15-5, CF-01-3)
- **FR-008**: 소개는 0~100자이다. (CF-15-5)
- **FR-009**: 바뀐 것이 없으면 저장 버튼이 눌리지 않는다. (CF-15-6)
- **FR-010**: 저장하면 "저장했습니다"를 보여 주고, 오류는 해당 칸 아래에 보여 준다. (CF-15-6)
- **FR-011**: 수정하던 중 다른 화면으로 가려고 하면 "저장하지 않은 내용이 있습니다. 나갈까요?"를 묻는다. (CF-15-7)
- **FR-012**: 프로필 사진은 이번 범위에서 만들지 않는다. (CF-15-8)

**비밀번호 변경**

- **FR-013**: 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력하며, 세 칸 모두 필수이다. (CF-15-10)
- **FR-014**: 현재 비밀번호가 맞아야 진행한다. 틀리면 "현재 비밀번호가 올바르지 않습니다"를 보여 준다. (CF-15-11)
- **FR-015**: 새 비밀번호는 가입할 때와 같은 규칙을 따른다. 영문, 숫자, 특수문자를 각각 1개 이상 포함하고 8~20자여야 하며, 공백은 쓸 수 없고, 쓸 수 있는 특수문자는 `! @ # $ % ^ & * ( ) _ + - =` 이다. (CF-15-12, CF-01-4)
- **FR-016**: 새 비밀번호는 현재 비밀번호와 같으면 안 된다. 같으면 "현재 비밀번호와 다른 값을 입력해 주세요"를 보여 준다. (CF-15-12)
- **FR-017**: 새 비밀번호와 새 비밀번호 확인이 같아야 한다. (CF-15-13)
- **FR-018**: 현재 비밀번호를 틀린 횟수는 로그인 실패 횟수와 **합산**한다. 연속 5회가 되면 로그인에서와 같이 10분 동안 잠근다. (CF-15-14, CF-02-6)
- **FR-019**: 비밀번호를 바꾸면 "비밀번호를 변경했습니다"를 보여 준다. (CF-15-15)
- **FR-020**: 비밀번호를 바꾸면 지금 사용 중인 기기의 로그인은 유지하고, **다른 모든 기기의 로그인은 끊는다.** (CF-15-15)
- **FR-021**: (선택) 비밀번호가 바뀌면 가입 이메일로 알려 준다. 본인이 바꾸지 않았을 때 알아채기 위한 것이다. 넣을지는 아직 정하지 않았다. (CF-15-16)

**회원 탈퇴**

- **FR-022**: 탈퇴하려면 비밀번호를 다시 입력해야 한다. 틀리면 FR-014의 문구("현재 비밀번호가 올바르지 않습니다")를 보여 주고, 틀린 횟수는 FR-018에 따라 로그인 실패 횟수와 합산한다. (CF-15-17)
- **FR-023**: 탈퇴하기 전에 되돌릴 수 없다는 것, **삭제되는 것**(내 블로그, 글, 분류, 내가 쓴 댓글 중 내 블로그 안의 것, 좋아요), **남는 것**(다른 사람 글에 단 댓글, 작성자는 "탈퇴한 사용자"로 표시)을 보여 준다. (CF-15-18)
- **FR-024**: 탈퇴하면 안내한 대로 삭제되는 것은 삭제하고, 남는 것은 남긴다. (CF-15-18)
- **FR-025**: 안내를 읽었다는 체크를 해야 `탈퇴하기`를 누를 수 있다. (CF-15-19)
- **FR-026**: `탈퇴하기`를 누르면 "정말 탈퇴하시겠습니까? 이 작업은 되돌릴 수 없습니다"를 한 번 더 묻는다. (CF-15-19)
- **FR-027**: 탈퇴하면 바로 로그아웃하고, 첫 화면에서 "탈퇴가 완료되었습니다"를 보여 준다. (CF-15-20)
- **FR-028**: 탈퇴한 사람은 같은 이메일과 닉네임으로 **다시 가입할 수 있다.** 새 계정이며 이전 데이터는 복구할 수 없다. (CF-15-21)
- **FR-030**: 탈퇴하면 그 회원의 이메일, 비밀번호, 닉네임, 소개를 **누구였는지 알아볼 수 없는 값으로 바꾸거나 지운다.** 회원 기록 자체는 남은 댓글의 작성자 표시를 위해 남기되, 남은 기록으로 원래 회원을 알아낼 수 없어야 한다. (CF-15-22, 2026-10-08 추가)

**공통**

- **FR-029**: 위의 입력 규칙, 현재 비밀번호 확인, 탈퇴 때의 비밀번호 확인, 마이페이지 접근 제한은 화면 검사와 상관없이, 화면을 거치지 않은 요청에도 똑같이 적용한다. (회원 가입과 로그인의 FR-034와 같은 취지)

### Key Entities *(include if feature involves data)*

- **회원**: 서비스에 가입한 사람. 이메일(바꿀 수 없음), 닉네임, 소개(0~100자), 가입일, 비밀번호(원문은 저장하지 않음), 연속 실패 횟수, 잠금 해제 시각을 가진다. 연속 실패 횟수는 로그인 실패와 비밀번호 확인 실패(비밀번호 변경, 탈퇴)를 합산한다. 가입하면 블로그 하나가 함께 만들어지고, 탈퇴하면 함께 삭제된다.
- **로그인 상태**: 회원이 로그인해 있다는 기록. 로그인한 기기마다 하나씩 있다. 비밀번호를 바꾸면 지금 쓰는 기기의 것만 남고 나머지는 모두 끊어진다. 탈퇴하면 끊어진다.
- **탈퇴 후 남는 댓글**: 탈퇴한 회원이 다른 사람 글에 단 댓글. 댓글은 남고, 작성자는 "탈퇴한 사용자"로 표시한다. 댓글 자체는 다른 기능에서 다룬다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인하지 않은 사람이나 다른 회원이 어떤 회원의 마이페이지(내 정보, 비밀번호 변경, 회원 탈퇴)를 보거나 고친 경우는 0건이다.
- **SC-002**: 이메일이 바뀐 계정은 0개이고, 닉네임을 바꾼 뒤 같은 닉네임(대소문자 무시)을 쓰는 회원이 둘 이상인 경우도 0건이다.
- **SC-003**: 현재 비밀번호(탈퇴할 때는 다시 입력한 비밀번호)를 맞게 입력하지 않고 비밀번호가 바뀌거나 탈퇴 처리된 계정은 0개다.
- **SC-004**: 새 비밀번호가 현재 비밀번호와 같거나 비밀번호 규칙을 어긴 채로 바뀐 경우는 0건이다.
- **SC-005**: 비밀번호를 바꾸면 바꾼 기기를 뺀 모든 기기의 로그인이 100% 끊기고, 바꾼 기기는 로그인이 유지된다.
- **SC-006**: 로그인 실패와 현재 비밀번호 오입력을 합쳐 연속 5회가 되면 그다음 시도부터 올바른 비밀번호로도 막히고, 10분 뒤에는 다시 가능하다.
- **SC-007**: 탈퇴한 계정의 블로그, 글, 분류, 내 블로그 안의 댓글, 좋아요는 하나도 남지 않고, 다른 사람 글에 단 댓글은 100% 남아 작성자가 "탈퇴한 사용자"로 표시된다.
- **SC-008**: 탈퇴한 사람이 같은 이메일과 닉네임으로 다시 가입할 수 있고, 새 계정에서 이전 데이터가 보이는 경우는 0건이다.
- **SC-009**: 저장하지 않은 수정이 있는 채로 다른 화면으로 가려 할 때 100% 확인을 묻고, 바뀐 것이 없는데 저장 버튼이 눌리는 경우는 0건이다.
- **SC-010**: 탈퇴한 회원의 기록에 원래 이메일, 비밀번호 해시, 닉네임, 소개가 남아 있는 경우는 0건이다. (FR-030)

## Assumptions

- 이 명세는 **내 기준(MyBlog) 요구사항**을 따른다. 원본 `docs/2-요구사항/상세/02-계정관리.md`의 요구사항 ID인 CF-15-1~CF-15-21과, 거기서 참조하는 CF-01-3, CF-01-4, CF-02-6, CF-16-1을 모두 FR에 연결했다. 연결하지 못한 ID는 없다.
- 이 기능은 `001-member-signup-login`(회원 가입과 로그인)에 의존한다. 로그인과 로그아웃, 로그인 유지 기간, 로그인 연속 실패 잠금, 로그인이 필요한 기능에서 로그인 창으로 안내하는 것은 001에서 다룬다. 마이페이지는 로그인한 회원만 쓸 수 있으므로 001이 먼저 되어 있어야 한다.
- 새 비밀번호 규칙은 CF-01-4와 같다. 001에서 정한 **8~20자**를 따른다. 원본 `02-계정관리.md`에는 글자 수가 적혀 있지 않고 CF-01-4를 가리킬 뿐이다. `docs/2-요구사항/상세/01-인증-인가.md`의 CF-01-4와 `기본값` 표도 2026-10-07에 8~20자로 고쳤다.
- "지금 사용 중인 기기의 로그인은 유지"할 때의 유지 기간은 001에서 정한 규칙(마지막 사용 후 7일, 로그인한 때부터 최대 30일)을 그대로 따른다.
- 비밀번호 원문을 저장하지 않는 규칙(001의 FR-010)은 새 비밀번호에도 그대로 적용한다.
- CF-15-14의 "CF-02-6처럼 10분간 잠근다"는 계정 단위의 잠금으로 보고, **잠긴 동안에는 올바른 현재 비밀번호로도 비밀번호 변경과 탈퇴가 진행되지 않고 남은 시간을 안내한다**고 풀어 썼다. 원본에는 이 부분이 로그인에 대해서만 적혀 있다.
- 탈퇴 최종 확인에서 취소하면 탈퇴되지 않는 것은 CF-15-19의 "한 번 더 묻는다"를 풀어 쓴 것이다.
- FR-029(화면을 거치지 않은 요청에도 같은 규칙을 적용)는 원본 02에 따로 적혀 있지 않다. 001의 FR-034와 같은 취지로, "본인만 볼 수 있다"와 "현재 비밀번호가 맞아야 진행한다"를 지키기 위해 더했다.
- 탈퇴로 삭제되거나 남는 블로그, 글, 분류, 댓글, 좋아요 자체는 다른 기능(`docs/2-요구사항/상세/03-코어-블로그-글.md`, `docs/2-요구사항/상세/05-소통-부가.md`)에서 다룬다. 이 명세는 탈퇴했을 때 그것들이 어떻게 되는지까지만 정한다.
- 이 명세는 소셜 로그인과 관리자 기능을 다루지 않는다. 이메일 변경은 할 수 없다. (CF-15-4)
- 화면에 보여 줄 문구와 숫자(글자 수, 시간, 횟수)는 원본의 `안내 문구`, `기본값` 표를 따르며 바꿀 수 있어야 한다. "저장하지 않은 내용이 있습니다. 나갈까요?"는 `안내 문구` 표가 아니라 CF-15-7의 상세에 적힌 문구다. 성공 기준의 5회, 10분, 0~100자도 원본의 값이며, 이 명세에서 제안값으로 새로 지은 숫자는 없다.
- **아직 정하지 않은 것** (원본 `정하지 못한 것`을 그대로 옮김):
  - **프로필 사진**: 이번 범위에서는 제외했지만, 넣을지 나중에 다시 확인합니다.
  - **비밀번호 변경 알림 메일**(CF-15-16)을 넣을지
- 마이페이지, 비밀번호 변경, 회원 탈퇴 화면은 아직 없다. (원본 상태: 화면 없음)
