# Quickstart: 계정 관리 확인 시나리오

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/account-api.md](contracts/account-api.md) | **Date**: 2026-10-07

> 구현이 끝났을 때 **이 기능이 제대로 동작하는지 처음부터 끝까지 확인하는 순서**입니다. 코드는 아직 없으므로 실행 명령은 적지 않았습니다. 프로젝트 저장소가 생기면 `준비`의 빈칸을 채웁니다.
> 각 시나리오에는 연결된 사용자 이야기(US), 요구사항(FR), 성공 기준(SC)을 적었습니다. 모든 SC가 어느 시나리오에서 확인되는지는 마지막 표에 있습니다.
> 문구 중 `research.md`의 `D-n`에 걸린 것(잠금 문구 등)은 결정에 따라 바뀔 수 있습니다.

| 테스트 계정 | 회원 A, 회원 B 두 명. 탈퇴 시나리오는 **새 계정**으로 | 탈퇴는 되돌릴 수 없다 |

## S-1. 마이페이지 열기와 접근 제한 (US1)

연결: US1-1 ~ 3, FR-001 ~ 004, FR-012, FR-029, SC-001

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 회원 A로 로그인하고 마이페이지를 연다 | 이메일, 닉네임, 소개, 가입일, 비밀번호 변경, 회원 탈퇴, 내 블로그 바로가기가 보인다. **프로필 사진 칸이 없다** |
| 2 | `GET /api/account`의 응답을 본다 | 이메일·닉네임·소개·가입일·블로그 번호만 있다. **비밀번호나 해시가 없다** |
| 3 | 로그아웃한 상태에서 마이페이지 주소로 바로 들어간다 | 로그인 창이 뜬다. 로그인하면 **마이페이지로 돌아온다** |
| 4 | 로그아웃한 상태에서 `GET /api/account`, `PATCH /api/account/profile`, `POST /api/account/password`, `POST /api/account/withdrawal`을 직접 보낸다 | 모두 `401 UNAUTHENTICATED`. 아무것도 바뀌지 않는다 |
| 5 | 회원 A로 로그인한 채, 주소나 요청 본문에 **B의 회원 번호**(`users_id`, `userId` 등)를 넣어 보낸다 | 항상 **A의** 정보만 보이고 고쳐진다. B의 정보는 보이지도 바뀌지도 않는다 |
| 6 | 마이페이지에서 `내 블로그`를 누른다 | 내 블로그 화면으로 간다 (US1-10, FR-003) |

## S-2. 내 정보 고치기 (US1)

연결: US1-4 ~ 8, FR-005 ~ 010, FR-029, SC-002

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 화면에서 이메일 칸을 고치려 한다 | 고칠 수 없다 |
| 2 | 요청 본문에 `email`을 넣어 `PATCH /api/account/profile`을 보낸다 | 이메일은 바뀌지 않는다 (DB에서 확인) |
| 3 | 소개만 고쳐 저장한다 (닉네임은 그대로) | "저장했습니다". 내 닉네임은 중복으로 보지 않는다 |
| 4 | 닉네임을 대소문자만 바꿔(`Kim` → `KIM`) 저장한다 | 저장된다 (내 닉네임이므로) |
| 5 | B가 쓰는 닉네임(대소문자만 다른 것 포함)으로 바꿔 저장한다 | "이미 사용 중인 닉네임입니다"가 닉네임 칸 아래. 저장되지 않는다 |
| 6 | 닉네임 1자, 11자, 공백·특수문자 포함으로 저장한다 | "닉네임은 한글, 영문, 숫자로 2~10자여야 합니다". 저장되지 않는다 |
| 7 | 소개를 100자로, 101자로 저장한다 | 100자는 저장, 101자는 칸 아래에 이유가 보이고 저장되지 않는다 |
| 8 | 소개를 비우고 저장한다 | 저장된다 (0자 허용) |
| 9 | 화면을 거치지 않고 규칙을 어긴 값을 직접 보낸다 | 서버가 거절한다 (FR-029) |
| 10 | A와 B가 **거의 동시에** 같은 새 닉네임(아무도 안 쓰는 것)으로 바꾼다 | 한 명만 성공한다. DB에서 소문자로 같은 닉네임인 탈퇴하지 않은 회원이 하나다 (SC-002) |
| 11 | 닉네임을 바꾼 뒤 화면 위쪽의 닉네임과 내 정보를 본다 | 바뀐 값이 보인다 |
| 12 | 아무것도 고치지 않고, 또는 고쳤다가 원래 값으로 되돌리고 저장 버튼을 본다 | 눌리지 않는다 (US1-6, FR-009) |

## S-3. 저장하지 않은 내용 확인 (US1-9)

연결: FR-009, FR-011, SC-009

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 소개를 고치고 저장하지 않은 채 화면 안의 다른 메뉴를 누른다 | "저장하지 않은 내용이 있습니다. 나갈까요?"를 묻는다 |
| 2 | 1에서 취소한다 / 확인한다 | 취소하면 그대로 남고 고친 값도 남는다 / 확인하면 이동한다 |
| 3 | 고친 채로 탭을 닫거나 새로고침한다 | 브라우저가 나갈지 묻는다 (문구는 브라우저 것일 수 있다, research R-5) |
| 4 | 고친 뒤 저장하고 다른 메뉴를 누른다 | 묻지 않고 이동한다 |
| 5 | 고쳤다가 원래 값으로 되돌리고 다른 메뉴를 누른다 | 묻지 않는다 (바뀐 것이 없음) |

## S-4. 비밀번호 변경 (US2)

연결: US2-1 ~ 5, FR-013 ~ 017, FR-019, FR-029, SC-003, SC-004

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 현재 비밀번호를 맞게, 새 비밀번호와 확인을 규칙에 맞게 넣고 변경한다 | "비밀번호를 변경했습니다" |
| 2 | 로그아웃하고 **옛 비밀번호**로 로그인한다 / **새 비밀번호**로 로그인한다 | 옛 것은 실패, 새 것은 성공 |
| 3 | 현재 비밀번호를 틀리게 넣고 변경한다 | "현재 비밀번호가 올바르지 않습니다". **로그인 창이 뜨지 않는다**(`401`이 아님). 비밀번호는 그대로 |
| 4 | 새 비밀번호를 현재와 같게 넣는다 | "현재 비밀번호와 다른 값을 입력해 주세요". 그대로 |
| 5 | 새 비밀번호를 7자, 21자, 특수문자 없음, 공백 포함, 허용하지 않는 특수문자(`~`)로 넣는다 | "비밀번호는 영문, 숫자, 특수문자를 포함해 8~20자로 입력해 주세요". 그대로 |
| 6 | 새 비밀번호와 확인을 다르게 넣는다 | "비밀번호가 일치하지 않습니다". 그대로 |
| 7 | 세 칸 중 하나씩 비우고 보낸다 (화면을 거치지 않은 요청 포함) | 변경되지 않는다 |
| 8 | 4 ~ 7을 화면을 거치지 않고 직접 보낸 뒤 DB의 비밀번호 해시를 본다 | 해시가 바뀌지 않았다 (SC-003, SC-004) |
| 9 | 변경 뒤 DB의 비밀번호 칸과 서버 로그를 본다 | 원문이 없고 해시만 있다. 로그 어디에도 입력한 비밀번호가 없다 (NF-01) |

## S-6. 실패 횟수 합산과 잠금 (US2-7, Edge Cases)

연결: FR-018, FR-022, SC-006, `research.md` D-3, D-4

> 잠금 시간을 줄인 설정으로 확인한다.

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 다른 브라우저에서 A의 로그인을 3번 틀린다. 그다음 마이페이지에서 현재 비밀번호를 2번 틀린다 | 5번째(두 번째 비밀번호 변경 실패)의 응답이 잠금 안내다. 남은 시간이 보인다 |
| 2 | 잠긴 동안 **올바른** 현재 비밀번호로 비밀번호를 바꾼다 | 바뀌지 않고 남은 시간이 보인다 |
| 3 | 잠긴 동안 올바른 비밀번호로 탈퇴한다 / 다른 브라우저에서 올바른 비밀번호로 로그인한다 | 둘 다 진행되지 않는다 |
| 4 | 잠긴 동안 이미 로그인한 기기에서 마이페이지를 연다 | 열린다 (로그인은 끊지 않음, research R-8) |
| 5 | 잠금 시간이 지난 뒤 올바른 비밀번호로 변경한다 | 된다. 실패 횟수가 0이다 |
| 6 | 로그인 2번 틀림 → 탈퇴 화면에서 비밀번호 2번 틀림 → 비밀번호 변경에서 1번 틀림 | 5번째에 잠긴다 (세 곳이 합산) |
| 7 | (`D-4`가 추천안일 때) 3번 틀린 뒤 비밀번호 변경에서 현재 비밀번호를 맞게 넣고, 다시 4번 틀린다 | 잠기지 않는다 (맞으면 0으로) |
| 8 | 새 비밀번호 규칙만 어긴 요청(현재 비밀번호는 틀림)을 여러 번 보낸다 | 형식 오류로 먼저 거절되고 실패 횟수는 늘지 않는다 (계약의 검사 순서) |
| 9 | 틀린 비밀번호 요청 5개를 **동시에** 보낸다 | 5회 안에 잠긴다 (횟수가 정확히 올라간다) |

## S-7. 탈퇴 흐름 (US3)

연결: US3-1 ~ 6, FR-022, FR-023, FR-025 ~ 027, FR-029, SC-003

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 탈퇴 화면을 연다 | 되돌릴 수 없다는 것, 삭제되는 것(내 블로그, 글, 분류, 내가 쓴 댓글 중 내 블로그 안의 것, 좋아요), 남는 것(다른 사람 글에 단 댓글, "탈퇴한 사용자"로 표시)이 보인다 |
| 2 | 체크하지 않고 `탈퇴하기`를 본다 | 눌리지 않는다 |
| 3 | 체크하고 비밀번호를 맞게 넣고 `탈퇴하기` | "정말 탈퇴하시겠습니까? 이 작업은 되돌릴 수 없습니다"를 묻는다 |
| 4 | 3에서 취소한다 | 탈퇴되지 않는다. 서버에 탈퇴 요청이 가지 않았다. 계정과 데이터가 그대로다 |
| 5 | 비밀번호를 틀리게 넣고 확인까지 한다 | "현재 비밀번호가 올바르지 않습니다". 탈퇴되지 않는다. DB의 실패 횟수가 1 늘었다 |
| 6 | 화면을 거치지 않고 틀린 비밀번호로, 또는 `agreed: false`로 탈퇴 요청을 보낸다 | 거절되고 아무것도 지워지지 않는다 (SC-003) |
| 7 | 3에서 확인한다 | 첫 화면으로 가고 "탈퇴가 완료되었습니다"가 보인다. 로그아웃 상태다 |
| 8 | 탈퇴 전에 다른 브라우저에서도 로그인해 두었다면, 그 브라우저에서 요청한다 | `401` (모든 세션 삭제) |
| 9 | 탈퇴한 이메일과 비밀번호로 로그인한다 | "이메일 또는 비밀번호가 올바르지 않습니다" (`001`의 일반 실패 문구) |

## S-8. 탈퇴 때 지우는 것과 남기는 것 (US3-7)

연결: FR-024, SC-007, `research.md` D-1, D-5, R-4

> `준비`의 탈퇴용 데이터를 만든 회원 A를 S-7의 순서로 탈퇴시킨 뒤 확인한다.

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | DB에서 A의 블로그, 분류, 글(공개·비공개)을 찾는다 | 하나도 없다 |
| 2 | A의 글에 달려 있던 댓글(A의 것, B의 것), 좋아요, 태그 연결, 이미지 기록, 신고를 찾는다 | 하나도 없다 |
| 3 | A가 B의 글에 누른 좋아요를 찾는다 | 없다. B의 글 좋아요 수가 1 줄었다 |
| 4 | B의 글을 열어 A가 단 댓글을 본다 | **남아 있고** 작성자가 "탈퇴한 사용자"로 보인다 |
| 5 | `006`의 댓글 관리 목록(있다면)에서 그 댓글을 본다 | 작성자가 "탈퇴한 사용자" |
| 6 | DB에서 A의 회원 줄을 본다 | (`D-1` 추천안일 때) 줄이 남아 있고 `deleted_at`이 있다 |
| 7 | 탈퇴 도중 실패하게 만든다 (예: 개발용 설정에서 블로그 삭제 단계에 오류) | 아무것도 지워지지 않았다 (한 묶음) |
| 8 | 다른 회원 B의 블로그, 글, 댓글 수를 탈퇴 전후로 비교한다 | A의 블로그에 달았던 B의 댓글 말고는 변화가 없다 |

## S-9. 탈퇴 후 다시 가입 (US3-8)

연결: FR-028, SC-008

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | S-8에서 탈퇴한 A의 이메일과 닉네임으로 `001`의 가입을 한다 | 이메일 인증을 받을 수 있고("이미 가입된 이메일입니다"가 나오지 않음) 가입된다 |
| 2 | 새 계정으로 로그인해 마이페이지와 내 블로그를 연다 | 새 블로그(`{닉네임}의 블로그`, `미분류`만)다. 이전 글, 분류, 소개가 없다. 가입일이 새 날짜다 |

## S-9a. 탈퇴 회원의 개인정보 (FR-030)

## S-11. 보안 점검 (공통)

연결: FR-002, FR-029, NF-01, NF-06, NF-07, NF-11, SC-001, SC-003

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | **CSRF 토큰 없이** 내 정보 저장, 비밀번호 변경, 탈퇴 요청을 보낸다 | 모두 거절된다. 아무것도 바뀌지 않는다 |
