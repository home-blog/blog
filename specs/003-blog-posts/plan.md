## 쉬운 설명: 이 기능이 어떻게 돌아가나

```
[가입할 때] (001이 부른다, 한 묶음)
 회원 저장 ─▶ 블로그 "{닉네임}의 블로그" 저장 ─▶ 분류 "미분류"(기본 분류 표시) 저장
              하나라도 실패하면 셋 다 취소

[글쓰기]
 글쓰기 화면 열기 ─▶ 서버: 내 블로그의 분류 목록 + 주제 목록 + 기본 분류·기본 주제(마지막에 쓴 글의 것) + 기본 공개
 [저장] ─▶ 서버: 로그인 확인 ─▶ 고른 분류가 "내 블로그의 분류"인지, 고른 주제가 `topic` 표에 있는지 확인
               제목·본문 규칙 검사 ─▶ PostgreSQL에 글 저장(작성 시각 자동) ─▶ 글 번호를 돌려줌
 화면 ─▶ 그 글의 상세 화면으로 이동

[글 읽기]
 글 상세 요청 ─▶ 서버: 글을 찾는다
               글이 비공개이거나 분류가 비공개인데 주인이 아니면 ─▶ 없는 글과 똑같이 "존재하지 않는 글입니다"
               이전/다음 글 = 같은 블로그의 공개 분류의 공개 글 중 바로 앞/뒤 (작성 시각 순)
 화면 ─▶ 본문(마크다운 원문)을 "스크립트가 실행되지 않는 방식"으로 그린다 (D-1)

[수정·삭제]  (기술스택-아키텍처 3장 D 그림)
 요청 ─▶ 서버: 글 주인 == 로그인한 회원? 아니면 "존재하지 않는 글입니다"
        수정: 바뀐 것이 있을 때만 저장하고 수정 시각 갱신
        삭제: 댓글·좋아요·태그 연결·이미지 기록과 글을 한 묶음으로 지움

[분류 관리] (주인만, 내 블로그는 세션으로 찾는다)
 추가(맨 아래) · 이름 바꾸기 · 공개/비공개 바꾸기 · 순서 바꾸기 · 삭제(글이 있거나 "미분류"면 거절)
 비공개 분류 ─▶ 주인이 아닌 사람에게는 분류도, 그 분류의 글도 보이지 않는다
```

## Summary

**주요 요구**: 가입하면 블로그 1개와 분류 "미분류"가 생기고(US1), 회원이 자기 블로그에 글을 쓰고(US2, 글마다 주제를 고른다), 누구나 공개 글을 읽으며(US3), 작성자만 글을 고치고 지우고(US4), 글마다 공개·비공개를 정하고(US5), 주인이 분류를 관리하고(US6, 분류도 비공개로 할 수 있다), 블로그 이름과 소개를 고친다(US7).

**기술 방향**: 단일 서버(Spring Boot)의 `blog` 모듈(블로그·분류)과 `post` 모듈(글)이 규칙을 모두 검사한다. 데이터는 PostgreSQL의 팀 ERD 표(`blog`, `category`, `post`)에 둔다. 권한은 **요청마다 서버가** "로그인한 회원 == 블로그 주인"을 비교해서 확인하고, 볼 수 없는 글은 없는 글과 같은 응답을 준다. 본문은 **마크다운 원문으로 저장**하고(편집기 `확정`), 화면은 스크립트가 실행되지 않게 그린다. 이 기능은 Redis를 쓰지 않는다.

### Source Code

코드는 이 문서 저장소가 아니라 **프로젝트 저장소**에 만든다. 안의 구조는 `기술스택-아키텍처.md` 3.A의 **기능별 모듈**(`blog`는 블로그·분류, `post`는 글)을 따른다. (모두 `가안`)

```text
서버 (Spring Boot, 단일 서버)
├── blog 모듈 (블로그·분류)
│   ├── 컨트롤러   # /api/blogs/..., /api/me/blog/... (contracts 1 ~ 9)
│   ├── 서비스     # 기본 블로그 만들기(001의 가입이 같은 묶음 안에서 부른다),
│   │              # 이름·소개 수정, 분류 추가·이름·순서·삭제 규칙, 분류별 글 개수
│   └── 저장소     # blog, category (PostgreSQL)
├── post 모듈 (글)
│   ├── 컨트롤러   # /api/posts/... (contracts 10 ~ 14)
│   ├── 서비스     # 작성·수정·삭제·상세, "보이는 글" 조건, 이전·다음 글, 기본 분류
│   └── 저장소     # post (PostgreSQL)
├── (다른 모듈의 입구) # 글 삭제 때 댓글·좋아요·태그 연결·이미지를 지우는 입구는 005의 모듈이 만든다
└── 공통 설정      # 설정값 읽기, 공통 오류 응답, 보안·세션 (001과 같음)

화면 (React + Vite)
└── 글쓰기·수정 화면(마크다운 입력, 나가기 확인, 버튼 잠금), 글 상세(마크다운을 안전하게 보여 주기),
    블로그 이름·소개 고치기, 분류 관리 (06의 관리 화면에 들어갈 수 있다)
```

**Structure Decision**: 화면과 서버를 나누는 **웹 애플리케이션** 구조이고, 서버는 기능별 모듈을 가진 **단일 서버**다. `post` 모듈은 `blog` 모듈의 입구(분류가 내 블로그의 것인지 확인 등)만 부르고 표를 직접 건드리지 않는다. (확정: 단일 서버, 가안: 모듈 이름과 경계)
