# Contract: 블로그·분류·글 API (초안)

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-10-07 | **상태**: `가안`

> 화면(React)과 서버가 주고받는 **요청과 응답의 약속**입니다. 주소, 필드 이름, 상태 코드는 모두 `가안`이고, 팀의 `API 명세서` 단계에서 다른 기능과 함께 맞춥니다.
> 화면에 보여 줄 문구는 `docs/상세/03-코어-블로그-글.md`의 `안내 문구` 표를 **그대로** 씁니다. 이 문서의 `message`는 그 표의 문구입니다. (문구를 바꾸면 그 표를 먼저 고칩니다.) **표에 없는 문구는 `※`로 표시했습니다.** 명세 Assumptions대로 길이 규칙을 어겼을 때의 문구는 아직 없으므로, `※` 문구는 표에 더하기 전까지 **제안**입니다.
> 통신은 REST(JSON)이고, 로그인 상태는 쿠키로 증명합니다. 공통 약속은 [`001`의 계약](../../001-member-signup-login/contracts/auth-api.md)을 그대로 따릅니다.

## 공통 약속

### `001`에서 그대로 가져오는 것

- **오류 응답 모양**: `{ "code", "message", "fieldErrors" }`. 서버 내부 정보는 넣지 않는다. (`001` contracts 공통, NF-06)
- **CSRF**: 변경 요청(POST, PUT, PATCH, DELETE)은 `GET /api/auth/csrf`로 받은 토큰을 헤더에 싣는다. (NF-11)
- **로그인하지 않았을 때**: `[로그인]` 표시가 있는 주소는 로그인하지 않으면 `401 UNAUTHENTICATED`. 화면은 하려던 화면을 기억하고 로그인 창을 띄운 뒤 돌아온다. (`001` contracts 9, FR-008)

### 이 기능의 약속

- 공개 여부 값은 `"public"` / `"private"`이다. 글(`post.visibility`)과 분류(`category.visibility`)가 같은 값을 쓴다. (팀 ERD의 값과 같다)
- **비공개 분류의 글은 비공개 글과 같다.** 주인이 아닌 사람에게는 글이 공개이고 **그 분류도 공개일 때만** 보인다. 비공개 분류는 주인이 아닌 사람의 분류 목록에도 나오지 않는다. (FR-048, SC-013)
- 주제(`topicId`)는 팀 ERD의 `topic` 표(여행, 음식, 취미, 운동, 개발)의 번호다. 글마다 하나를 고르며 필수다. (FR-046)
- 시각은 시간대가 붙은 ISO 8601 글자(`2026-10-07T10:00:00+09:00`)로 준다.
- **"내 블로그"는 세션으로 찾는다.** `/api/me/blog/...` 주소는 블로그 번호를 받지 않는다. 그래서 남의 블로그를 고칠 방법이 없다. (FR-006, FR-035, FR-044)
- **남의 글은 없는 글과 같다.** 수정 화면 조회, 수정, 삭제, 남의 비공개 글(비공개 분류의 글 포함) 보기는 모두 **같은 `404`와 같은 본문**으로 답한다. (FR-019, FR-026, FR-048, SC-003)

```json
{ "code": "POST_NOT_FOUND", "message": "존재하지 않는 글입니다" }
```

### 요청 검사 순서 (가안)

1. 로그인 확인 (`[로그인]` 주소만)
2. 대상 찾기와 주인 확인 (아니면 `404` — 형식 오류보다 먼저 답해서, 남의 글에 대해서는 항상 같은 응답이 나오게 한다)
3. 형식 검사 (비어 있음, 길이, 값)
4. 상태 검사 (중복, 글이 있는 분류, 기본 분류)
5. 처리

### 화면이 보여 주는 확인 문구 (서버와 주고받지 않음)

| 상황 | 문구 | FR |
|---|---|---|
| 저장 전 이탈 | 저장하지 않은 내용이 있습니다. 나갈까요? | FR-017 |
| 글 삭제 확인 | 삭제하면 되돌릴 수 없습니다. 삭제할까요? | FR-021 |
| 공개로 전환 | 공개로 바꾸면 누구나 볼 수 있습니다 | FR-033 |

확인 창에서 취소하면 화면은 **요청을 보내지 않는다.** 그래서 아무것도 바뀌지 않는다.

## 2. `GET /api/blogs/{blogId}/categories` — 분류 목록과 글 개수

| 항목 | 내용 |
|---|---|
| 연결 | FR-039, FR-043, FR-047, FR-048 |
| 로그인 | 필요 없음 (로그인했으면 주인인지 확인한다) |
| 성공 | `200` — 아래 |

```json
{
  "categories": [
    { "categoryId": 5, "name": "미분류", "postCount": 2, "isDefault": true, "visibility": "public" },
    { "categoryId": 8, "name": "일상", "postCount": 4, "isDefault": false, "visibility": "public" }
  ]
}
```

- 순서는 블로그 주인이 정한 순서다. (FR-039)
- `postCount`는 **보는 사람에 따라 다르다.** 방문자에게는 공개 분류의 공개 글만, 블로그 주인에게는 비공개 글도 포함해서 센다. (FR-043, `research.md` B-3)
- **비공개 분류**(`visibility: "private"`)는 블로그 주인에게만 목록에 나온다. 방문자의 목록에서는 빠진다. 화면은 주인에게 "비공개" 표시를 붙인다. (FR-047, FR-048)

오류: `1`과 같은 `BLOG_NOT_FOUND`.

## 5. `[로그인]` `POST /api/me/blog/categories` — 분류 추가

| 항목 | 내용 |
|---|---|
| 연결 | FR-035, FR-036, FR-037 |

## 6. `[로그인]` `PATCH /api/me/blog/categories/{categoryId}` — 분류 이름·공개 여부 바꾸기

| 항목 | 내용 |
|---|---|
| 연결 | FR-035, FR-036, FR-038, FR-042, FR-047, FR-048 |
| 요청 | `{ "name": "여행" }` 또는 `{ "visibility": "private" }` 또는 둘 다 (보낸 칸만 바꾼다, 가안) |
| 성공 | `200` — `{ "categoryId": 8, "name": "여행", "postCount": 4, "isDefault": false, "visibility": "private" }` |

**동작**: `categoryId`가 **내 블로그의 분류**인지 먼저 확인한다. 이름 규칙은 `5`와 같고, **자기 자신과는 비교하지 않는다.** `미분류`도 이름을 바꿀 수 있다. (FR-042) 글은 분류 번호만 가지고 있으므로 바꾼 이름이 그 분류의 모든 글에 바로 보인다. (FR-038)

**공개 여부** (FR-047, FR-048): `visibility`는 `"public"` / `"private"`. `미분류`도 비공개로 할 수 있다. 비공개로 바꾸면 이 요청이 끝나는 순간부터 그 분류와 그 분류의 모든 글이 주인이 아닌 사람에게 보이지 않는다. 글의 `visibility`는 바꾸지 않는다. (`data-model.md` 7)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 404 | `CATEGORY_NOT_FOUND` | ※ 존재하지 않는 분류입니다 | FR-035 (남의 분류도 이 응답) |
| 400 | `VALIDATION_FAILED` | (`5`와 같음) | FR-036 |
| 409 | `CATEGORY_NAME_DUPLICATED` | 이미 있는 분류입니다 | FR-036 |
| 400 | `VALIDATION_FAILED` (`field`: `visibility`) | ※ 공개 여부를 다시 골라 주세요 | FR-047 |

## 8. `[로그인]` `DELETE /api/me/blog/categories/{categoryId}` — 분류 삭제

| 항목 | 내용 |
|---|---|
| 연결 | FR-035, FR-040, FR-042 |
| 요청 | 없음 |
| 성공 | `204` |

**동작**: 내 분류인지 확인 → 기본 분류(`미분류`)면 거절 → 그 분류의 글 수를 **비공개 포함으로** 세서 1개 이상이면 거절 → 삭제. 세고 지우는 사이에 글이 들어오면 DB가 거절하고, 다시 세어 같은 오류로 답한다. (`research.md` R-3)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 404 | `CATEGORY_NOT_FOUND` | ※ 존재하지 않는 분류입니다 | FR-035 |
| 409 | `DEFAULT_CATEGORY_NOT_DELETABLE` | ※ 미분류는 삭제할 수 없습니다 | FR-042 |
| 409 | `CATEGORY_HAS_POSTS` | 이 분류에 글이 {N}개 있어 삭제할 수 없습니다. 글을 다른 분류로 옮긴 뒤 삭제해 주세요 | FR-040 |

- `CATEGORY_HAS_POSTS`에는 `postCount`를 함께 준다. 서버가 `{N}`을 채운 문구를 `message`에 넣는다. (가안)
- `DEFAULT_CATEGORY_NOT_DELETABLE`: 화면은 `미분류`에 삭제 버튼을 보이지 않는 것이 좋다. 이 응답은 화면을 거치지 않은 요청을 막기 위한 것이다.

## 9. `[로그인]` `GET /api/me/blog/post-form` — 글쓰기 화면의 기본값

| 항목 | 내용 |
|---|---|
| 연결 | FR-012, FR-013, FR-046 |
| 성공 | `200` — 아래 |

```json
{
  "categories": [ { "categoryId": 5, "name": "미분류" }, { "categoryId": 8, "name": "일상" } ],
  "topics": [ { "topicId": 1, "name": "여행" }, { "topicId": 2, "name": "음식" }, { "topicId": 3, "name": "취미" }, { "topicId": 4, "name": "운동" }, { "topicId": 5, "name": "개발" } ],
  "defaultCategoryId": 8,
  "defaultTopicId": 1,
  "defaultVisibility": "public",
  "limits": { "titleMaxLength": 100, "contentMaxLength": 10000 }
}
```

- `defaultCategoryId`: 내 블로그에서 **가장 최근에 쓴 글의 분류**. 글이 없으면 `미분류`. (`research.md` B-6)
- `topics`: 팀 ERD `topic` 표의 주제 목록 (`sort_order` 순서). 번호는 예시다.
- `defaultTopicId`: 내 블로그에서 **가장 최근에 쓴 글의 주제**. 글이 없으면 `null`이고, 화면은 주제 칸을 비워 두어 사용자가 고르게 한다. (FR-046, `research.md` B-6)
- `limits`: 화면 안내가 서버의 설정값과 어긋나지 않게 함께 준다. (가안, `plan.md` 설정값 목록)
- `D-6`에서 A를 고르면 화면은 이때 1회용 요청 번호(`requestKey`)를 만든다.

## 10. `[로그인]` `POST /api/posts` — 글 쓰기

| 항목 | 내용 |
|---|---|
| 연결 | FR-008 ~ FR-016, FR-018, FR-034, FR-044, FR-045, FR-046 |
| 요청 | `{ "title": "첫 글", "content": "마크다운 **원문**", "categoryId": 8, "topicId": 1, "visibility": "public", "requestKey": "…" }` |
| 성공 | `201` — `{ "postId": 12 }` |

**동작**

1. 글이 들어갈 블로그는 **세션의 회원으로 정한다.** 요청에 블로그 번호를 받지 않는다. (FR-008, US2-10)
2. `categoryId`가 **내 블로그의 분류**가 아니면 거절한다. 남의 블로그의 분류 번호를 보내도 그 블로그에는 글이 생기지 않는다. (US2-10)
3. `topicId`는 필수이고, `topic` 표에 있는 번호여야 한다. 없거나 비었으면 거절한다. (FR-046)
4. 제목은 앞뒤 공백을 지우고, 본문은 줄바꿈만 맞춘다. (`data-model.md` 6)
5. `visibility`가 없으면 `public`. 작성 시각은 서버가 넣는다. 요청에 작성 시각이 있어도 무시한다. (FR-013, FR-014)
6. 본문은 **마크다운 원문 그대로** 저장한다. 서버는 본문을 HTML로 바꾸지 않는다. 화면이 보여 주는 방식은 `research.md` D-1. (FR-045)
7. **연속 저장** (FR-018): `D-6`에서 A를 고르면, 같은 `requestKey`가 다시 오면 새 글을 만들지 않고 **처음 만든 글의 번호를 `200`으로** 돌려준다. 정해지기 전에는 `requestKey`를 받지 않는다.
8. 화면은 `postId`로 상세 화면으로 이동한다. 실패하면 입력 내용을 지우지 않는다. (FR-015)

**오류**

| HTTP | `code` | `field` | `message` | FR |
|---|---|---|---|---|
| 401 | `UNAUTHENTICATED` | — | (`001` contracts 8의 문구) | FR-008 |
| 400 | `VALIDATION_FAILED` | `title` | 제목을 입력해 주세요 | FR-010, FR-016 |
| 400 | `VALIDATION_FAILED` | `title` | ※ 제목은 100자 이하로 입력해 주세요 | FR-010 |
| 400 | `VALIDATION_FAILED` | `content` | 본문을 입력해 주세요 | FR-011, FR-016 |
| 400 | `VALIDATION_FAILED` | `content` | ※ 본문은 10,000자 이하로 입력해 주세요 | FR-011 |
| 400 | `VALIDATION_FAILED` | `categoryId` | ※ 분류를 골라 주세요 | FR-012, FR-034 |
| 400 | `VALIDATION_FAILED` | `topicId` | 주제를 골라 주세요 | FR-046 (비었거나 `topic` 표에 없는 번호) |
| 400 | `VALIDATION_FAILED` | `visibility` | ※ 공개 여부를 다시 골라 주세요 | FR-029 |
| 400 | `INVALID_CATEGORY` | `categoryId` | ※ 분류를 다시 골라 주세요 | FR-008 (내 블로그의 분류가 아님, 또는 그사이 지워짐) |

- 제목과 본문이 **모두** 비어 있으면 `fieldErrors`에 두 칸을 함께 넣는다. (화면이 칸마다 문구를 보여 준다)

## 11. `GET /api/posts/{postId}` — 글 상세

| 항목 | 내용 |
|---|---|
| 연결 | FR-023 ~ FR-027, FR-030, FR-031, FR-046, FR-048 |
| 로그인 | 필요 없음 (로그인했으면 주인인지 확인한다) |
| 성공 | `200` — 아래 |

```json
{
  "postId": 12,
  "blogId": 3,
  "blogName": "철수의 블로그",
  "category": { "categoryId": 8, "name": "일상", "visibility": "public" },
  "topic": { "topicId": 1, "name": "여행" },
  "title": "첫 글",
  "content": "마크다운 **원문**",
  "visibility": "public",
  "createdAt": "2026-10-07T10:00:00+09:00",
  "updatedAt": null,
  "prevPostId": 11,
  "nextPostId": null,
  "isOwner": false
}
```

- `updatedAt`이 `null`이면 수정한 적이 없다. 화면은 값이 있을 때만 수정 시각을 보여 준다. (FR-023)
- `topic`: 이 글의 주제. (FR-046)
- `prevPostId` / `nextPostId`: 같은 블로그의 **공개 분류의 공개 글** 중 바로 앞에 쓴 글 / 바로 뒤에 쓴 글. 없으면 `null`이고 화면이 버튼을 숨긴다. 주인이 자기 비공개 글을 볼 때도 공개 글만 가리킨다. (FR-024, `research.md` B-5)
- `blogId`, `category.categoryId`: `목록으로`가 그 분류의 글 목록(`004`)으로 가는 데 쓴다. (FR-025)
- `isOwner`: 참일 때만 화면이 `수정`, `삭제`를 보인다. (FR-027)
- `content`는 **원문**이다. 화면은 `research.md` D-1에서 정한 방식으로만 그린다. 정해지기 전에는 글자 그대로 보여 준다. (FR-045, SC-012)
- `블로그 이름`, `분류 이름`은 요청마다 그 표에서 읽는다. (FR-038, SC-010)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 404 | `POST_NOT_FOUND` | 존재하지 않는 글입니다 | FR-026 |

> **비공개 글 규칙**: 글이 비공개이거나 **글의 분류가 비공개**이고, 보는 사람이 그 블로그의 주인이 아니면(로그인하지 않은 사람 포함), **없는 글과 똑같은 `404`** 를 준다. 상태 코드, `code`, `message`, 본문 모양이 모두 같다. "비공개 글입니다" 같은 다른 문구나 `403`은 쓰지 않는다. (FR-026, FR-031, FR-048, SC-002, SC-003, SC-013)

## 12. `[로그인]` `GET /api/posts/{postId}/edit` — 수정 화면용 글

| 항목 | 내용 |
|---|---|
| 연결 | FR-019, FR-020, FR-046 |
| 성공 | `200` — `{ "postId": 12, "title": "…", "content": "…", "categoryId": 8, "topicId": 1, "visibility": "public", "categories": [ … ], "topics": [ … ] }` |

**동작**: 글 주인이 아니면 **공개 글이어도** `404 POST_NOT_FOUND` "존재하지 않는 글입니다". (FR-019) 화면은 이 응답으로 수정 화면을 채운다. `categories`, `topics`는 `9`와 같은 모양이다.

## 13. `[로그인]` `PUT /api/posts/{postId}` — 글 수정

| 항목 | 내용 |
|---|---|
| 연결 | FR-019, FR-020, FR-033, FR-041, FR-044, FR-046 |
| 요청 | `{ "title": "…", "content": "…", "categoryId": 9, "topicId": 2, "visibility": "private" }` |
| 성공 | `200` — `{ "postId": 12, "changed": true, "updatedAt": "2026-10-08T09:00:00+09:00" }` |

**동작**

1. 글 주인이 아니면 `404 POST_NOT_FOUND`. (FR-019)
2. 입력 규칙, "내 블로그의 분류" 확인, 주제 확인은 `10`과 같다. (주제도 필수)
3. 정리한 값을 지금 값과 비교한다. **하나라도 다르면** 저장하고 `updatedAt`을 지금으로 바꾼다. 모두 같으면 아무것도 저장하지 않고 `changed: false`와 **원래의** `updatedAt`을 준다. (FR-020, SC-009)
4. `createdAt`은 요청에 있어도 바꾸지 않는다.
5. 분류를 바꾸면 그 글은 새 분류 하나에만 속한다. 분류별 개수는 세는 방식이라 따로 고칠 것이 없다. (FR-041, US6-7)
6. 공개 여부를 바꾸면 이 요청이 끝나는 순간부터 반영된다. 비공개 → 공개의 확인 문구는 화면이 먼저 보여 준다. (FR-033)

**오류**: `10`의 `VALIDATION_FAILED`, `INVALID_CATEGORY`와 `404 POST_NOT_FOUND`.

## 14. `[로그인]` `DELETE /api/posts/{postId}` — 글 삭제

| 항목 | 내용 |
|---|---|
| 연결 | FR-021, FR-022, FR-044 |
| 요청 | 없음 |
| 성공 | `204` |

**동작**: 글 주인이 아니면 `404 POST_NOT_FOUND`로 답하고 아무것도 지우지 않는다. 주인이면 댓글, 좋아요, 태그 연결, 이미지 기록, (신고 기록 — `research.md` D-7), 글을 **한 묶음**으로 지우고, 이미지 파일은 묶음이 끝난 뒤 지운다. (`data-model.md` 5) 화면은 성공하면 **내 블로그 글 목록**(`004`)으로 이동한다. (FR-022)

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 404 | `POST_NOT_FOUND` | 존재하지 않는 글입니다 | FR-021 (남의 글, 이미 지운 글) |

## 15. 목록과 검색에 넘기는 약속 (`004`의 계약에서 적용)

글 목록, 분류별 목록, 검색 주소는 `004`가 만든다. 이 기능은 **어떤 글이 나오는지**만 정한다.

| 규칙 | 내용 | FR |
|---|---|---|
| 보이는 글 | (`post.visibility = public` **그리고** `category.visibility = public`) **또는** 보는 사람이 그 블로그의 주인 (`research.md` B-3의 조건을 그대로 쓴다) | FR-030, FR-031, FR-048 |
| 검색 | 비공개 글과 비공개 분류의 글은 **주인이 검색해도** 넣지 않는다 (CF-11-2: "비공개 글은 항상 제외한다") | FR-030, FR-031, FR-048 |
| 비공개 분류 | 주인이 아닌 사람의 분류 목록(분류 고르기 포함)에 넣지 않는다. 그 분류의 글은 비공개 글과 똑같이 다룬다 | FR-048 |
| 비공개 표시 | 주인이 자기 블로그 목록을 볼 때 각 글에 `visibility`를 담아, 화면이 "비공개" 표시를 붙인다 | FR-032 |
| 분류 이름·블로그 이름 | 목록에서도 요청마다 표에서 읽는다 | FR-038, SC-010 |
