# Quickstart: 블로그·분류·글 확인 시나리오

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/blog-post-api.md](contracts/blog-post-api.md) | **Date**: 2026-10-07

> 구현이 끝났을 때 **이 기능이 제대로 동작하는지 처음부터 끝까지 확인하는 순서**입니다. 코드는 아직 없으므로 실행 명령은 적지 않았습니다. 프로젝트 저장소가 생기면 `준비`의 빈칸을 채웁니다.
> 각 시나리오에는 연결된 사용자 이야기(US), 요구사항(FR), 성공 기준(SC)을 적었습니다. 모든 SC가 어느 시나리오에서 확인되는지는 마지막 표에 있습니다.
> `D-1 ~ D-7`이 정해지지 않은 동안은, 해당 줄의 **기대한다**를 추천안 기준으로 적었습니다. 다른 안을 고르면 그 줄만 고칩니다.

## 준비

| 필요한 것 | 내용 | 비고 |
|---|---|---|
| PostgreSQL | 개발용으로 띄운다 | 방법은 [가이드/03-로컬환경-도커컴포즈-사용법.md](../../docs/가이드/03-로컬환경-도커컴포즈-사용법.md)를 따른다. 이 기능은 Redis를 쓰지 않는다 (가입 시나리오는 `001`의 준비를 따른다) |
| 서버 | 개발용 설정으로 실행한다 | 실행 명령은 구현 뒤에 채운다 |
| 확인 도구 | 화면, 또는 API 도구(예: curl, Postman) | 변경 요청은 먼저 `GET /api/auth/csrf`로 받은 토큰을 헤더에 싣는다 (`001`) |
| 테스트 계정 | **회원 A**(블로그 주인)와 **회원 B**(다른 회원), 그리고 **로그인하지 않은 상태** | A와 B는 `001`의 가입 흐름으로 만든다 |
| 글자 수 줄이기 | 테스트용 설정에서 글자 수 제한을 줄여 확인해도 된다 | 예: `post.content.max-length` 20. 이름은 [plan.md](plan.md)의 `설정값 목록` |

## S-1. 가입하면 내 블로그가 생긴다 (US1)

연결: US1-1 ~ 3, FR-001 ~ 003, SC-001, SC-005

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 닉네임 `철수`로 새로 가입한다 (`001`) | 가입 완료 |
| 2 | 로그인해서 `GET /api/me/blog` | 이름 `철수의 블로그`, 소개 `""` |
| 3 | `GET /api/blogs/{blogId}/categories` | `미분류` 하나뿐이고 `isDefault`가 참 |
| 4 | DB에서 이 회원의 블로그 수를 센다 | 1개 |
| 5 | DB에서 같은 회원으로 블로그를 하나 더 넣어 본다 | DB가 거절한다 (`D-4`의 A: `UNIQUE`) |
| 6 | 가입 처리 중 블로그 저장이 실패하도록 만든 뒤(개발용 설정) 가입한다 | 회원도 만들어지지 않는다 (한 묶음) |

## S-2. 글쓰기 정상 흐름 (US2)

연결: US2-1 ~ 3, FR-008, 009, 012 ~ 015, SC-011

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 회원 A로 처음 `GET /api/me/blog/post-form` | `defaultCategoryId`가 `미분류`, `defaultVisibility`가 `public` |
| 2 | 제목과 본문을 쓰고 저장 | `201`과 `postId`. 화면은 그 글의 상세 화면으로 이동 |
| 3 | 상세를 연다 | `createdAt`이 저장한 시각, `updatedAt`이 `null` |
| 4 | 분류 `일상`을 만들고 `일상`으로 글을 하나 쓴 뒤, 다시 글쓰기 화면을 연다 | `defaultCategoryId`가 `일상` |
| 5 | 요청에 `createdAt`을 어제로 넣어 저장한다 | 무시되고 저장한 시각으로 기록된다 (FR-014) |
| 6 | **사람이 직접** 글쓰기 화면을 열어 저장한 글의 상세를 볼 때까지 시간을 잰다 (SC-011 제안값) | 3분 안에 끝난다 |

| 2 | 제목에 공백만 넣고 저장 | 1번과 같다 |

| 9 | 본문에 공백과 줄바꿈만 넣고 저장 | (`D-2` 추천안) "본문을 입력해 주세요" |
| 10 | 저장 중 서버를 멈춰 실패시킨다 | 화면에 입력한 제목·본문이 그대로 남는다 (FR-015) |

## S-4. 로그인 안내와 남의 블로그 (US2)

연결: US2-6, 10, FR-008, FR-044, SC-004

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 로그인하지 않고 `POST /api/posts` | `401 UNAUTHENTICATED` |
| 2 | 화면에서 로그인하지 않고 `글쓰기`를 누르고, 로그인 창에서 로그인 | 글쓰기 화면으로 돌아온다 (`001` S-8) |
| 3 | 회원 B로 로그인해 **회원 A의 분류 번호**로 `POST /api/posts` | `400 INVALID_CATEGORY`. A의 블로그에 글이 생기지 않는다 |
| 4 | 회원 B로 요청 본문에 `blogId`에 A의 블로그 번호를 넣어 보낸다 | 무시된다. 글은 B의 블로그에만 생길 수 있다 |

## S-5. 연속 저장과 나가기 확인 (US2)

연결: US2-8, 9, FR-017, FR-018, SC-008, `research.md` D-6

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 화면에서 `저장`을 빠르게 여러 번 누른다 | 글이 하나만 생긴다 |
| 2 | 같은 `requestKey`로 같은 요청 3개를 **동시에** 보낸다 | 글은 하나. 세 응답 모두 같은 `postId` (`D-6`의 A) |
| 3 | 다른 `requestKey`로 같은 제목·본문을 두 번 보낸다 | 글 두 개 (일부러 두 번 쓴 경우) |
| 4 | 제목을 쓰다가 다른 화면으로 가려 한다 | "저장하지 않은 내용이 있습니다. 나갈까요?" |
| 5 | 4번에서 취소 | 입력한 내용이 그대로 남는다 |

## S-6. 글 상세 (US3)

연결: US3-1 ~ 7, FR-023 ~ 027, SC-003, NF-09

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 로그인하지 않고 A의 공개 글을 연다 | 분류, 제목, 블로그 이름, 작성 시각, 본문이 보이고 줄바꿈이 그대로다 |
| 2 | 공개 글 3개(1 → 2 → 3 순서로 씀)의 가운데 글을 연다 | 이전 글 = 1, 다음 글 = 3 |
| 3 | 첫 글과 마지막 글을 연다 | 없는 쪽 버튼이 보이지 않는다 (`null`) |
| 4 | 1과 3 사이에 비공개 글을 하나 끼워 쓰고 2를 연다 | 이전·다음에 비공개 글이 나오지 않는다 |
| 5 | `목록으로`를 누른다 | 그 글의 분류 목록으로 간다 (`004`) |
| 6 | 없는 번호(`/api/posts/999999`)를 연다 | `404` "존재하지 않는 글입니다" |
| 7 | A로 자기 글을 연다 / B로 같은 글을 연다 | A만 `isOwner: true`, 화면에 `수정`·`삭제`가 A에게만 보인다 |

## S-7. 글 수정 (US4)

연결: US4-1 ~ 3, FR-019, 020, SC-004, SC-009, `research.md` R-2

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | A가 자기 글의 제목만 바꿔 저장 | `changed: true`, `updatedAt`이 생기고 `createdAt`은 그대로 |
| 2 | 아무것도 바꾸지 않고 저장 | `changed: false`, `updatedAt` 그대로 (**DB 값도 그대로**) |
| 3 | 제목 앞뒤에 공백만 더해 저장 | 2번과 같다 (정리한 값이 같음) |
| 4 | 공개 여부만 바꿔 저장 | `updatedAt` 갱신 |
| 5 | 요청에 `createdAt`을 넣어 저장 | `createdAt`이 바뀌지 않는다 |
| 6 | B가 A의 글 수정 화면 주소를 연다 (`GET …/edit`) | `404` "존재하지 않는 글입니다" |
| 7 | B가 화면을 거치지 않고 `PUT /api/posts/{A의 글}` | `404`. DB의 글이 바뀌지 않는다 |

## S-8. 글 삭제 (US4)

연결: US4-4 ~ 7, FR-021, 022, SC-004, SC-007, `research.md` D-7, R-1

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 화면에서 `삭제` | "삭제하면 되돌릴 수 없습니다. 삭제할까요?" |
| 2 | 취소 | 요청이 가지 않고 글이 그대로 |
| 3 | 댓글(대댓글 포함), 좋아요, 태그, 이미지가 달린 글을 삭제 확인 (`005`가 만들어진 뒤) | `204`. 내 블로그 글 목록으로 이동 |
| 4 | DB에서 그 글 번호로 댓글, 좋아요, 태그 연결, 이미지 기록을 센다 | 모두 0. 태그 자체(`tag`)는 남는다 |
| 5 | 이미지 저장소에서 그 글의 파일을 찾는다 | 없다 |
| 6 | 신고가 달린 글을 삭제 | 삭제된다 (`D-7`의 A: 신고도 함께 지움) |
| 7 | 삭제 도중(댓글을 지운 뒤) 실패하도록 만든다 | 글과 댓글이 모두 그대로 남는다 (한 묶음) |
| 8 | B가 `DELETE /api/posts/{A의 글}` | `404`. 지워지지 않는다 |

> `005`가 만들어지기 전에는 3~6번 중 댓글·좋아요·태그·이미지·신고 부분을 DB에 직접 넣어서 확인한다.

## S-10. 분류 관리 (US6)

연결: US6-1 ~ 11, FR-034 ~ 043, SC-004, SC-005, SC-006, SC-010

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | A가 `일상`을 추가 | 목록 맨 아래에 생긴다 |
| 2 | `일상`, ` 일상 `을 다시 추가 | "이미 있는 분류입니다" |
| 3 | `Daily`를 만든 뒤 `daily`를 추가 | "이미 있는 분류입니다" |
| 4 | `daily` 추가 요청 두 개를 **동시에** 보낸다 (`Daily`가 없는 상태) | 하나만 생긴다 (DB 중복 불가) |
| 5 | B의 블로그에 `일상`을 만든다 | 생긴다 (다른 블로그와는 겹쳐도 된다) |
| 6 | `일상` → `여행`으로 이름을 바꾸고 그 분류의 글 상세와 블로그 화면을 연다 | 모두 `여행` |
| 7 | 순서를 바꾼다 | 블로그 화면의 분류 목록도 같은 순서 |
| 8 | 분류 번호 하나를 빼고 순서 바꾸기를 보낸다 | `400 INVALID_CATEGORY_ORDER` |
| 9 | 글 2개(공개 1, 비공개 1)가 있는 분류를 지운다 | "이 분류에 글이 2개 있어 삭제할 수 없습니다. 글을 다른 분류로 옮긴 뒤 삭제해 주세요" |
| 10 | 두 글을 글 수정에서 다른 분류로 옮긴 뒤 지운다 | 삭제된다. 옮긴 글은 새 분류에만 속하고 옛 분류 개수에서 빠졌다 |
| 11 | `미분류`를 지운다 / 이름을 `기타`로 바꾼다 | 삭제 거절 / 이름 바꾸기 성공. 이름을 바꾼 뒤에도 삭제는 거절 |
| 12 | 분류 개수를 B와 A가 각각 본다 (공개 1, 비공개 1인 분류) | B에게 1, A에게 2 |
| 13 | B가 A의 분류 번호로 이름 바꾸기·삭제를 보낸다 | `404 CATEGORY_NOT_FOUND`. 바뀌지 않는다 |
| 14 | 분류에 글이 0개라고 확인된 직후, 그 분류로 글을 쓰는 요청과 삭제 요청을 동시에 보낸다 | 둘 중 하나만 성공한다. 분류 없는 글이 생기지 않는다 (`research.md` R-3) |
| 15 | DB에서 분류가 없는 글, 분류가 없는 블로그를 센다 | 모두 0 |

## S-12. 보안 점검 (공통)

연결: FR-044, FR-045, SC-004, SC-012, NF-02, NF-07, NF-11, `research.md` D-1

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 제목에 `<script>alert(1)</script>`를 넣고 저장한 뒤 상세·목록을 연다 | 경고창이 뜨지 않고 **글자 그대로** 보인다 |
| 2 | 본문에 `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>`를 넣는다 | 실행되지 않는다. (`D-1`의 A) 글자 그대로 보인다 |
| 3 | 본문에 `[눌러 보세요](javascript:alert(1))`를 넣고 링크를 누른다 | 실행되지 않는다 (위험한 링크 차단) |
| 4 | 본문에 `**굵게**`, 목록, 이미지 문법을 쓴다 | (`D-1`의 A) 마크다운으로 그려진다. `D-1`이 정해지기 전에는 글자 그대로 |
| 5 | 블로그 이름, 소개, 분류 이름에 1번과 같은 값을 넣는다 | 실행되지 않고 글자 그대로 |
| 6 | 제목·분류 이름에 `' OR 1=1 --`, `'; DROP TABLE post; --`를 넣는다 | 그 글자 그대로 저장되고 다른 데이터가 바뀌지 않는다 |
| 7 | CSRF 토큰 없이 `POST /api/posts`, `DELETE /api/posts/{id}` | 거절된다 |
| 8 | 화면을 거치지 않고 101자 제목, 21자 분류 이름을 보낸다 | 서버가 거절한다 |
| 9 | 이상한 요청(잘못된 JSON, 숫자 자리에 글자)을 보낸다 | 오류 응답에 예외 이름, 쿼리, 파일 경로가 없다 (NF-06) |
