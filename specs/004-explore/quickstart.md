# Quickstart: 글 탐색 확인 시나리오

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/explore-api.md](contracts/explore-api.md) | **Date**: 2026-10-07

> 구현이 끝났을 때 **이 기능이 제대로 동작하는지 처음부터 끝까지 확인하는 순서**입니다. 코드는 아직 없으므로 실행 명령은 적지 않았습니다. 프로젝트 저장소가 생기면 `준비`의 빈칸을 채웁니다.
> 각 시나리오에는 연결된 사용자 이야기(US), 요구사항(FR), 성공 기준(SC)을 적었습니다. 모든 SC가 어느 시나리오에서 확인되는지는 마지막 표에 있습니다.

## 준비

| 필요한 것 | 내용 | 비고 |
|---|---|---|
| PostgreSQL | 개발용으로 띄운다 | 방법은 [가이드/03-로컬환경-도커컴포즈-사용법.md](../../docs/4-가이드/03-로컬환경-도커컴포즈-사용법.md)를 따른다. 이 기능은 Redis를 쓰지 않는다 |
| 서버 | 개발용 설정으로 실행한다 | 실행 명령은 구현 뒤에 채운다. `001`(로그인), `003`(블로그·분류·글)이 먼저 있어야 한다 |
| 확인 도구 | 화면, 또는 API 도구(예: curl, Postman) | 이 기능은 읽기(GET)만 있어서 CSRF 토큰이 필요 없다 |
| 계정 | **블로그 주인 A**, **다른 회원 B**, 그리고 **로그아웃 상태** | A, B는 `001`의 가입으로 만든다 |
| 시험용 글 | A의 블로그에 아래 글을 만든다 | `003`의 글쓰기로 만들거나 DB에 직접 넣는다 |
| 시간 줄이기 | 필요 없다. 페이지 넘김을 적은 글로 보고 싶으면 `explore.list.page-size`를 3으로 줄여도 된다 | 기본 시나리오는 **10개 기준**으로 적었다 |

**시험용 글 (A의 블로그)**

| 묶음 | 내용 |
|---|---|
| 글 25개 | 모두 공개. 분류 `미분류` 12개, `일상` 13개. 작성 시각이 서로 다르다 |
| 같은 시각 글 2개 | 작성 시각을 **똑같이** 맞춘 공개 글 둘 (DB에서 맞춘다). 먼저 만든 글 `T1`, 나중에 만든 글 `T2` |
| 긴 본문 글 1개 | 본문 150자, 중간에 줄바꿈 3개 |
| 짧은 본문 글 1개 | 본문 80자 |
| 비공개 글 2개 | 제목에 `비밀단어` |

그리고 **글이 없는 블로그**(새로 가입한 회원 C), **비공개 글만 있는 블로그**(회원 D)를 하나씩 둔다.

## S-1. 최신순 목록과 페이지 넘기기 (US1)

연결: US1-1 ~ 6, FR-001 ~ FR-005, FR-009, SC-003, SC-004, SC-005

> 아래 숫자는 위 `시험용 글` 기준이다(공개 글 29개 = 25 + 2 + 1 + 1). 로그아웃 상태로 본다.

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | A의 블로그 글 목록을 연다 | 맨 위가 가장 최근 글이다. 아래로 갈수록 오래된 글이다. 목록 위에 "29개의 글" |
| 2 | 첫 페이지의 글 수를 센다 | 정확히 10개. 페이지 번호 1, 2, 3이 보이고 1이 강조된다 |
| 3 | 첫 페이지에서 `이전`을 본다 | 눌리지 않는다 |
| 4 | 3페이지로 간다 | 9개가 보인다. `다음`이 눌리지 않는다 |
| 5 | 모든 페이지를 넘기며 위 글과 아래 글의 작성 시각을 비교한다 | 어디서든 위 글이 같거나 더 최신이다 (SC-003) |
| 6 | `T1`, `T2`가 있는 곳을 본다 | `T2`(나중에 만든 글)가 `T1` 위에 있다 |
| 7 | 주소의 페이지 번호를 `99`로 바꿔 연다 | 오류 화면 없이 3페이지(마지막)가 보이고, 3이 강조된다 (SC-005) |
| 8 | 긴 본문 글을 본다 | 분류, 작성일, 제목과 함께 본문 앞 100자가 **한 줄로** 보이고 끝에 "…"가 붙는다. 줄바꿈 자리는 공백이다 |
| 9 | 짧은 본문 글을 본다 | 80자 전체가 "…" 없이 보인다 |
| 10 | 응답을 API 도구로 본다 | 한 페이지에 11개 이상 온 적이 없다 (SC-004). `preview`가 10,000자 본문 전체가 아니다 |

## S-2. 공개 글은 누구나, 비공개는 주인만 (US2)

연결: US2-1 ~ 3, FR-006, FR-019, SC-001, SC-002

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 로그아웃 상태로 A의 목록을 연다 | 로그인 창이 뜨지 않는다. 비공개 글 2개가 **없다**. "29개의 글" |
| 2 | B로 로그인해서 A의 목록을 연다 | 1번과 같다 (비공개 없음, "29개의 글") |
| 3 | A로 로그인해서 자기 목록을 연다 | 비공개 글 2개가 **있고** "비공개" 표시가 붙는다(`003`). "31개의 글" (SC-002) |
| 4 | B로 로그인한 채 A의 목록 요청에 `visibility=private`, `includePrivate=true` 같은 값을 붙여 보낸다 | 무시된다. 비공개 글이 오지 않는다 (서버가 거름) |
| 5 | A로 로그인한 뒤 **쿠키를 지우고** 다시 연다 | 방문자로 보인다 (1번과 같음) |
| 6 | 만료된 쿠키(로그아웃한 뒤의 쿠키)로 목록을 연다 | `401`이 아니라 방문자로 보인다 |

## S-2a. 비공개 분류는 방문자에게 보이지 않는다 (US2, US4, US5)

연결: FR-006, FR-007, FR-009, FR-011, SC-001, SC-002, `research.md` D-7, `003` FR-047, `003` FR-048

> 회원 D의 블로그에 분류 `일기`를 만들고 **공개 글** 2개(제목에 `숨김단어`)를 쓴 뒤, `일기`를 비공개로 바꾼다 (`003` contracts 6). D의 다른 글은 위 `준비`대로 비공개 글뿐이다.

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 로그아웃 상태로, 또 B로 로그인해서 D의 목록을 연다 | "글이 없습니다". "0개의 글". `일기`의 공개 글 2개가 **없다** |
| 2 | 1번 상태에서 분류 고르기 목록을 본다 | `일기`가 나오지 않는다 |
| 3 | 방문자로 D의 목록 요청에 `categoryId`로 `일기`의 번호를 넣어 보낸다 | 없는 분류와 **똑같은** 응답 (`D-2`를 따른다. 추천: `404` "존재하지 않는 분류입니다"). `일기`의 글이 오지 않는다 |
| 4 | 3번의 응답과 아무 블로그에도 없는 분류 번호의 응답을 비교한다 | 같다 (비공개 분류가 있다는 것이 드러나지 않는다) |
| 5 | 로그아웃 상태로, 또 **D로 로그인한 채** `숨김단어`로 검색 | "검색 결과가 없습니다" (주인도 검색에서는 제외, FR-011) |
| 6 | D로 로그인해서 자기 목록을 연다 | `일기`의 두 글이 보이고, 분류 고르기 목록에 `일기`가 있다. `일기`를 고르면 "2개의 글" |
| 7 | D가 `일기`를 다시 공개로 바꾼 뒤 1번과 5번을 다시 한다 | 방문자에게 두 글이 보이고("2개의 글"), 검색에도 나온다 |

## S-5. 키워드로 공개 글 찾기 (US5)

연결: US5-1 ~ 7, FR-011 ~ FR-016, SC-001, SC-002, SC-003, SC-004, SC-007

> 검색용 공개 글을 따로 만든다: 제목에만 `단풍`이 있는 글 `K1`, 본문에만 `단풍`이 있는 글 `K2`, `단풍`과 `명소`가 둘 다 있는 글 `K3`(제목에 `단풍`, 본문에 `명소`), `명소`만 있는 글 `K4`, 제목이 `Spring Boot`인 글 `K5`. 다른 블로그(B)에도 `단풍` 공개 글 `K6`을 하나 만든다.

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | `단풍`으로 검색 | `K1`, `K2`, `K3`, `K6`이 나온다. 블로그가 달라도 나온다 |
| 2 | `단풍 명소`로 검색 | `K3`만 나온다. `K1`, `K4`는 나오지 않는다 (SC-007) |
| 3 | `spring boot`, `SPRING BOOT`로 각각 검색 | 둘 다 `K5`가 나오고 결과가 같다 (SC-007) |
| 4 | 로그아웃 상태로 `비밀단어`로 검색 | "검색 결과가 없습니다" (SC-001) |
| 5 | **A로 로그인한 채** `비밀단어`로 검색 | 여전히 "검색 결과가 없습니다". 자기 비공개 글도 나오지 않는다 (SC-002) |
| 6 | 맞는 공개 글이 15개가 되게 만든 뒤 검색 | "검색 결과 15건". 첫 페이지 10개, 둘째 페이지 5개. 최신 글이 위 (SC-003, SC-004) |
| 7 | 결과 한 줄을 본다 | 블로그 이름, 분류, 작성일, 제목, 본문 앞부분이 보인다 |
| 8 | `없는단어조합xyz`로 검색 | "검색 결과가 없습니다". API는 `200`과 `totalCount: 0` |

## S-6. 검색어 규칙과 특수문자 (US6)

연결: US6-1 ~ 5, FR-010, FR-017, FR-018, SC-008, `research.md` R-1

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 빈 검색창으로 검색 | 검색하지 않고 "검색어를 2자 이상 입력해 주세요" |
| 2 | 공백만 넣고 검색 | 1번과 같다 |
| 3 | `가` 한 글자로 검색 | 1번과 같다 |
| 4 | 화면을 거치지 않고 `q=%20가%20`(앞뒤 공백 + 1자)로 직접 보낸다 | `400` `SEARCH_KEYWORD_TOO_SHORT` (서버도 막는다) |
| 5 | `  단풍  `(앞뒤 공백)으로 검색 | `단풍`으로 찾은 결과와 같다. 응답의 `keyword`는 `단풍` |
| 6 | 결과 화면의 검색창을 본다. 새로고침도 해 본다 | 입력한 검색어가 그대로 남아 있다 |
| 7 | 제목이 `할인 100%`인 글과 `할인 1000원`인 글을 만든 뒤 `100%`로 검색 | `할인 100%`만 나온다. `%`가 "아무 글자"로 해석되지 않는다 (R-1) |
| 8 | 제목이 `a_b`인 글과 `axb`인 글을 만든 뒤 `a_b`로 검색 | `a_b`만 나온다 (R-1) |
| 9 | `\`, `'`, `"`, `;`, `--`, `<script>`, `(`, `)`가 든 검색어로 각각 검색 | 오류 화면이 한 번도 없다. 그 글자가 든 글이 있으면 나오고, 없으면 "검색 결과가 없습니다" (SC-008) |
| 10 | 51자 검색어를 넣는다 | `D-1` 결정에 따른다 (추천: 화면이 50자까지만 받고, 직접 보내면 서버가 거절) |

## S-9. 보안 점검 (공통)

연결: FR-006, FR-011, FR-018, SC-001, SC-008, NF-07

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 검색어에 `' OR 1=1 --`, `'; DROP TABLE post; --`를 넣는다 | 그 글자 그대로 찾는다. 비공개 글이 나오지 않고 DB가 바뀌지 않는다 |
| 2 | `page`, `categoryId`에 `1 OR 1=1`, `abc`, 아주 큰 숫자를 넣는다 | 서버 오류가 나지 않는다. 결과는 `D-2`를 따른다. 응답에 예외 이름, 쿼리, 경로가 없다 |
| 3 | 제목이 `<script>alert(1)</script>`인 공개 글을 만든 뒤 목록과 검색 결과를 연다 | 스크립트가 실행되지 않고 글자 그대로 보인다 |
| 4 | 서버 로그를 켜고 S-2, S-5를 다시 한다 | 실행된 조건에 **방문자·검색일 때 항상 공개 글 조건**이 들어 있다 |
