# Contract: 글 탐색 API (초안)

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-10-07 | **상태**: `가안`

> 화면(React)과 서버가 주고받는 **요청과 응답의 약속**입니다. 주소, 요청 값 이름, 필드 이름, 상태 코드는 모두 `가안`이고, 팀의 `API 명세서` 단계에서 다른 기능과 함께 맞춥니다. 특히 블로그와 글 상세의 주소는 `003`의 계약과 맞춰야 합니다.
> 화면에 보여 줄 문구는 `docs/상세/04-탐색.md`의 `안내 문구` 표를 **그대로** 씁니다. (문구를 바꾸면 그 표를 먼저 고칩니다.) 표에 없는 문구는 `※`로 표시했습니다.
> 오류 응답의 모양, 로그인 상태(쿠키), 로그인 요구 약속은 [`001`의 계약](../../001-member-signup-login/contracts/auth-api.md)을 그대로 씁니다.

## 공통 약속

### 요청

- 이 문서의 요청은 모두 **읽기(GET)** 이고, **로그인 없이** 부를 수 있다. (FR-019)
- 쿠키가 있으면 서버가 "누구인지" 확인해서 블로그 주인인지 본다. 쿠키가 없거나 만료되었으면 **오류 없이 방문자로** 본다. (SC-010, research B-6)
- 읽기 요청이라 CSRF 토큰은 필요 없다. (`001` research B-7)
- 요청 값은 주소 뒤의 물음표 값(query string)으로 보낸다. 서버는 이 값을 **쿼리에 이어 붙이지 않고 값으로 전달**한다. (헌법 IV, NF-07)
- 페이지 번호는 **1부터** 센다. 보내지 않으면 1이다.

### 오류 응답 (공통 모양, `001`과 같음)

```json
{
  "code": "SEARCH_KEYWORD_TOO_SHORT",
  "message": "검색어를 2자 이상 입력해 주세요"
}
```

- `code`: 화면이 어떤 상황인지 알아보는 **영문 이름**이다.
- `message`: 화면에 그대로 보여 줘도 되는 **한글 문구**다.
- **서버 내부 정보(예외 이름, 쿼리, 경로 등)는 응답에 넣지 않는다.** 특수문자가 든 검색어 때문에 서버 오류가 나더라도 같다. (SC-008)

### 목록 한 줄의 모양 (두 요청이 같이 씀)

| 필드 | 뜻 | FR |
|---|---|---|
| `postId` | 글 번호 (글 상세로 가는 데 씀, 상세는 `003`) | — |
| `title` | 제목 (글자 그대로. 화면이 스크립트로 해석하지 않고 글자로 보여 준다) | FR-005, FR-015 |
| `categoryId`, `categoryName` | 분류 | FR-005, FR-015 |
| `createdAt` | 작성 시각 (ISO 8601, 시간대 포함). 화면이 "작성일"로 보여 준다 | FR-005, FR-015 |
| `preview` | 본문 앞부분. 줄바꿈은 공백, 최대 100자, 넘으면 끝에 "…" (서버가 만든다) | FR-005 |
| `visibility` | `public` 또는 `private`. 글 목록에서 **주인에게만** `private`가 올 수 있다 (화면이 "비공개" 표시, `003`, CF-13-5) | FR-006 |

## 1. `GET /api/blogs/{blogId}/posts` — 한 블로그의 글 목록

| 항목 | 내용 |
|---|---|
| 연결 | FR-001 ~ FR-009, FR-019 |
| 요청 | `?page=2` (선택), `?categoryId=7` (선택, 고르지 않으면 모든 글) |
| 로그인 | 필요 없음. 주인이면 비공개 글과 비공개 분류의 글도 포함 |
| 성공 | `200` (아래) |

```json
{
  "blogId": 3,
  "isOwner": false,
  "categoryId": null,
  "totalCount": 25,
  "page": 3,
  "totalPages": 3,
  "pageSize": 10,
  "posts": [
    {
      "postId": 41,
      "title": "가을 산책",
      "categoryId": 7,
      "categoryName": "일상",
      "createdAt": "2026-10-05T09:30:00+09:00",
      "preview": "오늘은 공원을 한 바퀴 돌았다. 은행잎이 …",
      "visibility": "public"
    }
  ]
}
```

**동작**

1. `blogId`의 블로그가 있는지 확인한다. 없으면 `404`.
2. 쿠키의 회원이 이 블로그의 주인인지 본다. 아니면 **공개 분류의 공개 글만** 대상으로 한다(`post.visibility = 'public'` 그리고 `category.visibility = 'public'`). 비공개 분류의 글은 공개 글이어도 빠진다. 화면이 보낸 어떤 값으로도 이 조건을 바꿀 수 없다. (FR-006, research B-1, D-7)
3. `categoryId`가 있으면 그 분류가 **이 블로그의 분류인지** 확인한 뒤 조건에 더한다. (FR-007, 아니면 `D-2`) 주인이 아닌 사람이 **비공개 분류**의 번호를 보내면 **없는 분류와 똑같이** 다룬다. 응답은 `D-2`를 따른다(추천: 아래 `CATEGORY_NOT_FOUND`). 비공개 분류가 있다는 것을 알려 주지 않는다. (FR-006, research D-7)
4. 조건에 맞는 글 수를 센다 → `totalCount` ("N개의 글", FR-009).
5. 마지막 페이지를 계산한다(글이 0개면 1). 요청한 `page`가 더 크면 **마지막 페이지로 바꾼다.** 바뀐 번호를 응답의 `page`에 넣는다. (FR-004) 1보다 작거나 숫자가 아닌 값은 `D-2`(추천: 1페이지).
6. 작성 시각 내림차순, 같으면 나중에 만든 글이 위로 정렬해서 10개를 준다. (FR-001, FR-002)

**화면이 하는 일**

- `page`, `totalPages`로 페이지 번호를 그리고, 현재 페이지를 강조한다. 첫 페이지에서 `이전`, 마지막 페이지에서 `다음`을 누를 수 없게 한다. (FR-003)
- 페이지를 넘길 때 **같은 `categoryId`를 계속 보낸다.** (FR-007) 주소에 담아 두면 새로고침에도 유지된다.
- 분류 고르기 목록은 `003`의 분류 목록(`GET /api/blogs/{blogId}/categories`)을 쓴다. 방문자에게는 **비공개 분류가 빠진 목록**이 온다. (FR-006, `003` FR-048)
- 목록 위에 "{totalCount}개의 글"을 보여 준다. (FR-009)
- `totalCount`가 0이면 "글이 없습니다"를 보여 준다. `isOwner`가 참이면 "첫 글을 써 보세요"와 `글쓰기` 버튼도 보여 준다. (FR-008)
  - "첫 글을 써 보세요"는 CF-10-8 본문에 있는 문구이고, `안내 문구` 표에는 없다. 표에 더할지 확인한다. (※)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 404 | `BLOG_NOT_FOUND` | ※ 존재하지 않는 블로그입니다 | (명세에 없음. 없는 블로그의 주소로 들어왔을 때) |
| 404 | `CATEGORY_NOT_FOUND` | ※ 존재하지 않는 분류입니다 | FR-007 (`D-2` 추천안. 결정 전에는 `미정`). 방문자가 비공개 분류를 고른 경우도 같은 응답 (FR-006) |
| 400 | `INVALID_PAGE` | ※ (문구 미정) | FR-004 (`D-2`의 B를 고를 때만. 추천 A면 이 오류는 없다) |

> 글이 0개인 것은 **오류가 아니다.** `200`과 `totalCount: 0`이다. (FR-008, US3)

## 2. `GET /api/search/posts` — 공개 글 검색 (여러 블로그)

| 항목 | 내용 |
|---|---|
| 연결 | FR-010 ~ FR-018, FR-019 |
| 요청 | `?q=단풍 명소` (필수), `?page=1` (선택) |
| 로그인 | 필요 없음. 로그인해도 결과는 같다 (비공개는 항상 제외) |
| 성공 | `200` (아래) |

```json
{
  "keyword": "단풍 명소",
  "totalCount": 15,
  "page": 1,
  "totalPages": 2,
  "pageSize": 10,
  "results": [
    {
      "postId": 88,
      "blogId": 5,
      "blogName": "민지의 블로그",
      "title": "올가을 단풍 명소, 어디로 갈까",
      "categoryId": 12,
      "categoryName": "여행",
      "createdAt": "2026-10-06T20:10:00+09:00",
      "preview": "주말에 다녀온 단풍 명소 세 곳을 …"
    }
  ]
}
```

**동작**

1. `q`의 앞뒤 공백을 지운다. 지운 뒤 2자 미만(비어 있음, 공백만, 1자)이면 **검색하지 않고** `400`. (FR-010)
2. 50자를 넘으면 `D-1`(추천: `400`). 결정 전에는 `미정`.
3. 공백으로 단어를 나눈다. 단어마다 `\`, `%`, `_`를 **일반 글자로 바꾼 뒤** 값으로 전달한다. (FR-018, research R-1)
4. **공개 분류의 공개 글** 중에서 모든 단어가 제목이나 본문에 들어 있는 글을 대소문자 무시로 찾는다. 비공개 글과 비공개 분류의 글은 항상 빠진다. 주인 여부는 보지 않는다. (FR-011 ~ FR-013, research D-7)
5. 결과 수를 센다 → `totalCount` ("검색 결과 N건", FR-015).
6. 작성 시각 내림차순(같으면 나중에 만든 글이 위)으로 10개를 준다. 범위 밖 `page`는 `D-2`(추천: 1 또는 마지막 페이지). (FR-014)
7. `keyword`에는 **실제로 찾은 값**(앞뒤 공백을 지운 값)을 넣는다.
8. `results`에는 `visibility`를 넣지 않는다. (항상 공개 분류의 공개 글이므로)
9. 미리보기 길이는 `D-3`(추천: 글 목록과 같은 100자).

**화면이 하는 일**

- 요청 전에 같은 검사(앞뒤 공백 지우고 2자 이상)를 먼저 해서, 짧으면 요청하지 않고 "검색어를 2자 이상 입력해 주세요"를 보여 준다. (FR-010, 서버 검사는 마지막 방어선)
- 검색어를 주소(`/search?q=…`)에 담고, 결과 화면의 검색창에 **입력한 그대로** 다시 채운다. (FR-017)
- "검색 결과 {totalCount}건"을 보여 주고, 결과마다 블로그 이름, 분류, 작성일, 제목, 본문 앞부분을 보여 준다. (FR-015)
- `totalCount`가 0이면 "검색 결과가 없습니다"를 보여 준다. (FR-016)
- 페이지 번호와 `이전`·`다음`은 글 목록과 같게 그린다.

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `SEARCH_KEYWORD_TOO_SHORT` | 검색어를 2자 이상 입력해 주세요 | FR-010 |
| 400 | `SEARCH_KEYWORD_TOO_LONG` | ※ 검색어는 50자까지 입력할 수 있습니다 (제안) | FR-010 (`D-1`. 결정 전에는 `미정`) |
| 400 | `INVALID_PAGE` | ※ (문구 미정) | FR-014 (`D-2`의 B를 고를 때만) |

> 결과가 없는 것은 **오류가 아니다.** `200`과 `totalCount: 0`이다. (FR-016)
> 특수문자(`%`, `_`, `'`, `"`, `;`, `--`, `<script>` 등)가 들어 있어도 **오류가 아니다.** 일반 글자로 찾고 `200`을 준다. (FR-018, SC-008)

## 3. 쓰는 기능은 로그인으로 (FR-020)

글쓰기, 댓글, 좋아요, 신고, 마이페이지의 요청은 이 문서가 아니라 각 기능(`002`, `003`, `005`)의 계약에 있다. 로그인하지 않았을 때는 [`001` 계약 9](../../001-member-signup-login/contracts/auth-api.md)의 약속을 그대로 따른다.

1. 서버는 `401 UNAUTHENTICATED`를 돌려준다.
2. 화면은 하려던 화면을 기억하고 로그인 창을 띄운다.
3. 로그인하면 기억해 둔 화면으로 돌아간다.

- 화면은 로그인하지 않은 방문자에게도 이 버튼들을 보여 줄 수 있다. 누르는 순간 로그인 창을 띄운다(요청을 보내기 전에 `GET /api/auth/me`의 결과로 알 수 있다).
- **이 문서의 두 요청(1, 2)은 `401`을 돌려주지 않는다.** (FR-019, SC-010)
