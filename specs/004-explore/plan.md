## 쉬운 설명: 이 기능이 어떻게 돌아가나

```
[글 목록]  (로그인 없어도 됨)
 블로그 화면 열기 ─▶ 서버: 쿠키가 있으면 "누구인지" 확인 (001의 세션, 없으면 방문자)
                     "이 블로그의 주인인가?" 판단 ─ 주인이면 공개+비공개, 아니면 공개만
                     (분류를 골랐으면 그 분류만) 조건으로 PostgreSQL에서
                     ① 글 수를 센다 ("N개의 글")  ② 최신순으로 10개만 꺼낸다
                     본문은 앞 100자만 잘라서(줄바꿈 → 공백, 넘으면 "…") 돌려준다
 페이지 번호가 너무 크면 ─▶ 서버가 마지막 페이지로 바꿔서 돌려준다

[글 검색]  (로그인 없어도 됨)
 검색어 입력 ─▶ 서버: 앞뒤 공백 지우기 → 2~50자 확인 (짧으면 거절하고 안내)
                     공백으로 단어를 나눈다 ("단풍 명소" → "단풍", "명소")
                     단어마다 %, _ 같은 글자를 "그냥 글자"로 바꿔 둔다
                     공개 글 중에서 "모든 단어가 제목이나 본문에 들어 있는" 글을
                     대소문자 무시로 찾는다 (값은 쿼리에 끼워 넣지 않고 따로 전달)
                     ① 결과 수 ("검색 결과 N건")  ② 최신순 10개 + 블로그 이름
 비공개 글은 누가 검색하든(주인이어도) 항상 빠진다
```

## Summary

**주요 요구**: 한 블로그의 글을 최신순으로 10개씩 나눠 보고(US1), 방문자에게는 공개 글만, 주인에게는 비공개 글도 보이며(US2), 글이 없으면 안내하고(US3), 분류로 좁혀 본다(US4). 여러 블로그의 공개 글을 키워드로 찾고(US5), 검색어 규칙과 특수문자를 지킨다(US6). 쓰는 기능만 로그인으로 안내한다(US7).

**기술 방향**: 단일 서버(Spring Boot)가 **읽기 전용** 요청 두 개(글 목록, 글 검색)를 로그인 없이 받는다. "누구에게 무엇이 보이는가"는 화면이 아니라 **서버의 쿼리 조건**이 정한다. 검색은 PostgreSQL의 **단순 포함 검색(대소문자 무시)** 으로 시작한다. 이 기능은 Redis를 쓰지 않는다.

### Source Code

코드는 이 문서 저장소가 아니라 **프로젝트 저장소**에 만든다. 안의 구조는 `기술스택-아키텍처.md` 3.A의 **기능별 모듈**을 따른다. 글 목록은 `post`, 검색은 `search` 모듈에 둔다. (모두 `가안`)

```text
서버 (Spring Boot, 단일 서버)
├── post 모듈 (글)
│   ├── 컨트롤러   # GET /api/blogs/{blogId}/posts (contracts 1)
│   ├── 서비스     # 주인 판단, 보이는 대상 조건, 마지막 페이지로 바꾸기, 미리보기 만들기
│   └── 저장소     # 글 수 세기, 최신순 10개 읽기 (PostgreSQL)
├── search 모듈 (검색)
│   ├── 컨트롤러   # GET /api/search/posts (contracts 2)
│   ├── 서비스     # 검색어 다듬기·검사, 단어 나누기, 특수문자를 일반 글자로
│   └── 저장소     # 공개 글 + 모든 단어 포함 조건으로 세기·읽기
│                  # (글 표는 post 모듈의 것이므로, 읽는 입구를 post 모듈에 두고 부를지는 구현 때 정한다)
└── 공통          # 미리보기 만들기, 페이지 계산, 설정값 읽기 (두 모듈이 같이 씀)

화면 (React + Vite)
└── 블로그 글 목록(분류 선택, 페이지 번호, 빈 목록 안내), 검색창과 검색 결과 화면
```

**Structure Decision**: 화면과 서버를 나누는 **웹 애플리케이션** 구조이고, 서버는 기능별 모듈을 가진 **단일 서버**다. (확정: 단일 서버, 가안: 모듈 이름과 나눔)
