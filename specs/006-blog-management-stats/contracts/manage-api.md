# Contract: 블로그 관리·통계 API (초안)

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-10-07 | **상태**: `가안`

> 블로그 관리 화면(React)과 서버가 주고받는 **요청과 응답의 약속**입니다. 주소, 필드 이름, 상태 코드는 모두 `가안`이고, 팀의 `API 명세서` 단계에서 다른 기능과 함께 맞춥니다.
> 화면에 보여 줄 문구는 `docs/상세/06-블로그관리-통계.md`의 `안내 문구` 표를 **그대로** 씁니다. 그 표에 없는 문구는 `※`로 표시하고 어디서 왔는지 적었습니다. (문구를 바꾸면 그 표를 먼저 고칩니다.)
> 글 삭제·분류 규칙·블로그 이름 규칙은 `003`, 댓글 삭제 규칙은 `005`가 주인입니다. 이 문서의 해당 주소는 **그 기능의 처리를 그대로 부르는 것**이고, `003`·`005` plan이 다른 주소를 정하면 그쪽을 따릅니다.

## 공통 약속

### 요청

- 로그인·세션·CSRF·오류 모양은 [001 계약](../../001-member-signup-login/contracts/auth-api.md)의 `공통 약속`을 그대로 쓴다. 변경 요청(POST, PATCH, DELETE)은 CSRF 토큰을 헤더에 싣는다. (NF-11)
- 이 문서의 **모든 주소는 로그인한 블로그 주인만** 부를 수 있다.

### 블로그 주인 확인 (모든 요청, 서버가 한다 — FR-002, FR-003, 헌법 원칙 IV)

1. 로그인하지 않았으면 **`401 UNAUTHENTICATED`** — 화면은 로그인 창을 띄우고, 로그인하면 하려던 화면으로 돌아간다. ([001 계약 9](../../001-member-signup-login/contracts/auth-api.md))
2. **블로그는 주소로 받지 않는다.** 서버가 세션의 회원으로 그 회원의 블로그를 찾는다. 그래서 다른 회원의 관리 화면을 가리키는 주소가 없다.
3. 주소나 본문에 글·분류·댓글 번호가 오면, **"내 블로그 것"이라는 조건을 같은 쿼리에** 넣는다. 없으면 `404`다. (없는 것과 남의 것을 구분하지 않는다)
4. 화면에서 버튼을 숨기는 것과 상관없이, 화면을 거치지 않은 요청도 똑같이 검사한다.

### 공통 오류

| HTTP | `code` | `message` | 언제 |
|---|---|---|---|
| 401 | `UNAUTHENTICATED` | ※ 로그인이 필요합니다 (`001`에서 새로 제안한 문구) | 로그인하지 않음 (FR-002) |
| 404 | `NOT_FOUND` | ※ 찾을 수 없습니다 (새 문구. 글이면 `003`의 "존재하지 않는 글입니다"를 쓸 수 있다) | 없거나 내 블로그 것이 아님 (FR-003) |
| 400 | `VALIDATION_FAILED` | (칸마다 `fieldErrors`) | 형식이 틀림 |

- 서버 내부 정보(예외 이름, 쿼리, 경로)는 응답에 넣지 않는다. (NF-06)
- 거르기·쪽·기간 값은 **정해진 값만** 받는다. 그 밖의 값은 `400`이다. 받은 글자를 쿼리에 붙이지 않는다. (NF-07)

### 날짜와 시각

- `date`는 **한국 날짜**(`YYYY-MM-DD`)다. 시각(`createdAt` 등)은 시간대가 붙은 값(ISO 8601)이고, 화면이 한국 시간으로 보여 준다. (FR-036)

## 2. `GET /api/manage/dashboard` — 대시보드

| 항목 | 내용 |
|---|---|
| 연결 | FR-006 ~ FR-011, FR-037 |
| 요청 | 없음 |
| 성공 | `200` — 아래 |

```json
{
  "views":    { "today": 12, "yesterday": 32, "total": 1520 },
  "visitors": { "today": 8,  "yesterday": 21, "total": 940 },
  "newCommentCount": 2,
  "chart": [ { "date": "2026-09-08", "views": 0, "visitors": 0 }, "... 30일" ],
  "popularPosts": [ { "postId": 10, "title": "…", "views": 54 } ],
  "recentPosts":  [ { "postId": 12, "title": "…", "createdAt": "2026-10-07T09:10:00+09:00", "visibility": "private" } ]
}
```

- `total`의 계산은 **정하지 않았다** (`research.md` D-7).
- `chart`는 오늘 포함 30일의 **모든 날짜**이고, 기록이 없는 날은 0이다.
- `popularPosts`: 공개 글만, 최근 7일 조회수가 많은 순 5개. `views`가 7일 숫자인지 누적인지는 **`D-6`이 정해지면** 정한다.
- `recentPosts`: 비공개 포함 최근에 쓴 5개. 화면은 `visibility`가 `private`이면 "비공개" 표시를 붙인다. (FR-009)
- 글도 댓글도 없으면 숫자는 0, 두 목록은 빈 배열. 화면은 "아직 쓴 글이 없습니다"를 보여 준다. (FR-011)
- "통계 더 보기", "댓글 보기"는 화면 이동이다. (FR-007, FR-010)

**오류**: 공통 오류만.

## 3. 글 관리

### 3-1. `GET /api/manage/posts` — 내 글 목록 (비공개 포함)

| 항목 | 내용 |
|---|---|
| 연결 | FR-012 ~ FR-014, FR-017, SC-002 |
| 요청 (쿼리) | `visibility` = `all`(기본) / `public` / `private`, `categoryId`(선택), `page`(1부터, 기본 1) |
| 성공 | `200` — 아래 |

```json
{
  "items": [
    { "postId": 12, "title": "…", "category": { "categoryId": 4, "name": "일상" },
      "createdAt": "2026-10-07T09:10:00+09:00", "visibility": "private",
      "views": 0, "commentCount": 3 }
  ],
  "page": 1, "pageSize": 10, "totalCount": 11,
  "hasAnyPost": true
}
```

**동작**

1. 내 블로그 분류에 속한 글을 **비공개 포함** 모두 대상으로 한다.
2. `visibility`와 `categoryId`를 함께 주면 **둘 다 맞는** 글만. `categoryId`는 내 블로그 것이어야 한다.
3. 작성 시각 최신순(같으면 글 번호 큰 것 먼저), 한 쪽 10개(설정값).
4. `hasAnyPost`는 거르기 전 내 글이 하나라도 있는지다. 화면은 `false`면 "아직 쓴 글이 없습니다"와 글쓰기 버튼, `true`인데 `items`가 비면 "글이 없습니다"를 보여 준다. (FR-017)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | ※ 잘못된 요청입니다 (새 문구) | FR-014 (`visibility`, `page`가 정해진 값이 아님) |
| 404 | `NOT_FOUND` | ※ 찾을 수 없습니다 | FR-003 (`categoryId`가 내 블로그 것이 아님) |

### 3-2. 보기·수정·글쓰기 (FR-015, FR-016)

화면 이동만 한다. 보기는 글 상세, 수정은 글 수정 화면(CF-06), 글쓰기는 글쓰기 화면(CF-05). 주소와 규칙은 `003`.

### 3-3. `DELETE /api/posts/{postId}` — 글 삭제 (`003`의 처리)

| 항목 | 내용 |
|---|---|
| 연결 | FR-015, SC-003 |
| 요청 | 없음 |
| 성공 | `204` |

- 화면은 먼저 "삭제하면 되돌릴 수 없습니다. 삭제할까요?"(FR-015 문구, 화면의 확인 창)로 묻고, **확인했을 때만** 이 요청을 보낸다. 취소하면 보내지 않는다.
- 서버는 `003`의 규칙(작성자 본인만, 댓글·좋아요·태그 연결·이미지 함께 삭제)을 따른다. `post_daily_stat`(⚠ `D-6`)도 함께 지운다.
- 오류: `401`, 남의 글이면 `404`(`003`의 "존재하지 않는 글입니다", ※ 상세/03 문구).

## 5. 댓글 관리 (규칙은 `005`)

### 5-1. `POST /api/manage/comments/read` — 읽음 처리 (댓글 관리 화면을 열 때 먼저)

| 항목 | 내용 |
|---|---|
| 연결 | FR-029, SC-008 |
| 요청 | 없음 |
| 성공 | `200` — `{ "previousReadAt": "2026-10-06T08:00:00+09:00", "readAt": "2026-10-07T09:30:00+09:00" }` |

- 서버가 블로그의 "마지막으로 연 시각"을 **서버의 지금**으로 바꾸고 이전 값을 돌려준다. 이전 값이 없으면 `previousReadAt`은 `null`.
- **순서 약속**: 화면은 댓글 관리를 열 때 **이 요청을 먼저** 보내고, 받은 `previousReadAt`을 5-2에 실어 보낸다. (읽음 처리 뒤에 달린 댓글은 다음번 새 댓글로 남는다 — `research.md` R-4)
- 이 요청 뒤에는 메뉴 옆·사용자 메뉴·대시보드의 숫자가 모두 0이 된다(같은 계산을 쓰므로). 화면은 떠 있는 숫자를 0으로 바꾼다.

### 5-2. `GET /api/manage/comments` — 내 블로그 글의 모든 댓글

| 항목 | 내용 |
|---|---|
| 연결 | FR-023, FR-024, FR-026, FR-028 |
| 요청 (쿼리) | `page`(기본 1), `newSince`(선택, 5-1의 `previousReadAt`) |
| 성공 | `200` — 아래 |

```json
{
  "items": [
    { "commentId": 77, "author": { "nickname": "영희", "withdrawn": false },
      "createdAt": "2026-10-07T08:55:00+09:00",
      "preview": "앞 50자까지…",
      "post": { "postId": 12, "title": "…" },
      "isNew": true }
  ],
  "page": 1, "pageSize": 10, "totalCount": 23
}
```

- 작성 시각 **최신순**(새 댓글이 위), 한 쪽 10개. (FR-023)
- `preview`는 서버가 앞 50자로 자른다(설정값). 화면은 **글자 그대로** 보여 준다. (NF-07)
- `author.withdrawn`이 `true`면 `nickname`은 `null`이고, 화면은 "탈퇴한 사용자"를 보여 준다. (CF-18-6)
- `isNew` = `newSince`보다 늦게 달렸고 작성자가 블로그 주인이 아님. `newSince`가 없으면 `false`, `null`(한 번도 연 적 없음)을 보내면 남이 쓴 모든 댓글이 `true`. (FR-027, FR-028) `newSince`는 **보여 주기에만** 쓰고 권한과 상관없다.
- 글 제목을 누르면 화면이 그 글의 댓글 위치로 이동한다(주소 모양은 `005`와 맞춘다).
- 빈 목록이면 화면은 "아직 달린 댓글이 없습니다". (FR-026)

**오류**: 공통 오류. `page`·`newSince` 형식이 틀리면 `400 VALIDATION_FAILED`(※ 잘못된 요청입니다).

### 5-3. `DELETE /api/comments/{commentId}` — 댓글 삭제 (`005`의 처리)

| 항목 | 내용 |
|---|---|
| 연결 | FR-025, SC-003 |
| 성공 | `204` |

- 화면은 먼저 "댓글을 삭제할까요?"(CF-18-4 문구, 화면의 확인 창)로 묻고, **확인했을 때만** 보낸다.
- 서버는 `005`의 규칙(댓글 작성자 본인 또는 **그 글의 블로그 주인**)을 따른다. 블로그 주인은 누가 쓴 댓글이든 지울 수 있다.
- 오류: `401`, 내 블로그 글의 댓글이 아니고 내가 쓴 것도 아니면 `404`(※ 찾을 수 없습니다. `005` plan의 문구를 따른다).

## 7. `GET /api/manage/stats` — 통계

| 항목 | 내용 |
|---|---|
| 연결 | FR-031, FR-032, FR-036, FR-038 |
| 요청 (쿼리) | `days` = `7` / `30` (기본 `30`) |
| 성공 | `200` — `{ "days": 30, "daily": [ { "date": "2026-10-07", "views": 12, "visitors": 8, "comments": 1 } ] }` |

- 오늘 포함 `days`일의 **모든 날짜**, 기록이 없는 날은 0. 날짜는 한국 날짜. (FR-036)
- 화면은 `views`·`visitors`를 한 그래프에, `comments`를 다른 그래프에 그리고, 마우스를 올리면 그날 숫자를 보여 준다. (FR-032, 도구는 `D-10`)
- 유입 경로, 시간대, 기기 정보는 **응답에 없다**(저장도 하지 않는다). (FR-038, BM-06-8 `확인 필요`)

**오류**

|---|---|---|---|
| 400 | `VALIDATION_FAILED` | ※ 잘못된 요청입니다 | FR-031 (`days`가 7, 30이 아님) |

## 8. `PATCH /api/manage/blog` — 블로그 설정 저장 (규칙은 `003`)

| 항목 | 내용 |
|---|---|
| 연결 | FR-039, FR-040, FR-041, SC-010 |
| 요청 | `{ "name": "철수의 여행 블로그", "intro": "…" }` |
| 성공 | `200` — `{ "message": "※ 저장했습니다", "name": "…", "intro": "…" }` |

- `message`의 "저장했습니다"는 BM-07-2 본문의 문구 그대로이고, `안내 문구` 표에는 없다(※).
- 이름은 앞뒤 공백을 지운 뒤 1~30자, 소개는 0~200자(`003`). "n/200"은 화면이 센다.
- 저장 뒤 화면은 응답의 새 값으로 떠 있는 이름을 바로 바꾼다. 서버는 이름을 따로 기억해 두지 않아 다음 요청부터 모든 화면이 새 값을 읽는다. (FR-040)
- "데모 데이터 초기화"에 해당하는 주소는 **만들지 않는다.** (FR-041)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | (칸마다 `fieldErrors`) | FR-039, FR-040 |

`VALIDATION_FAILED`의 칸별 문구:

| `field` | `code` | `message` |
|---|---|---|
| `name` | `BLOG_NAME_REQUIRED` | 블로그 이름을 입력해 주세요 |
| `name` | `BLOG_NAME_TOO_LONG` | ※ (상세/03 규칙 1~30자. 문구는 상세/03에서 정한다) |
| `intro` | `BLOG_INTRO_TOO_LONG` | ※ (상세/03 규칙 0~200자. 문구는 상세/03에서 정한다) |

## 9. 숫자를 세는 약속 (관리 주소가 아님 — 글 상세에 붙는다)
