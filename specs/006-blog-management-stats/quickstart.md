# Quickstart: 블로그 관리와 통계 확인 시나리오

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [contracts/manage-api.md](contracts/manage-api.md) | **Date**: 2026-10-07

> 구현이 끝났을 때 **이 기능이 제대로 동작하는지 처음부터 끝까지 확인하는 순서**입니다. 코드는 아직 없으므로 실행 명령은 적지 않았습니다. 프로젝트 저장소가 생기면 `준비`의 빈칸을 채웁니다.
> 각 시나리오에는 연결된 사용자 이야기(US), 요구사항(FR), 성공 기준(SC)을 적었습니다. 모든 SC가 어느 시나리오에서 확인되는지는 마지막 표에 있습니다.
> 조회수·방문자 시나리오(S-6 ~ S-8)의 일부는 [research.md](research.md)의 `D-1`, `D-2`, `D-4`, `D-5`가 정해져야 기대 결과가 확정됩니다. 해당 줄에 표시했습니다.

|---|---|---|

| 서버 | 개발용 설정으로 실행한다 | 실행 명령은 구현 뒤에 채운다 |
| 먼저 있어야 하는 기능 | `001` 가입·로그인, `003` 블로그·분류·글, `005` 댓글 | 없으면 해당 시나리오는 뒤로 미룬다 |
| ERD 변경 | [data-model.md](data-model.md) 11번 표의 요청이 반영돼 있어야 한다 | 특히 분류 순서 칸, 새 댓글 기준 시각 칸 |
| 계정 | **주인 A**(블로그 주인), **회원 B**(다른 회원), 탈퇴할 **회원 C**, 로그인하지 않은 브라우저 | 비회원은 쿠키를 지우지 않은 **같은 브라우저 창**으로 확인 |
| 시간 줄이기 | 테스트용 설정에서 `stats.view.dedupe-window`를 짧게(예: 1분) | 이름은 [plan.md](plan.md)의 `설정값 목록` |
| 시각 맞추기 | 서버가 "지금 시각"을 한곳에서 얻으므로 테스트에서 23:59, 0:01(한국 시간)을 만들 수 있게 한다 | [research.md](research.md) B-4, R-1 |
| 확인 도구 | 화면, 또는 API 도구(예: curl, Postman) | 변경 요청은 CSRF 토큰을 싣는다(`001`) |
| 댓글 주의 | ERD `comment`의 `UNIQUE(users_id, post_id)` 표시가 그대로면 한 회원이 한 글에 댓글을 하나만 달 수 있다 | 이 경우 **서로 다른 글**에 댓글을 단다 ([research.md](research.md) R-6) |

## S-1. 주인만 관리 화면에 들어간다 (US1)

연결: US1-1 ~ 5, FR-001 ~ 005, SC-001

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 주인 A로 로그인해 사용자 메뉴를 연다 | `마이페이지`와 `블로그 관리`가 **따로** 있다 (FR-004, BM-01-3 `확인 필요`) |
| 2 | `블로그 관리`를 연다 | 왼쪽에 대시보드·글 관리·분류 관리·댓글 관리·통계·설정, 위에 블로그 이름과 "내 블로그 보기"·"글쓰기" |
| 3 | "내 블로그 보기"를 누른다 | 방문자가 보는 내 블로그 화면으로 간다 |
| 4 | 로그아웃한 상태로 관리 화면을 연다 | 로그인 창이 뜬다. 관리 주소를 화면 없이 직접 부르면 `401` |
| 5 | 회원 B로 로그인해 관리 주소들(대시보드, 글 목록, 통계 등)을 직접 부른다 | **B 자신의 블로그** 내용만 온다. A의 숫자·글·댓글은 하나도 오지 않는다 |
| 6 | 회원 B로 A의 글·분류·댓글 번호를 넣어 관리 요청(목록 거르기, 이름 바꾸기, 옮기기, 삭제)을 보낸다 | 모두 `404`. A의 데이터가 바뀌지 않는다 |

## S-2. 글 관리 (US2)

연결: US2-1 ~ 7, FR-012 ~ 017, SC-002, SC-003

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 글을 쓰지 않은 새 블로그로 글 관리를 연다 | "아직 쓴 글이 없습니다"와 글쓰기 버튼 |
| 2 | 공개 6개, 비공개 5개를 두 분류에 나눠 쓰고 글 관리를 연다 | 1쪽에 10개, 2쪽에 1개. **11개가 모두** 최신순으로 나온다 (빠짐·겹침 없음) |
| 3 | 한 줄을 본다 | 제목, 분류, 작성일, 공개 여부, 조회수, 댓글 수 |
| 4 | 공개 / 비공개 / 전체를 고른다 | 6 / 5 / 11개 |
| 5 | 분류 하나와 `비공개`를 함께 고른다 | 둘 다 맞는 글만. 맞는 글이 없으면 "글이 없습니다" |
| 6 | `보기`, `수정`, 목록 위 글쓰기를 누른다 | 글 상세, 글 수정 화면, 글쓰기 화면으로 간다 |
| 7 | `삭제` → 확인 창에서 **취소** | "삭제하면 되돌릴 수 없습니다. 삭제할까요?"가 뜨고, 취소하면 글이 남는다 |
| 8 | `삭제` → **확인** | 글이 목록에서 사라진다. 그 글의 댓글도 지워진다(`003`) |
| 9 | 화면을 거치지 않고 `visibility=abc`, `page=-1`을 보낸다 | `400`. 오류 응답에 내부 정보가 없다 |

## S-3. 분류 관리 (US3)

연결: US3-1 ~ 7, FR-018 ~ 022, SC-004

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 분류 관리를 연다 | 순서대로, 이름·글 개수(비공개 포함)·색 점. 아래에 입력칸과 "글이 하나라도 있는 분류는 삭제할 수 없습니다. 글은 글 수정에서 다른 분류로 옮길 수 있습니다." |
| 2 | 이름을 비우고(또는 공백만) 추가 | "분류 이름을 입력해 주세요". 추가되지 않는다 |
| 3 | "여행", "음식"을 차례로 추가 | 맨 아래에 붙고, 색은 정해진 순서대로 저절로 정해진다. 색 고르는 칸이 없다 |
| 4 | "음식"을 위로 옮긴다 | "음식"과 바로 위 분류의 순서가 바뀐다. **색은 그대로**다(`D-9` A일 때) |
| 5 | 맨 위 분류를 위로 옮긴다 | 바뀌는 것 없이 그대로 |
| 6 | "여행"의 이름을 바꾼다 | 목록과 그 분류의 글에 새 이름 |
| 7 | 글이 없는 분류를 삭제 | 지워진다 |
| 8 | 글이 하나라도 있는 분류를 삭제 (화면을 거치지 않은 요청 포함) | 지워지지 않는다 |
| 9 | 같은 분류의 위로 옮기기를 **동시에 여러 번** 보낸다 | 순서가 겹치거나 분류가 사라지지 않는다 |

## S-3a. 분류 공개 여부 (US3)

연결: FR-042, `003` FR-047, `003` FR-048

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 공개 글 2개가 있는 "여행"을 비공개로 바꾼다 | "여행"에 "비공개" 표시가 붙는다. 글 개수는 그대로 2 |
| 2 | 로그아웃 상태로 내 블로그를 연다 | "여행"이 분류 목록에 없고, 그 글 2개도 목록에 없다 (`003`, `004`) |
| 3 | `미분류`를 비공개로 바꾼다 | 바뀐다. "비공개" 표시가 붙는다 |
| 4 | "여행"을 다시 공개로 바꾼다 | 표시가 사라지고, 방문자에게 다시 보인다 |
| 5 | 회원 B가 A의 분류 번호로 공개 여부 바꾸기를 보낸다 | `404`. 바뀌지 않는다 |

## S-4. 댓글 관리 (US4)

연결: US4-1 ~ 6, FR-023 ~ 026, SC-003

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 댓글이 없는 블로그로 댓글 관리를 연다 | "아직 달린 댓글이 없습니다" |
| 2 | 회원 B·C가 A의 여러 글에 댓글 11개를 단 뒤 A가 연다 | 최신순(새 댓글이 위), 10개 + 1개 |
| 3 | 한 댓글을 본다 | 닉네임, 작성 시각, 내용 앞 50자, 글 제목. 60자 댓글은 50자까지만 |
| 4 | 글 제목을 누른다 | 그 글의 댓글 위치로 간다 |
| 5 | 회원 C가 탈퇴한 뒤 다시 연다 | C의 댓글이 남아 있고 작성자가 "탈퇴한 사용자" |
| 6 | B가 쓴 댓글을 `삭제` → 취소 / 확인 | "댓글을 삭제할까요?". 취소하면 남고, 확인하면 지워진다 |
| 7 | `<script>` 같은 내용이 든 댓글을 본다 | 실행되지 않고 글자 그대로 보인다 (NF-07) |

## S-5. 새 댓글 표시 (US5)

연결: US5-1 ~ 6, FR-027 ~ 030, SC-008

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | A가 댓글 관리를 한 번 연다 (기준 시각을 만든다) | 숫자가 없다 |
| 2 | 회원 B가 A의 글에 댓글 2개를 단다 | A의 ① 메뉴 `댓글 관리` 옆 ② 사용자 메뉴 ③ 대시보드에 **모두 2** |
| 3 | A가 자기 글에 댓글을 단다 | 숫자는 여전히 2 |
| 4 | A가 댓글 관리를 연다 | B의 두 댓글에만 `NEW`. 쪽을 넘겨도 `NEW`가 맞다 |
| 5 | 다른 화면으로 갔다가 세 곳을 본다 | 세 곳 **모두** 숫자가 없다 |
| 6 | B가 댓글을 하나 더 단다 | 세 곳 모두 1 |
| 7 | 읽음 처리 요청과 B의 새 댓글이 거의 동시에 일어나게 한다 | 그 댓글은 이번에 `NEW`로 보이거나, 아니면 **다음번 새 댓글로 남는다**. 보지도 못하고 사라지지 않는다 (research R-4) |
| 8 | 알림을 살펴본다 | 숫자와 `NEW`뿐. 종 모양 목록, 메일, 푸시가 없다 (BM-05-7 `확인 필요`) |

## S-6. 조회수는 같은 사람·같은 글 30분에 한 번 (US6)

연결: US6-4, US6-5, US6-8, FR-033, FR-037, SC-005

> `dedupe-window`를 1분으로 줄인 설정으로 확인한다. 방문자 구분은 `D-2`, 본인 열람은 `D-4`에 따른다.

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 회원 B가 A의 공개 글을 연다 | 그 글의 누적 조회수 +1, 오늘 조회수 +1 |
| 2 | B가 1분(=30분) 안에 같은 글을 다시 열거나 새로고침을 여러 번 한다 | 숫자가 늘지 않는다 |
| 3 | 1분이 지난 뒤 B가 다시 연다 | 다시 +1 |
| 4 | 로그인하지 않은 브라우저로 같은 글을 두 번 연다 | 처음만 +1 (같은 브라우저, 쿠키 유지) |
| 5 | B가 같은 글을 **동시에 여러 요청**으로 연다 | 정확히 +1 |
| 6 | A(주인)가 자기 글을 연다 | **`D-4`가 정해지면 확정**: 추천 A면 늘지 않는다 |
| 7 | 없는 글, 남의 비공개 글 주소를 연다 | 숫자가 늘지 않는다 |
| 8 | 글 관리 목록과 대시보드 인기 글의 숫자를 본다 | 글마다 따로 센 숫자다 (FR-037, 인기 글의 숫자 뜻은 `D-6`) |

## S-7. 방문자는 하루 한 번, 날짜는 한국 시간 자정 (US6)

연결: US6-6, US6-7, FR-034 ~ 036, SC-006, SC-007

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 회원 B가 같은 날 A의 글 3개를 연다 | 그날 방문자 **1**, 조회수 **3** |
| 2 | B가 블로그 첫 화면만 보고 나간다 | **`D-5`가 정해지면 확정**: 추천 B면 방문자 +1 |
| 3 | 지금 시각을 **23:59(한국 시간)** 로 맞추고 B가 글을 연 뒤, **다음 날 0:01**로 맞추고 다시 연다 | 두 날짜에 방문자가 **각각 1**. 그래프의 날짜도 한국 날짜 |
| 4 | 서버나 DB의 시간대가 세계 표준시(UTC)인 상태에서 한국 시간 **오전 8시**에 방문·댓글을 만든다 | 그 숫자가 **오늘**(한국 날짜)에 들어간다. 전날로 가지 않는다 (research R-1) |
| 5 | 서로 다른 두 브라우저(비회원)로 같은 날 연다 | 방문자 2 (서로 다른 사람으로 본다 — research R-2의 한계) |

## S-8. 통계 화면 (US6)

연결: US6-1 ~ 3, US6-9, FR-031, FR-032, FR-038

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 통계 화면을 처음 연다 | 30일이 골라져 있다. 7일 / 30일을 고를 수 있다 |

| 3 | 그래프를 본다 | 조회수·방문자가 한 그래프, 댓글 수가 다른 그래프. 마우스를 올리면 그날 숫자 |
| 4 | 방문이 없던 날을 본다 | 0으로 보인다 (날짜가 빠지지 않는다) |
| 5 | 화면을 거치지 않고 `days=10`을 보낸다 | `400` |
| 6 | 화면과 응답을 살펴본다 | 유입 경로, 시간대별, 기기별이 없다 (BM-06-8 `확인 필요`) |

## S-9. 대시보드 (US7)

연결: US7-1 ~ 6, FR-006 ~ 011, SC-009, SC-011

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 글·댓글이 없는 새 블로그로 대시보드를 연다 | 숫자 모두 0, 인기 글·최근 글에 "아직 쓴 글이 없습니다" |
| 2 | S-6, S-7 뒤에 대시보드를 연다 | 오늘·어제 조회수와 방문자가 통계 화면의 같은 날 숫자와 같다. 누적은 `D-7`에 따른다 |
| 3 | 그래프를 본다 | 최근 30일 일별 조회수·방문자 선 그래프. "통계 더 보기"로 통계 화면 |
| 4 | 최근 7일 조회수가 가장 많은 글을 **비공개로 바꾼 뒤** 인기 글을 본다 | 그 글이 나오지 않는다. 공개 글만 5개까지 (`D-6`) |
| 5 | 글이 6개 이상일 때 최근 글을 본다 | 최근 5개, 작성일과 함께, 비공개 글에 "비공개" |
| 6 | 새 댓글이 있을 때 본다 | 숫자가 강조되고 "댓글 보기"로 댓글 관리 |
| 7 | **사람이 직접** 로그인 상태에서 `블로그 관리`를 열어 어제 방문자와 새 댓글 수를 찾을 때까지 시간을 잰다 (SC-011 제안값) | 1분 안에 끝난다 |

## S-10. 블로그 설정 (US8)

연결: US8-1 ~ 4, FR-039 ~ 041, SC-010

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | 설정 화면을 연다 | 이름(필수, 1~30자)·소개(0~200자) 칸, 소개 아래 "n/200". "데모 데이터 초기화" 버튼이 없다 |
| 2 | 이름을 비우고 저장 | 칸 아래 "블로그 이름을 입력해 주세요". 저장되지 않는다 |
| 3 | 31자 이름, 201자 소개를 화면 없이 직접 보낸다 | 서버가 거절한다 |
| 4 | 규칙에 맞게 바꿔 저장 | "저장했습니다" |
| 5 | 관리 화면 위쪽, 내 블로그, 글 상세, 검색 결과 등 블로그 이름이 보이는 화면을 차례로 연다 | **모두** 새 이름. 옛 이름이 보이는 곳이 없다 |

## S-11. 보안 점검 (공통)

연결: FR-002, FR-003, NF-02, NF-06, NF-07, NF-11, SC-001

| # | 한다 | 기대한다 |
|---|---|---|
| 1 | **CSRF 토큰 없이** 분류 추가, 읽음 처리, 설정 저장을 보낸다 | 거절된다 |
| 2 | 거르기·기간 값에 `' OR 1=1 --` 같은 값을 넣는다 | `400`이고 DB가 바뀌지 않는다 |
| 3 | 분류 이름, 블로그 이름에 `<script>` 를 넣어 저장하고 관리 화면을 연다 | 실행되지 않고 글자 그대로 |
| 4 | 이상한 요청(잘못된 JSON, 없는 주소)을 보낸다 | 오류 응답에 예외 이름, 쿼리, 경로가 없다 |
| 5 | 방문자 쿠키의 속성과 값을 본다 | `HttpOnly`, `SameSite`. 값은 무작위이고 개인 정보가 없다 (`D-2` A일 때) |
