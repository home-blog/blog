## Summary

**주요 요구**: 로그인한 블로그 주인만 관리 화면에 들어오고(US1), 비공개 글까지 내 글을 한곳에서 관리하며(US2), 분류와 댓글을 정리하고(US3, US4), 새 댓글을 숫자와 `NEW`로 알아채며(US5), 조회수·방문자를 규칙대로 세어 통계와 대시보드로 보고(US6, US7), 블로그 이름·소개를 바꾼다(US8).

**기술 방향**: `001`~`005`와 같은 단일 서버(Spring Boot)가 모든 규칙을 검사한다. 관리 화면의 모든 요청은 **세션의 회원으로 블로그를 찾고**, 글·분류·댓글은 "내 블로그 것"인 경우에만 읽고 쓴다. 숫자는 PostgreSQL의 일별 통계 표와 글의 누적 조회수 칸에 쌓는다. "30분 안에 봤다", "오늘 왔다"를 기억하는 짧은 값은 **어디에 둘지 정하지 않았다** — 기존 가안은 Redis지만 헌법은 Redis를 이메일 인증번호에만 쓰게 한다. (`D-1`) 글 쓰기·분류 규칙은 `003`, 댓글 규칙은 `005`의 것을 그대로 부른다.

### Source Code

코드는 **프로젝트 저장소**에 만든다. 안의 구조는 `기술스택-아키텍처.md` 3장 A의 **기능별 모듈**을 따른다. 관리 화면만을 위한 모듈을 따로 만들지 않고, **그 데이터의 주인 모듈**이 관리용 주소도 가진다. (모두 `가안`)

```text
서버 (Spring Boot, 단일 서버)
├── stats 모듈 (통계)            # 이 기능의 중심
│   ├── 기록     # 글 상세를 열 때 조회수·방문자 세기 (post 모듈이 정해진 입구로 부른다)
│   ├── 집계     # 오늘·어제·누적, 7일·30일 일별, 인기 글
│   └── 컨트롤러 # 대시보드, 통계 (contracts 2, 7)
├── blog 모듈 (블로그·분류)       # 규칙은 003
│   └── 블로그 설정, 분류 관리(순서·색), 새 댓글 기준 시각 (contracts 1, 4, 8)
├── post 모듈 (글)               # 규칙은 003
│   └── 글 관리 목록(비공개 포함), 글 삭제는 003의 처리를 부른다 (contracts 3)
├── comment 모듈 (댓글)          # 규칙은 005
│   └── 댓글 관리 목록, 새 댓글 수, 읽음 처리, 삭제는 005의 처리를 부른다 (contracts 5, 6)
└── 공통 # "지금 블로그 주인은 누구" 확인, 한국 시간 날짜 계산(한곳), 설정값 읽기

화면 (React + Vite)
└── 블로그 관리: 왼쪽 메뉴 + 오른쪽 내용 (대시보드·글·분류·댓글·통계·설정)
    화면 위쪽 사용자 메뉴: 마이페이지(002) / 블로그 관리, 새 댓글 숫자
```

**Structure Decision**: 화면과 서버를 나누는 **웹 애플리케이션** 구조이고, 서버는 기능별 모듈을 가진 **단일 서버**다. (확정: 단일 서버, 가안: 모듈 나누기)
