## Summary

**주요 요구**: 로그인한 회원이 글에 댓글을 쓰고(US1) 본인 또는 블로그 주인이 지우며(US2), 남의 글에 좋아요를 누르거나 취소하고(US3), 글에 이미지를 올리고(US4), 태그를 붙여 같은 태그의 공개 글을 모아 보며(US5), 문제 있는 남의 글을 신고해 접수만 저장한다(US6).

**기술 방향**: 001과 같은 단일 서버(Spring Boot)가 모든 권한과 입력 규칙을 검사한다. 댓글·좋아요·태그·신고·이미지 기록은 PostgreSQL의 팀 ERD 표에 저장하고, "한 회원이 한 글에 하나"는 DB의 중복 불가 규칙이 마지막 방어선이다. 이미지 **파일**은 DB가 아니라 이미지 저장소에 두고 DB에는 위치만 적는다. 저장소는 `ImageStorage` 인터페이스 하나로 감싸서 MinIO와 서버 디스크를 바꿔 끼울 수 있게 한다. 이 기능에서는 Redis를 쓰지 않는 것을 추천한다(`D-2`).

### Source Code

코드는 이 문서 저장소가 아니라 **프로젝트 저장소**에 만든다. 안의 구조는 `기술스택-아키텍처.md` 3장 A의 **기능별 모듈**을 따른다. 그 목록에 `comment`(댓글)는 있지만 좋아요·태그·신고·이미지는 없어서, 아래처럼 **글에 붙는 것은 `post` 모듈 안에** 두는 것을 제안한다. (모두 `가안`)

```text
서버 (Spring Boot, 단일 서버)
├── comment 모듈 (댓글)
│   ├── 컨트롤러   # contracts 1 ~ 3
│   ├── 서비스     # 1~500자, 5초 간격, 삭제 권한(작성자 또는 블로그 주인)
│   └── 저장소     # comment (PostgreSQL)
├── post 모듈 (글, 003) 안에 더하는 것
│   ├── like       # 좋아요 누르기·취소, 개수와 "내가 눌렀나"
│   ├── tag        # 태그 규칙 검사, 글 저장 때 연결 바꾸기, 태그별 공개 글 목록
│   ├── report     # 신고 접수
│   └── image      # 이미지 검사(용량·내용), 새 이름 만들기, 이미지 기록
│       └── ImageStorage (인터페이스)
│           ├── MinIO 구현 (S3 표준 방식)     # D-1
│           └── 서버 디스크 구현              # D-1
└── 글 삭제(003)   # 위의 기록을 한 묶음으로 지운 뒤 파일을 지운다 (D-5)

화면 (React + Vite)
└── 글 상세의 댓글·좋아요·태그·신고 영역, 글쓰기 화면의 태그 입력과 이미지 올리기, 태그별 글 목록
```

- `comment` 모듈은 글을 직접 읽지 않고 `post` 모듈의 **정해진 입구**(예: "이 글을 이 사람이 볼 수 있나, 글 주인은 누구인가")만 부른다. (기술스택 3장 A의 "서로는 정해진 입구로만 부른다") `가안`

**Structure Decision**: 001과 같이 화면과 서버를 나누는 **웹 애플리케이션** 구조이고, 서버는 기능별 모듈을 가진 **단일 서버**다. (확정: 단일 서버, 가안: 모듈 이름과 나누는 방법)

| FR-007 | 탈퇴한 작성자의 댓글은 남기고, 응답에서 작성자를 "탈퇴한 사용자"로 바꿔 준다. 탈퇴를 어떻게 표시할지(회원 줄의 `deleted_at` / 댓글 작성자 칸 비우기)는 **정하지 않았다** | `미정` | research D-9 |
