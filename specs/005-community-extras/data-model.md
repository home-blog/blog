# Data Model: 소통과 부가 기능 (댓글·좋아요·태그·신고·이미지)

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-10-07

> 명세의 `Key Entities`(댓글, 좋아요, 태그, 신고, 글 이미지)를 **어디에 어떤 모양으로 저장할지** 정리합니다. 모든 내용은 `가안`입니다. 팀 공통 ERD(`comment`, `post_like`, `tag`, `post_tag`, `post_report`, `post_image`, `comment_report`)와 **맞춰야 하는 부분**은 `⚠`로 표시했습니다. 팀 ERD는 합의 없이 고치지 않으므로, `⚠`는 모두 **팀에 보낼 요청**입니다. 결정은 [research.md](research.md)의 `D-n`에 있고, **아직 하나도 정하지 않았습니다.**
> ERD 문법에는 MySQL(`COMMENT`, 백틱)과 PostgreSQL(`TIMESTAMPTZ`)이 섞여 있습니다. 실제 DDL은 구현할 때 PostgreSQL 기준으로 정리합니다. ERD의 `COMMENT 'UNIQUE(...)'`는 **설명일 뿐 실제 제약이 아니므로**, 아래 표의 중복 불가 규칙은 DDL에 제약으로 따로 적어야 합니다.

## 한눈에 보기

| 명세의 개념 | 저장 위치 | 오래 남나 | 종류 |
|---|---|---|---|
| 댓글 | PostgreSQL `comment` | 글이 있는 동안 | 팀 ERD에 있음 (⚠ `UNIQUE` 제거 필요, 쓰지 않는 칸 2개) |
| 좋아요 | PostgreSQL `post_like` | 취소하거나 글이 지워질 때까지 | 팀 ERD에 있음 (그대로 사용) |
| 태그 | PostgreSQL `tag`(이름표), `post_tag`(글-이름표 연결) | 이름표는 계속, 연결은 글이 있는 동안 | 팀 ERD에 있음 (그대로 사용, `D-10`) |
| 신고 | PostgreSQL `post_report` | 계속 (글 삭제 때는 `D-11`) | 팀 ERD에 있음 (⚠ 중복 불가 규칙 없음) |
| 글 이미지 (기록) | PostgreSQL `post_image` | 글이 있는 동안 | 팀 ERD에 있음 (⚠ `D-3`에 따라 칸 변경) |
| 글 이미지 (파일) | 이미지 저장소 (MinIO / 서버 디스크, `D-1`) | 기록과 같이 | ERD 밖 |
| 댓글 신고 | PostgreSQL `comment_report` | — | 팀 ERD에 있지만 **이번에는 쓰지 않음** (`D-8`) |
| 5초 간격 | 따로 저장하지 않음 (추천안: `comment.created_at`을 읽음) | — | `D-2` |

이 기능이 **읽기만** 하는 표: `users`(닉네임, 탈퇴 여부), `post`(공개 여부), `category`·`blog`(글 주인 찾기). 글 주인은 **`post.category_id` → `category.blog_id` → `blog.users_id`** 로 찾는다. (`post`에 작성자 칸이 없음)

## 1. 댓글 — PostgreSQL `comment`

| 칸 | 팀 ERD의 지금 모양 | 이 기능이 필요한 것 | 관련 FR |
|---|---|---|---|
| `comment_id` | BIGINT, 자동 증가, 기본키 | 그대로. 같은 시각의 댓글을 줄 세우는 데도 쓴다 | FR-003 |
| `users_id` | BIGINT, NOT NULL, 외래 키 → `users`. **⚠ `UNIQUE(users_id, post_id)`** | 쓴 회원. **⚠ `UNIQUE(users_id, post_id)`를 없애야 한다** — 그대로면 한 글에 댓글을 하나만 쓸 수 있다(`D-7`). 탈퇴해도 줄은 그대로 두는 것을 추천(`D-9`) | FR-001, FR-004, FR-007, FR-008 |
| `post_id` | BIGINT, NOT NULL, 외래 키 → `post`. ⚠ 위와 같은 `UNIQUE` | 댓글이 달린 글 | FR-003, FR-006 |
| `parent_id` | BIGINT, NULL, 외래 키 → `comment` (대댓글) | **쓰지 않는다.** 항상 비워 둔다. 명세에 대댓글이 없다(`D-7`) | — |
| `body` | VARCHAR(500), NOT NULL | 내용. 1~500자, 공백만 불가, 줄바꿈 허용. 앞뒤 공백을 지운 뒤 저장한다(research B-2) | FR-002, FR-030 |
| `is_secret` | BOOLEAN, NOT NULL, 기본 false (비밀 댓글) | **쓰지 않는다.** 항상 false. 명세에 비밀 댓글이 없다(`D-7`) | — |
| `created_at` | TIMESTAMPTZ, NOT NULL | 작성 시각. 정렬과 5초 간격(`D-2`의 A), 006의 일별 댓글 수에 쓴다 | FR-003, FR-008 |

- **수정 시각 칸이 없다**: 댓글은 고치지 않으므로(FR-005) 필요 없다. 그대로 둔다.
- **삭제 표시 칸이 없다**: 댓글 삭제는 줄을 **실제로 지운다**. (research B-3)
- **색인 (가안)**: `(post_id, created_at)` — 글 상세의 댓글 목록(오래된 순)과 댓글 수. `(users_id, created_at)` — 5초 간격 확인(`D-2`의 A). 006의 "내 블로그 글에 달린 댓글 최신순"도 `post_id`로 찾는다.

### 검증 규칙 (서버가 검사, FR-029)

| 입력 | 규칙 | FR |
|---|---|---|
| 내용 | 줄바꿈을 `\n`으로 맞추고 앞뒤 공백·줄바꿈을 지운 뒤 **1~500자**. 비면 "공백만"으로 거절 | FR-002 |
| 대상 글 | 있는 글이고, 요청한 사람이 **볼 수 있는** 글 (남의 비공개 글이면 없는 글과 같게) | FR-029 (CF-09-4) |
| 간격 | 같은 회원의 직전 댓글로부터 **5초**가 지났을 것 | FR-008 |
| 삭제 | 요청한 회원 == 댓글의 `users_id` **또는** == 글의 블로그 주인 | FR-004 |

### 댓글의 상태 변화

```
(없음) ──등록 (로그인, 1~500자, 5초 지남)──▶ 있음 ──삭제 (작성자 또는 블로그 주인)──▶ (없음)
                                              │
                                              ├─ 글 삭제 ──────────────────────────▶ (없음)  FR-006
                                              └─ 작성자 탈퇴 ─▶ 있음 (작성자는 "탈퇴한 사용자"로 보임)  FR-007, D-9
                                                  (단, 탈퇴한 사람 **자기 블로그 글**의 댓글은 블로그와 함께 지워진다 — 002)
```

- 수정 단계는 없다. (FR-005)

## 3. 태그 — PostgreSQL `tag`, `post_tag`

### `tag` (이름표)

| 칸 | 팀 ERD의 지금 모양 | 이 기능이 필요한 것 | 관련 FR |
|---|---|---|---|
| `tag_id` | BIGINT, 자동 증가, 기본키 | 그대로 | — |
| `name` | VARCHAR(15), NOT NULL, UNIQUE (설명) | 정리한 태그 이름(1~15자). **대소문자를 구분하는 비교**라서, 소문자로 바꿔 저장하면(`D-10`의 A) 그대로 대소문자 무시가 된다. B를 고르면 ⚠ 소문자 비교용 중복 불가 규칙이 필요 | FR-014 |

### `post_tag` (글-이름표 연결)

| 칸 | 팀 ERD의 지금 모양 | 이 기능이 필요한 것 | 관련 FR |
|---|---|---|---|
| `post_id` | BIGINT, NOT NULL, 외래 키 → `post`, 기본키의 일부 | 그대로 | FR-013, FR-028 |
| `tag_id` | BIGINT, NOT NULL, 외래 키 → `tag`, 기본키의 일부 | 그대로. 기본키가 `(post_id, tag_id)`라서 **같은 글에 같은 태그 두 번**은 DB가 막는다 | FR-014, SC-004 |

- **"글당 5개"는 DB가 막지 않는다.** 서버가 글 저장 때 검사한다. (DB에서 개수를 막으려면 별도 장치가 필요해서 쓰지 않는다)
- **색인 (가안)**: 태그별 글 목록을 위해 `post_tag(tag_id)` 쪽으로 찾는 색인. (기본키는 `post_id`가 앞이라 태그로 찾을 때 도움이 안 될 수 있다. 구현 때 확인)

### 검증 규칙

| 입력 | 규칙 | FR |
|---|---|---|
| 태그 하나 | 앞뒤 공백 지우기 → 앞의 `#` 모두 지우기 → **1~15자**, 공백·쉼표 없음 | FR-014 |
| 한 글의 태그 목록 | **0~5개**. 대소문자 무시로 겹치는 것이 없을 것 | FR-013, FR-014 |
| 태그별 목록 | `post.visibility = public`인 글만 | FR-015, SC-008 |

### 태그 연결의 상태 변화

```
글 저장(003) ─ 보낸 목록 [a, b] ─▶ 연결 a, b
글 수정(003) ─ 보낸 목록 [b, c] ─▶ 연결 b, c   (a 연결 삭제, c 추가 — 목록이 곧 새 전체, FR-016)
글 삭제(003) ─────────────────▶ 연결 없음  (이름표 `tag` 줄은 남는다, research B-6)
글을 비공개로 ─────────────────▶ 연결은 그대로, 태그별 목록에서만 빠짐 (research R-4)
```

## 4. 신고 — PostgreSQL `post_report`

|---|---|---|---|
| `post_report_id` | BIGINT, NOT NULL, 기본키. **⚠ 다른 표와 달리 "자동 증가" 설명이 없다** | 자동 증가로 만든다. (설명이 빠진 것으로 보이며 확인 요청) | — |

| `reason` | VARCHAR(20), NOT NULL (`SPAM, ABUSE, ADULT, OTHER`) | 네 값 중 하나만 받는다. DB에서도 이 네 값만 들어가게 막는 규칙(CHECK)을 제안 | FR-018 |

- **처리 상태 칸을 두지 않는다**: 이번 범위는 접수만 저장한다(FR-020). 관리자 기능(CF-23)을 만들 때 더한다. 운영자는 저장된 기록을 직접 본다(CF-23-1).

## 5. 글 이미지 — PostgreSQL `post_image` + 이미지 저장소

| 칸 | 팀 ERD의 지금 모양 | 이 기능이 필요한 것 | 관련 FR |
|---|---|---|---|
| `post_image_id` | BIGINT, 자동 증가, 기본키 | 그대로. 응답의 `imageId` | — |
| `post_id` | BIGINT, **NOT NULL**, 외래 키 → `post` | **⚠ `D-3`의 A를 고르면 NULL 허용**이 필요하다 (글 저장 전에 올린 이미지는 아직 글이 없다) | FR-024, FR-027 |
| `storage_key` | VARCHAR(500), NOT NULL ("파일 경로") | 저장소 안의 위치. 서버가 만든 **무작위 이름 + 확인한 형식의 확장자**(예: `posts/3f2a….webp`). 사용자가 준 이름은 쓰지 않는다. 중복 불가를 제안 | FR-022, FR-026 |
| `users_id` | **없음 ⚠** | `D-3`의 A를 고르면 필요: 올린 회원 (연결 전 이미지의 주인, 새 글의 개수 세기) | FR-024 |
| `created_at` | **없음 ⚠** | `D-3`의 A를 고르면 필요: 올린 시각 (오래 연결되지 않은 이미지 정리) | FR-027 |
| `content_type` | 없음 | 선택. 확장자에서 알 수 있으므로 없어도 된다 | FR-022 |

- **파일은 DB에 넣지 않는다.** 파일은 `ImageStorage`가 저장소(MinIO 또는 서버 디스크, `D-1`)에 두고, DB에는 `storage_key`만 적는다. 저장소를 바꿔도 `storage_key`와 이미지 주소는 그대로다. (research B-5)
- **원래 파일 이름과 용량은 저장하지 않는다.** 명세가 보여 줄 곳이 없다. 용량은 올릴 때 검사만 한다.

### 검증 규칙

| 입력 | 규칙 | FR |
|---|---|---|
| 로그인 | 필수 | FR-029 |
| 용량 | 한 장 **5MB 이하** (정확히 5MB는 통과) | FR-023 |
| 형식 | **파일 내용**이 jpg·png·gif·webp (`D-6`). 확장자만 보지 않는다 | FR-022 |
| 개수 | 한 글 **10장 이하**. 올릴 때와 글 저장 때 두 번 센다 (`D-3`) | FR-024, SC-004 |
| 대상 글 (수정 중일 때) | 내 글일 것 | FR-029 |

### 이미지의 상태 변화 (`D-3`의 A를 고른 경우)

```
(없음) ──올리기──▶ 연결 전 (post_id 없음, 올린 회원만 볼 수 있음)
                     │
                     ├─ 글 저장 때 본문에 있음 ──▶ 연결됨 (post_id 있음)
                     ├─ 글 저장 때 본문에 없음 ──▶ 기록·파일 삭제
                     └─ 오래 연결되지 않음 ─(정리 작업 @Scheduled)─▶ 기록·파일 삭제
연결됨 ──글 수정 때 본문에서 빠짐──▶ 기록·파일 삭제
연결됨 ──글 삭제──▶ 기록 삭제(묶음 안) ─▶ 파일 삭제(묶음 뒤, D-5)
```

`D-3`에서 C(글 저장 요청에 파일을 함께 보냄)를 고르면 "연결 전" 단계가 없어지고 ERD를 고치지 않아도 된다.

## 6. 댓글 신고 — PostgreSQL `comment_report` (쓰지 않음)

- 팀 ERD에 있지만 명세에 댓글 신고가 없다. **이 기능은 이 표를 쓰지 않는다.** (`D-8`)
- 이 표의 `comment_id`가 `comment`를 가리키므로, 나중에 이 표에 기록이 생기면 **댓글 삭제와 글 삭제 때 이 표도 먼저 지워야** 한다.

## 7. 글을 지울 때 함께 지우는 것 (FR-006, FR-027, FR-028, SC-005)

글 삭제는 003의 기능이고, 아래를 **한 묶음(트랜잭션)** 으로 지운다. 하나라도 실패하면 모두 취소한다.

| 순서 | 지우는 것 | 이유 |
|---|---|---|
| 1 | 그 글의 `comment` | FR-006 |
| 2 | 그 글의 `post_like` | FR-028 |
| 3 | 그 글의 `post_tag` | FR-028 |
| 4 | 그 글의 `post_report` | `D-11` (추천: 함께 삭제. 그대로면 외래 키 때문에 글을 지울 수 없다) |
| 5 | 그 글의 `post_image` 기록 (지울 파일의 `storage_key`는 기억해 둔다) | FR-027 |
| 6 | `post` | CF-05-14, CF-05-15 (003) |
| 묶음 뒤 | 저장소의 파일 | FR-027, `D-5` |

- ⚠ 팀 ERD의 외래 키에는 **"함께 지우기(`ON DELETE CASCADE`)"가 없다.** 위 순서를 서버가 지키면 ERD를 고치지 않아도 된다. 팀이 원하면 DB가 함께 지우도록 바꾸는 것을 제안한다(마지막 방어선).
- **회원 탈퇴(002)** 도 그 회원의 글마다 이 흐름을 쓴다. 그 회원이 **남의 글에 단 댓글**은 지우지 않는다(FR-007). 그 회원의 **좋아요**는 지운다(CF-15-18, 002). 그 회원이 남의 글에 한 **신고**는 명세에 없어서 남겨 두는 것을 가안으로 한다.

## 8. 이 기능이 읽거나 쓰는 표 요약

| 표 | 읽기 | 쓰기 | 언제 |
|---|---|---|---|
| `comment` | 글 상세, 5초 간격 확인, 삭제 권한 | 등록, 삭제 | 댓글 |
| `post_like` | 글 상세(개수, 내가 눌렀나) | 누르기, 취소 | 좋아요 |
| `tag`, `post_tag` | 글 상세, 태그별 목록 | 글 저장·수정(003) | 태그 |
| `post_report` | 중복 확인 | 접수 | 신고 |
| `post_image` + 저장소 | 이미지 내려 주기, 개수 세기 | 올리기, 글 저장 때 연결, 정리 | 이미지 |
| `users` | 닉네임, 탈퇴 여부(`deleted_at`) | — | 댓글 목록 |
| `post`, `category`, `blog` | 볼 수 있는 글인지, 글 주인 | — (삭제는 003) | 모든 요청 |
| `comment_report` | — | — | 쓰지 않음 |

## 9. 팀에 보낼 ERD 요청 모음 (⚠)

| 표 | 요청 | 왜 | 관련 |
|---|---|---|---|
| `comment` | `UNIQUE(users_id, post_id)` 없애기 | 한 글에 댓글을 여러 개 쓸 수 있어야 한다 | `D-7`, FR-005, FR-008 |
| `comment` | `parent_id`, `is_secret`을 둘지 확인 (이 기능은 쓰지 않음) | 명세에 대댓글·비밀 댓글이 없다 | `D-7` |
| `post_report` | `UNIQUE(users_id, post_id)` 추가, `post_report_id` 자동 증가 확인, `reason`에 CHECK 제안 | 두 번 신고 0건(SC-003) | FR-019 |
| `post_image` | `post_id` NULL 허용, `users_id`·`created_at` 추가 (`D-3`의 A일 때) | 글 저장 전에 올린 이미지 | `D-3` |
| `post_image` | `storage_key` 중복 불가 제안 | 한 파일을 두 기록이 가리키지 않게 | FR-027 |
| 여러 표 | 글을 가리키는 외래 키에 함께 지우기 검토 (선택) | 글 삭제 연쇄의 마지막 방어선 | FR-006, FR-027, FR-028 |
| `comment_report` | 이번 범위에서 쓰지 않음을 알림 | 명세는 글 신고만 | `D-8` |
| `comment.users_id` | (`D-9`의 B를 고를 때만) NULL 허용 | 탈퇴한 작성자 칸 비우기 | `D-9` |
