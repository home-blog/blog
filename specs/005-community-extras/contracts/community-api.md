# Contract: 댓글·좋아요·태그·신고·이미지 API (초안)

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-10-07 | **상태**: `가안`

> 화면(React)과 서버가 주고받는 **요청과 응답의 약속**입니다. 주소, 필드 이름, 상태 코드는 모두 `가안`이고, 팀의 `API 명세서` 단계에서 다른 기능과 함께 맞춥니다.
> 화면에 보여 줄 문구는 `docs/상세/05-소통-부가.md`의 `안내 문구` 표를 **그대로** 씁니다. "존재하지 않는 글입니다"는 `docs/상세/03-코어-블로그-글.md`의 `안내 문구` 표, "탈퇴한 사용자"는 `상세/05`의 CF-18-6 본문에서 가져왔습니다. **표에 없는 문구는 `※`로 표시**했고, 명세대로 "이유를 알려 준다"까지만 정해진 상황이라 문장은 `가안`입니다. 화면을 만들기 전에 `상세/05`의 `안내 문구` 표에 먼저 추가합니다.
> 통신은 REST(JSON)이고, 이미지 올리기만 `multipart/form-data`입니다. 로그인 상태는 쿠키로 증명합니다. (확정: 서버 세션, `가안`: REST와 JSON)

## 공통 약속

001의 [공통 약속](../../001-member-signup-login/contracts/auth-api.md)을 그대로 따릅니다. 이 기능에서 다시 적거나 더하는 것만 아래에 둡니다.

### 요청

- 본문은 JSON(`Content-Type: application/json`)이다. 이미지 올리기(10번)만 `multipart/form-data`다.
- **변경 요청(POST, PUT, DELETE)** 은 CSRF 토큰을 헤더에 싣는다. 이미지 올리기도 같다. 토큰은 `GET /api/auth/csrf`로 받는다. (NF-11)
- **회원 전용 요청**은 로그인하지 않으면 `401 UNAUTHENTICATED`다. 화면은 001 contracts 9의 약속대로 로그인 창을 띄우고, 로그인하면 하려던 화면으로 돌아간다. (FR-001, FR-009, FR-017)
- **댓글 수정 주소는 없다.** (FR-005)

### 오류 응답 (공통 모양)

001과 같다. `code`(영문 이름), `message`(화면에 보여 줄 한글 문구), 칸별 오류가 있을 때만 `fieldErrors`. **서버 내부 정보(예외 이름, 쿼리, 파일 경로, 저장소 위치)는 넣지 않는다.**

### 이 기능의 모든 요청에 공통인 오류

| HTTP | `code` | `message` | 언제 | FR |
|---|---|---|---|---|
| 401 | `UNAUTHENTICATED` | ※ 로그인이 필요합니다 (001과 같은 `※` 문구) | 회원 전용 요청인데 로그인하지 않음 | FR-001, FR-009, FR-017 |
| 404 | `POST_NOT_FOUND` | 존재하지 않는 글입니다 (`상세/03`) | 없는 글, 또는 **남의 비공개 글** (둘을 구분하지 않는다) | FR-029, CF-09-4 |
| 400 | `VALIDATION_FAILED` | (칸마다 `fieldErrors`) | 형식이 맞지 않는 요청 | FR-029 |

### 요청 검사 순서 (가안, research B-1)

1. 로그인 → 2. 볼 수 있는 글인가 → 3. 권한(자기 글 제외, 삭제 권한) → 4. 입력 규칙 → 5. 중복 → 6. 처리

## 1. `GET /api/posts/{postId}/comments` — 댓글 목록

| 항목 | 내용 |
|---|---|
| 연결 | FR-003, FR-007 |
| 누가 | 누구나 (그 글을 볼 수 있는 사람) |
| 요청 | 없음 |
| 성공 | `200` |

```json
{
  "count": 2,
  "comments": [
    {
      "id": 31,
      "author": { "id": 7, "nickname": "철수", "withdrawn": false },
      "body": "잘 읽었습니다.\n사진이 예뻐요",
      "createdAt": "2026-10-07T12:00:00+09:00",
      "canDelete": false
    },
    {
      "id": 35,
      "author": { "id": null, "nickname": null, "withdrawn": true },
      "body": "저도 가 봤어요",
      "createdAt": "2026-10-07T12:05:00+09:00",
      "canDelete": true
    }
  ]
}
```

- **오래된 댓글이 위**다. 작성 시각이 같으면 먼저 만든 댓글이 위다. (FR-003)
- 명세에 나눠 보기가 없어서 **모두 한 번에** 돌려준다. (research R-2)
- 작성자가 탈퇴했으면 `withdrawn: true`이고 **닉네임과 번호를 보내지 않는다.** 화면은 "탈퇴한 사용자"로 보여 준다. (FR-007, `D-9`)
- `canDelete`는 로그인한 회원이 댓글 작성자이거나 그 글의 블로그 주인일 때 `true`다. 화면이 삭제 버튼을 보여 줄지 정하는 **편의 값**이고, 서버는 삭제할 때 다시 검사한다. (FR-004)
- `body`는 **입력한 글자 그대로**다. 화면은 이것을 HTML로 넣지 않고 글자로만 그린다. (FR-030)
- 로그인하지 않은 사람에게는 화면이 입력칸 대신 **"로그인한 회원만 댓글을 쓸 수 있습니다"** 와 로그인 버튼을 보여 준다. 로그인 여부는 `GET /api/auth/me`로 안다. (FR-001)

**오류**: 공통 오류의 `POST_NOT_FOUND`.

## 2. `POST /api/posts/{postId}/comments` — 댓글 쓰기

| 항목 | 내용 |
|---|---|
| 연결 | FR-001, FR-002, FR-008, FR-029, FR-030 |
| 누가 | 로그인한 회원 |
| 요청 | `{ "body": "잘 읽었습니다.\n사진이 예뻐요" }` |
| 성공 | `201` — 1번 목록의 댓글 하나와 같은 모양 |

**동작**

1. 로그인과 글을 볼 수 있는지 확인한다.
2. 줄바꿈을 하나의 모양으로 맞추고 앞뒤 공백을 지운 뒤, 비어 있으면 거절하고 500자를 넘으면 거절한다. (FR-002, research B-2)
3. 같은 회원의 직전 댓글로부터 **5초**가 지나지 않았으면 거절한다. 거의 동시에 온 두 요청도 하나만 통과한다. (FR-008, `D-2`)
4. 저장하고 만든 댓글을 돌려준다. 화면은 목록 맨 아래에 붙이고 댓글 수를 하나 늘린다.

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | (`fieldErrors`의 `body`에 아래 문구) | FR-002 |
| 429 | `COMMENT_TOO_FREQUENT` | ※ 잠시 뒤에 다시 등록해 주세요 | FR-008 |
| 401 | `UNAUTHENTICATED` | (공통) | FR-001 |
| 404 | `POST_NOT_FOUND` | (공통) | FR-029 |

`VALIDATION_FAILED`의 칸별 문구:

| 상황 | `code` | `message` |
|---|---|---|
| 비어 있거나 공백만 | `COMMENT_EMPTY` | ※ 댓글 내용을 입력해 주세요 |
| 500자 초과 | `COMMENT_TOO_LONG` | ※ 댓글은 500자 이하로 입력해 주세요 |

## 3. `DELETE /api/comments/{commentId}` — 댓글 지우기

| 항목 | 내용 |
|---|---|
| 연결 | FR-004, FR-029 |
| 누가 | 댓글 작성자 본인, 또는 그 글을 쓴 블로그 주인 |
| 요청 | 없음 |
| 성공 | `204` (본문 없음) |

- **"댓글을 삭제할까요?"** 확인은 화면이 요청을 보내기 **전에** 묻는다. 취소하면 요청을 보내지 않는다. (FR-004, US2-4)
- 서버는 요청마다 **로그인한 회원 == 댓글 작성자** 또는 **== 그 글의 블로그 주인**인지 확인한다. 화면을 거치지 않은 요청도 같다. (FR-029, SC-006)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 401 | `UNAUTHENTICATED` | (공통) | FR-004 |
| 403 | `COMMENT_DELETE_FORBIDDEN` | ※ 댓글을 삭제할 권한이 없습니다 | FR-004 |
| 404 | `COMMENT_NOT_FOUND` | ※ 존재하지 않는 댓글입니다 | FR-004 |

- 남의 비공개 글에 달린 댓글을 지우려 하면 `COMMENT_NOT_FOUND`로 답한다. (그 글을 볼 수 없는 사람에게 댓글이 있다는 사실을 알리지 않는다, 가안)

## 4. `PUT /api/posts/{postId}/like` — 좋아요 누르기

| 항목 | 내용 |
|---|---|
| 연결 | FR-009, FR-010, FR-011, FR-012 |
| 누가 | 로그인한 회원 (자기 글 제외) |

- 이미 눌렀으면 아무것도 바꾸지 않고 같은 성공 응답을 준다. 거의 동시에 두 번 와도 줄은 하나다. (FR-010, research B-8, R-1)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 401 | `UNAUTHENTICATED` | (공통) — 화면은 로그인 창을 띄운다 | FR-009 |
| 403 | `SELF_LIKE_NOT_ALLOWED` | ※ 자기 글에는 좋아요를 누를 수 없습니다 | FR-012 |
| 404 | `POST_NOT_FOUND` | (공통) | FR-029 |

## 5. `DELETE /api/posts/{postId}/like` — 좋아요 취소

| 항목 | 내용 |
|---|---|
| 연결 | FR-010, FR-011 |
| 누가 | 로그인한 회원 |
| 요청 | 없음 |
| 성공 | `200` — `{ "likeCount": 12, "likedByMe": false }` |

- 누르지 않은 상태에서 취소가 와도 같은 성공 응답을 준다.

- 오류: 4번과 같다(`SELF_LIKE_NOT_ALLOWED` 제외).

## 6. `POST /api/posts/{postId}/reports` — 글 신고

| 항목 | 내용 |
|---|---|
| 연결 | FR-017 ~ FR-021 |
| 누가 | 로그인한 회원 (자기 글 제외) |
| 요청 | `{ "reason": "OTHER", "detail": "광고 링크가 반복됩니다" }` |
| 성공 | `201` — `{ "message": "신고가 접수되었습니다" }` |

- `reason`: `SPAM`(스팸), `ABUSE`(욕설·혐오), `ADULT`(음란물), `OTHER`(기타) 중 하나. (FR-018)
- `detail`: `OTHER`일 때만 0~200자로 저장한다. 비우거나 보내지 않아도 된다. 다른 사유에 보내면 **저장하지 않고 버린다**. (research B-10)
- 접수는 **저장만** 한다. 글은 전과 같이 보인다. (FR-020)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | (`fieldErrors`에 아래 문구) | FR-018 |
| 401 | `UNAUTHENTICATED` | (공통) — 화면은 로그인 창을 띄운다 | FR-017 |
| 403 | `SELF_REPORT_NOT_ALLOWED` | ※ 자기 글은 신고할 수 없습니다 | FR-017 |
| 404 | `POST_NOT_FOUND` | (공통) | FR-029 |
| 409 | `ALREADY_REPORTED` | 이미 신고한 글입니다 | FR-019 |

`VALIDATION_FAILED`의 칸별 문구:

| `field` | 상황 | `message` |
|---|---|---|
| `reason` | 없거나 네 값이 아님 | ※ 신고 사유를 골라 주세요 |
| `detail` | 200자 초과 | ※ 신고 내용은 200자 이하로 입력해 주세요 |

- 같은 회원이 거의 동시에 두 번 보내도 한 건만 접수되고 나머지는 `ALREADY_REPORTED`다. 이것은 ⚠ 팀 ERD `post_report`에 중복 불가 규칙이 더해져야 확실해진다. ([data-model.md](../data-model.md) 4)

## 7. 글 상세 응답에 더할 칸 (003의 글 상세)

글 상세 자체는 003의 계약이다. 이 기능은 응답에 아래 칸을 **더해 달라고** 요청한다. (가안)

| 칸 | 예 | 뜻 | FR |
|---|---|---|---|
| `commentCount` | `2` | 댓글 수 | FR-003 |
| `likeCount` | `13` | 좋아요 수 | FR-011 |
| `likedByMe` | `true` | 로그인한 회원이 눌렀는가 (로그인하지 않았으면 `false`) | FR-011 |
| `tags` | `["여행", "java"]` | 그 글의 태그. 글 상세 **아래**에 보여 준다 | FR-015 |

- 좋아요·신고 버튼을 자기 글에서 숨기는 것은 003의 "작성자 본인인가" 값(CF-09-5)을 같이 쓴다. 숨겨도 서버는 4번, 6번에서 다시 막는다.
- 댓글 목록은 1번으로 따로 받는다. (한 번에 받을지는 003의 계약과 맞출 때 정한다)

## 8. 글 저장·수정 요청에 더할 칸 (003의 글 저장·수정)

| 칸 | 예 | 규칙 | FR |
|---|---|---|---|
| `tags` | `["#여행", "Java"]` | 0~5개. 서버가 앞뒤 공백 → 앞의 `#` 지우기 → 1~15자, 공백·쉼표 없음 → 대소문자 무시로 겹침 확인. **보낸 목록이 새 전체 목록**이다(수정 때 빠진 태그는 연결이 지워짐). 보내지 않거나 빈 목록이면 태그 없음 | FR-013, FR-014, FR-016 |

- 어느 이미지를 그 글에 연결할지는 **본문에서 찾는다.** (`D-3`, `D-4`) 저장할 때 본문 속 이미지가 10장을 넘으면 거절한다.

**이 기능이 더하는 오류** (003 저장 요청의 `fieldErrors`에 들어감)

| `field` | `code` | `message` | FR |
|---|---|---|---|
| `tags` | `TAG_TOO_MANY` | ※ 태그는 5개까지 붙일 수 있습니다 | FR-013 |
| `tags[n]` | `TAG_INVALID` | ※ 태그는 공백과 쉼표 없이 1~15자로 입력해 주세요 | FR-014 |
| `tags[n]` | `TAG_DUPLICATED` | ※ 이미 붙인 태그입니다 | FR-014 |
| `content` | `IMAGE_LIMIT_EXCEEDED` | ※ 이미지는 글 하나에 10장까지 올릴 수 있습니다 | FR-024 |

- 화면은 태그를 하나씩 더할 때도 같은 규칙으로 바로 안내한다(보조). 서버가 저장 때 다시 검사한다. (FR-029)

| 연결 | FR-015, SC-008 |
| 누가 | 누구나 |

| 성공 | `200` |

```json
{
  "tag": "java",
  "totalCount": 23,
  "page": 1,
  "pageSize": 10,

      "categoryName": "개발",
```

- 없는 태그이거나 공개 글이 없으면 빈 목록(`200`)이고, 화면은 "글이 없습니다"(`상세/04`)를 보여 준다.

## 10. `POST /api/images` — 이미지 올리기

| 항목 | 내용 |
|---|---|
| 연결 | FR-022 ~ FR-026, FR-029 |
| 누가 | 로그인한 회원 (글쓰기·수정 중) |
| 요청 | `Content-Type: multipart/form-data` — `file`(필수, 한 장), `postId`(선택, **수정 중인 글**의 번호) |
| 성공 | `201` — `{ "imageId": 12, "url": "/api/images/3f2a9c1e-….webp" }` |

**동작** (기술스택 3장 E, research B-5)

1. 로그인 확인. `postId`가 있으면 **내 글**인지 확인한다.
2. 용량 **5MB 이하** (정확히 5MB는 통과).
3. **파일 내용**이 jpg·png·gif·webp인지 확인한다. 확장자나 브라우저가 보낸 형식 정보만 믿지 않는다. (`D-6`)
4. 개수: 수정 중인 글이면 그 글의 이미지 수, 새 글이면 아직 글에 연결되지 않은 내 이미지 수가 10장이면 거절한다. (`D-3`)
5. **서버가 새 이름**(무작위 값 + 확인한 형식의 확장자)을 만들어 저장소에 저장한다. 사용자가 준 파일 이름은 쓰지 않고 응답에도 넣지 않는다.
6. DB에 기록하고 주소를 돌려준다. 화면은 이 주소를 본문에 넣는다. (FR-026, `D-4`)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `INVALID_IMAGE` | 이미지는 5MB 이하의 jpg, png, gif, webp만 올릴 수 있습니다 | FR-022, FR-023, FR-025 |
| 409 | `IMAGE_LIMIT_EXCEEDED` | ※ 이미지는 글 하나에 10장까지 올릴 수 있습니다 | FR-024 |
| 401 | `UNAUTHENTICATED` | (공통) | FR-029 |
| 404 | `POST_NOT_FOUND` | (공통) — `postId`가 없는 글이거나 남의 글 | FR-029 |
| 503 | `STORAGE_UNAVAILABLE` | ※ 잠시 뒤 다시 시도해 주세요 (001과 같은 `※` 문구) | (저장소에 연결할 수 없을 때) |

- **5MB를 넘는 파일**은 프레임워크가 우리 코드보다 먼저 거절할 수 있다. 그때도 `400 INVALID_IMAGE`와 같은 문구로 바꿔 준다. 프레임워크가 다른 상태 코드(예: `413`)를 쓰는 경우에 맞출지는 구현 때 확인한다. (research R-6)
- 파일 여러 장은 **한 장씩 따로** 보낸다. (한 요청이 커지지 않게, 가안)

## 11. `GET /api/images/{fileName}` — 이미지 보기

| 항목 | 내용 |
|---|---|
| 연결 | FR-026 |
| 누가 | 공개 글의 이미지는 누구나. 비공개 글의 이미지는 작성자만. 아직 글에 연결되지 않은 이미지는 올린 사람만 (research B-5) |
| 성공 | `200` — 이미지 파일. `Content-Type`은 올릴 때 확인한 형식, `X-Content-Type-Options: nosniff` |
| 오류 | `404` — 없거나 볼 수 없는 이미지 (본문 없음 또는 공통 모양) |

- 저장소가 MinIO든 서버 디스크든 **이 주소는 같다.** 저장소 주소를 바깥에 보여 주지 않는다. (`D-1`)
- 오래 바뀌지 않는 파일이므로 브라우저 저장(캐시) 설정은 구현 때 정한다. 단 비공개 글의 이미지는 공용 캐시에 남지 않게 한다. (가안)
