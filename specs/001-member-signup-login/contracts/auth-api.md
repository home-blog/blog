# Contract: 회원 가입·로그인 API (초안)

**Feature**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md) | **Date**: 2026-10-07 | **상태**: `가안`

> 화면(React)과 서버가 주고받는 **요청과 응답의 약속**입니다. 주소, 필드 이름, 상태 코드는 모두 `가안`이고, 팀의 `API 명세서` 단계에서 다른 기능과 함께 맞춥니다.
> 화면에 보여 줄 문구는 `docs/2-요구사항/상세/01-인증-인가.md`의 `안내 문구` 표를 **그대로** 씁니다. 이 문서의 `message`는 그 표의 문구입니다. (문구를 바꾸면 그 표를 먼저 고칩니다.) 표에 없는 문구는 `※`로 표시했습니다.
> 통신은 REST(JSON)이고, 로그인 상태는 쿠키로 증명합니다. (확정: 서버 세션, `가안`: REST와 JSON)

## 공통 약속

### 요청

- 본문은 JSON(`Content-Type: application/json`)이다.
- **변경 요청(POST)** 은 CSRF 토큰을 헤더에 싣는다. 토큰은 `GET /api/auth/csrf`로 먼저 받는다. (NF-11)
- 이 문서의 모든 주소는 **로그인 없이** 부를 수 있다. 단, `로그아웃`은 로그인한 상태에서만 의미가 있다.

### 오류 응답 (공통 모양)

```json
{
  "code": "EMAIL_ALREADY_REGISTERED",
  "message": "이미 가입된 이메일입니다",
  "fieldErrors": [
    { "field": "email", "code": "EMAIL_ALREADY_REGISTERED", "message": "이미 가입된 이메일입니다" }
  ]
}
```

- `code`: 화면이 어떤 상황인지 알아보는 **영문 이름**이다.
- `message`: 화면에 그대로 보여 줘도 되는 **한글 문구**다.
- `fieldErrors`: 칸마다 어긴 규칙이 있을 때만 들어간다. (FR-009: 어긴 칸마다 이유를 칸 아래에 보여 준다)
- **서버 내부 정보(예외 이름, 쿼리, 경로 등)는 응답에 넣지 않는다.** (FR-035, NF-06)

### 요청 검사 순서 (가안)

1. 형식 검사 (비어 있음, 길이, 허용 글자)
2. 상태 검사 (인증됨 표시, 횟수 제한, 잠금)
3. 중복 검사
4. 처리

## 2. `POST /api/auth/email-verifications` — 인증번호 받기

| 항목 | 내용 |
|---|---|
| 연결 | FR-004, FR-005, FR-013, FR-014, FR-016, FR-018, FR-020 |
| 요청 | `{ "nickname": "철수", "email": "a@b.com" }` |
| 성공 | `200` — `{ "message": "인증번호를 보냈습니다. 10분 안에 입력해 주세요", "expiresInSeconds": 600, "verificationToken": "…" }` |

> **인증 증표 `verificationToken`** (2026-10-08, 첫 리뷰 반영): 인증번호를 받은 그 사람만 가지는 값이다. 화면은 이 값을 기억했다가 **확인(3)·이메일 변경(4)·가입(5)** 요청에 그대로 보낸다. 증표가 맞지 않으면 확인은 `CODE_EXPIRED`, 가입은 `EMAIL_NOT_VERIFIED`로 거절하고, 이메일 변경은 아무것도 하지 않는다. 남이 같은 이메일로 먼저 가입하거나(선점) 인증을 취소해 방해하는 것을 막는다.

**동작**

1. 이메일 형식과 닉네임 규칙을 검사한다. (이메일은 앞뒤 공백을 지우고 소문자로 맞춘다)
2. **이미 가입된 이메일이면 메일을 보내지 않고** 거절한다. (FR-004)
3. 이미 쓰는 닉네임이면 거절한다. (가안: 가입할 때도 한 번 더 확인한다)
4. 1분 안에 다시 요청했거나 하루 5번을 넘겼으면 거절한다. (FR-018)
5. 인증번호를 만들어 저장하고 메일을 보낸다. **메일이 나갈 때까지 기다린 뒤** 응답한다. 이전 번호는 쓸 수 없게 된다. (FR-017, `research.md` D-2)
6. 메일 발송에 실패하면 저장한 번호를 지우고, 횟수에도 넣지 않는다. (FR-020, `research.md` D-2)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `INVALID_EMAIL` | 이메일 형식이 올바르지 않습니다 | FR-003 |
| 400 | `INVALID_NICKNAME` | 닉네임은 한글, 영문, 숫자로 2~10자여야 합니다 | FR-005 |
| 409 | `EMAIL_ALREADY_REGISTERED` | 이미 가입된 이메일입니다 | FR-004 |
| 409 | `NICKNAME_ALREADY_USED` | 이미 사용 중인 닉네임입니다 | FR-005 |
| 429 | `RESEND_TOO_SOON` | 잠시 뒤에 다시 요청해 주세요 | FR-018 |
| 429 | `RESEND_DAILY_LIMIT` | 오늘은 더 이상 인증번호를 보낼 수 없습니다 | FR-018 |
| 502 | `MAIL_SEND_FAILED` | 메일을 보내지 못했습니다. 잠시 뒤 다시 시도해 주세요 | FR-020 |
| 503 | `SERVICE_UNAVAILABLE` | ※ 잠시 뒤 다시 시도해 주세요 | (인증번호 저장소에 연결할 수 없을 때, 상세/01 `구현 방식`의 문구) |

## 3. `POST /api/auth/email-verifications/confirm` — 인증번호 확인

| 항목 | 내용 |
|---|---|
| 연결 | FR-015, FR-016, FR-017, FR-019 |
| 요청 | `{ "email": "a@b.com", "code": "K7QX9M", "verificationToken": "…" }` |
| 성공 | `200` — `{ "message": "이메일 인증이 완료되었습니다" }` |

**동작**: 맞으면 인증번호를 **바로 지우고** "인증됨" 표시를 30분 동안 남긴다. 틀리면 틀린 횟수를 올리고, 5회째에 그 번호를 폐기한다. 인증번호는 대문자로 바꿔서 비교한다. (가안)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `CODE_MISMATCH` | 인증번호가 올바르지 않습니다 | FR-015 |
| 400 | `CODE_EXPIRED` | 인증번호가 만료되었습니다. 인증번호를 다시 받아 주세요 | FR-016 |
| 429 | `CODE_ATTEMPTS_EXCEEDED` | 인증번호 입력 횟수를 초과했습니다. 인증번호를 다시 받아 주세요 | FR-019 |
| 503 | `SERVICE_UNAVAILABLE` | ※ 잠시 뒤 다시 시도해 주세요 | — |

## 5. `POST /api/auth/signup` — 가입하기

| 항목 | 내용 |
|---|---|
| 연결 | FR-001 ~ FR-012, FR-022, FR-023, FR-034 |
| 요청 | `{ "nickname": "철수", "email": "a@b.com", "password": "…", "passwordConfirm": "…", "verificationToken": "…" }` |
| 성공 | `201` — `{ "message": "가입이 완료되었습니다. 로그인해 주세요" }` |

**동작**

1. 모든 칸을 서버가 다시 검사한다. (화면 검사와 상관없이 같은 규칙, FR-034)
2. 그 이메일의 **"인증됨" 표시가 아직 있는지** 확인한다. 없으면 거절한다. (FR-022)
3. 이메일과 닉네임이 아직 비어 있는지 한 번 더 확인한다. (FR-023)
4. 비밀번호를 해시로 바꿔 회원, 블로그, `미분류` 분류를 **한 번에** 저장한다. (FR-010, FR-011)
5. "인증됨" 표시를 지운다. (같은 이메일로 다시 가입할 수 없게)
6. **가입 직후 자동 로그인은 하지 않는다.** 로그인 화면으로 안내한다. (CF-01-9)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | (칸마다 `fieldErrors`로 아래 문구를 넣는다) | FR-009 |
| 409 | `EMAIL_ALREADY_REGISTERED` | 이미 가입된 이메일입니다 | FR-004, FR-023 |
| 409 | `NICKNAME_ALREADY_USED` | 이미 사용 중인 닉네임입니다 | FR-005 |
| 403 | `EMAIL_NOT_VERIFIED` | 이메일 인증을 먼저 완료해 주세요 | FR-002, FR-022 |
| 403 | `VERIFICATION_EXPIRED` | 인증 유효 시간이 지났습니다. 이메일 인증을 다시 해 주세요 | FR-022 |

> 구현 (2026-10-08): 서버의 "인증됨" 표시는 30분이 지나면 저절로 사라지므로, 서버는 "인증한 적 없음"과 "시간이 지남"을 구별하지 못하고 둘 다 `EMAIL_NOT_VERIFIED`로 답한다. **화면이 인증을 마친 상태에서 이 답을 받으면 `VERIFICATION_EXPIRED` 문구를 보여 주고** 인증을 처음부터 다시 하게 한다.

`VALIDATION_FAILED`의 칸별 문구:

| `field` | `message` |
|---|---|
| `email` | 이메일 형식이 올바르지 않습니다 |
| `nickname` | 닉네임은 한글, 영문, 숫자로 2~10자여야 합니다 |
| `password` | 비밀번호는 영문, 숫자, 특수문자를 포함해 8~20자로 입력해 주세요 |
| `passwordConfirm` | 비밀번호가 일치하지 않습니다 |

**두 번 눌러도 한 번만** (FR-012): 같은 이메일로 거의 동시에 두 요청이 와도 한 건만 성공하고 나머지는 `EMAIL_ALREADY_REGISTERED`로 거절된다. (`research.md` R-3)

**`EMAIL_NOT_VERIFIED`와 `VERIFICATION_EXPIRED` 구분 (가안)**: "인증됨" 표시가 처음부터 없었는지, 30분이 지나서 사라졌는지를 서버가 구분할 수 없으면 두 경우 모두 `EMAIL_NOT_VERIFIED`로 답할 수 있다. 구분이 필요하면 만료 직후 짧은 시간 동안 표시를 남기는 방법을 구현 때 정한다.

## 6. `POST /api/auth/login` — 로그인

| 항목 | 내용 |
|---|---|
| 연결 | FR-024 ~ FR-029, FR-030, FR-032, FR-035 |
| 요청 | `{ "email": "a@b.com", "password": "…" }` |
| 성공 | `200` — `{ "member": { "id": 1, "nickname": "철수" } }` + 세션 쿠키 |

**동작**

1. 이메일과 비밀번호가 둘 다 있어야 한다. (FR-024)
2. 계정이 잠겨 있으면 비밀번호를 비교하지 않고 거절한다. 남은 시간을 알려 준다. (FR-027)
3. 이메일이 없거나 비밀번호가 틀리면 **같은 응답**을 준다. 있는 계정이면 실패 횟수를 올리고, 5회째에 10분 동안 잠근다. (FR-026, FR-027)
4. 성공하면 실패 횟수를 0으로 되돌리고, **새 로그인 상태를 만든다.** 이전에 쓰던 값은 쓸 수 없다. (FR-028, FR-032)
5. 응답에는 **몇 번 더 틀리면 잠기는지를 넣지 않는다.** (FR-029)
6. 로그인 뒤 어디로 갈지는 **화면이 정한다.** (이전 화면 또는 첫 화면, FR-025)

**오류**

| HTTP | `code` | `message` | FR |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | (이메일 또는 비밀번호가 비어 있음) | FR-024 |
| 401 | `INVALID_CREDENTIALS` | 이메일 또는 비밀번호가 올바르지 않습니다 | FR-026 |
| 423 | `ACCOUNT_LOCKED` | 로그인 시도가 5회 실패해 잠겼습니다. {N}분 뒤에 다시 시도해 주세요 | FR-027 |

- `ACCOUNT_LOCKED`에는 남은 시간(초)을 `retryAfterSeconds`로 함께 준다. 화면이 `{N}`을 올림한 분으로 보여 준다. (가안)
- **5번째로 틀린 그 요청의 응답**은 잠금 문구(`ACCOUNT_LOCKED`)다. (US3-1)
- 가입되지 않은 이메일은 항상 `INVALID_CREDENTIALS`다. (US3-4)

## 8. `GET /api/auth/me` — 지금 로그인했는지 확인

| 항목 | 내용 |
|---|---|
| 연결 | FR-030, FR-033 |
| 요청 | 없음 |
| 성공 | `200` — `{ "member": { "id": 1, "nickname": "철수" } }` |
| 로그인하지 않았을 때 | `401` — `{ "code": "UNAUTHENTICATED", "message": "※ 로그인이 필요합니다" }` |

> `UNAUTHENTICATED`의 문구는 `안내 문구` 표에 없는 **새 문구**입니다. 화면이 보여 줄 문구가 필요하면 표에 먼저 추가합니다. (가안)

화면은 처음 열릴 때 이 요청으로 로그인 상태를 알아낸다. 로그인 후 30일이 지났거나 7일 동안 쓰지 않아 세션이 사라졌다면 `401`이 온다. (FR-030, SC-005)

## 9. 로그인이 필요한 모든 요청의 약속 (FR-033)

회원 전용 기능(글쓰기, 마이페이지, 댓글, 좋아요 등)의 요청은 로그인하지 않았을 때 **`401 UNAUTHENTICATED`** 를 돌려준다. 화면은 이 응답을 받으면 다음과 같이 한다.

1. 하려던 화면(주소)을 기억해 둔다.
2. 로그인 창을 띄운다.
3. 로그인에 성공하면 기억해 둔 화면으로 돌아간다.

이 약속은 **다른 기능의 요청에도 똑같이 적용**된다. (`002` ~ `006`의 계약에서 다시 설명하지 않고 이 문서를 가리킨다.) 권한(누가 무엇을 할 수 있는가)이 없는 경우의 `403`은 각 기능의 명세에서 정한다.
