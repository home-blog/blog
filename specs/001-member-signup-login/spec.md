# Feature Specification: 회원 가입과 로그인

**Feature Branch**: `001-member-signup-login`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "이메일 인증을 마친 사람만 회원으로 가입하고, 가입한 회원이 로그인·로그아웃할 수 있다. 로그인이 필요한 기능은 로그인으로 안내한다. (docs/2-요구사항/상세/01-인증-인가.md 기준)"

> 이 명세는 **"무엇을 할 수 있어야 하는가"만** 적습니다. 기술과 구현 방식은 `plan` 단계에서 정합니다. 괄호 안의 `CF-xx`, `NF-xx`는 기존 요구사항 문서(`docs/2-요구사항/상세/01-인증-인가.md`)의 ID입니다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 이메일 인증을 마치고 회원 가입 (Priority: P1)

방문자가 가입 화면 한 곳에서 이메일 인증을 먼저 마치고, 나머지 항목과 함께 가입한다. 인증을 마치기 전에는 계정이 만들어지지 않는다.

```
닉네임·이메일 입력 → [인증번호 받기] → 메일로 온 인증번호 입력 → [확인]
→ 비밀번호·비밀번호 확인 입력 → [가입하기] → 가입 완료
```

**Why this priority**: 회원이 없으면 글쓰기, 댓글 등 다른 모든 기능을 쓸 수 없다. 이 흐름이 서비스의 출발점이다.

**Independent Test**: 가입 화면에서 새 이메일로 인증을 마치고 가입하면 계정이 만들어지고, 같은 이메일로 다시 가입하려 하면 거절되는지 확인한다. 이것만으로 "회원이 생긴다"는 가치가 전달된다.

**Acceptance Scenarios**:

1. **Given** 가입되지 않은 이메일과 규칙에 맞는 닉네임을 입력했을 때, **When** `인증번호 받기`를 누르면, **Then** 그 이메일로 인증번호가 담긴 메일이 간다.
2. **Given** 메일로 받은 인증번호가 유효할 때, **When** 인증번호를 입력하고 `확인`을 누르면, **Then** "이메일 인증이 완료되었습니다"가 보이고 이메일 칸은 고칠 수 없게 잠긴다.
3. **Given** 이메일 인증이 끝나고 모든 칸이 규칙을 지켰을 때, **When** `가입하기`를 누르면, **Then** "가입이 완료되었습니다. 로그인해 주세요"가 보이고 로그인 화면으로 이동하며 내 블로그가 만들어진다.
4. **Given** 이미 가입된 이메일일 때, **When** `인증번호 받기`를 누르면, **Then** "이미 가입된 이메일입니다"가 보이고 메일은 보내지 않는다.
5. **Given** 이메일 인증을 마치지 않았을 때, **When** 가입 요청을 보내면(화면을 거치지 않은 요청 포함), **Then** "이메일 인증을 먼저 완료해 주세요"가 보이고 계정은 만들어지지 않는다.

### User Story 2 - 로그인과 로그아웃 (Priority: P1)

가입한 회원이 이메일과 비밀번호로 로그인하고, 다시 로그인하지 않아도 일정 기간 로그인 상태를 유지하며, 원할 때 로그아웃한다.

**Why this priority**: 가입만으로는 회원 기능을 쓸 수 없다. 로그인이 있어야 글쓰기, 댓글, 좋아요가 가능하다.

**Independent Test**: 가입된 계정으로 로그인해 첫 화면으로 이동하는지, 브라우저를 닫았다 열어도 로그인 상태인지, 로그아웃하면 바로 로그인 전 상태가 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입된 계정일 때, **When** 올바른 이메일과 비밀번호로 로그인하면, **Then** 로그인 전에 보던 화면으로 돌아간다. 로그인 화면에서 직접 왔다면 첫 화면으로 간다.
2. **Given** 이메일이 없거나 비밀번호가 틀렸을 때, **When** 로그인하면, **Then** 어느 쪽이 틀렸든 "이메일 또는 비밀번호가 올바르지 않습니다"만 보인다.
3. **Given** 로그인한 회원이 마지막으로 사용한 지 7일이 지나지 않았을 때, **When** 브라우저를 닫았다가 다시 열면, **Then** 다시 로그인하지 않아도 된다.
4. **Given** 로그인한 상태일 때, **When** 로그아웃을 누르면, **Then** 바로 로그인 전 상태가 되고, 로그인이 필요한 화면에 있었다면 첫 화면으로 이동한다.
5. **Given** 로그인한 지 30일이 지났을 때, **When** 그동안 계속 사용했더라도 다음 요청을 하면, **Then** 다시 로그인하도록 안내한다.

---

### User Story 3 - 로그인 연속 실패 시 계정 보호 (Priority: P2)

같은 계정으로 로그인에 연속 5회 실패하면 일정 시간 동안 로그인을 막아, 남이 비밀번호를 계속 시도하지 못하게 한다.

**Why this priority**: 서비스를 쓰는 데 꼭 필요한 기능은 아니지만, 계정을 지키는 기본 장치다. P1이 끝난 뒤에 더한다.

**Independent Test**: 같은 계정으로 5번 연속 틀리게 로그인한 뒤, 올바른 비밀번호로도 로그인이 막히는지, 10분 뒤 풀리는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 계정으로 연속 4회 실패했을 때, **When** 5번째로 실패하면, **Then** "로그인 시도가 5회 실패해 잠겼습니다. {N}분 뒤에 다시 시도해 주세요"가 보이고 계정이 잠긴다.
2. **Given** 계정이 잠겨 있을 때, **When** 올바른 비밀번호로 로그인하면, **Then** 로그인되지 않고 남은 시간이 안내된다.
3. **Given** 잠금 시간(10분)이 지났을 때, **When** 로그인하면, **Then** 실패 횟수가 0으로 돌아가 정상 로그인된다.
4. **Given** 가입되지 않은 이메일일 때, **When** 로그인에 실패하면, **Then** 잠금 기록은 남지 않고 화면에는 일반 실패 문구만 보인다.

---

### User Story 4 - 로그인이 필요한 기능에서 로그인으로 안내 (Priority: P3)

로그인하지 않은 사람이 회원 전용 기능(글쓰기, 마이페이지, 댓글, 좋아요 등)을 누르면 로그인 창을 보여 주고, 로그인하면 하려던 화면으로 돌아간다.

**Why this priority**: 편의 기능이다. 없어도 로그인 화면으로 직접 갈 수 있다.

**Independent Test**: 로그아웃 상태에서 `글쓰기`를 누르면 로그인 창이 뜨고, 로그인하면 글쓰기 화면으로 돌아가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않았을 때, **When** 회원 전용 기능을 누르면, **Then** 로그인 창이 뜬다.
2. **Given** 로그인 창이 떠 있을 때, **When** 로그인에 성공하면, **Then** 하려던 화면으로 돌아간다.

---

### Edge Cases

- 인증을 마친 뒤 **30분이 지나서** 가입하면? → "인증 유효 시간이 지났습니다. 이메일 인증을 다시 해 주세요"를 보여 주고 다시 인증하게 한다.
- 인증하는 동안 **다른 사람이 같은 이메일로 먼저 가입**하면? → 가입할 때 거절한다. (CF-01-21)
- 인증번호를 **연속 5회 틀리면?** → 그 번호는 더 쓸 수 없고 새로 받아야 한다.
- 인증번호가 **10분이 지나면?** → "인증번호가 만료되었습니다. 인증번호를 다시 받아 주세요"를 보여 준다.
- 인증번호를 **너무 자주 다시 받으면?** → 1분에 1번, 하루 5번까지만 허용하고 문구로 알린다.
- **메일 발송에 실패하면?** → "메일을 보내지 못했습니다. 잠시 뒤 다시 시도해 주세요"를 보여 주고 다시 받기를 누를 수 있다.
- 인증을 마친 뒤 **이메일을 바꾸면?** → 인증이 취소되어 다시 받아야 한다.
- `가입하기`를 **연속으로 눌러도** 한 번만 처리한다.
- **잠금 중에** 올바른 비밀번호를 넣으면? → 로그인되지 않는다.
- **몇 번 더 틀리면 잠기는지**는 알려 주지 않는다. (계정이 있는지 짐작하지 못하게)

## Requirements *(mandatory)*

### Functional Requirements

**가입**

- **FR-001**: 가입에는 닉네임, 이메일, 인증번호, 비밀번호, 비밀번호 확인이 모두 필요하다. (CF-01-1)
- **FR-002**: `가입하기`는 이메일 인증을 마치고 모든 칸이 규칙을 지켰을 때만 누를 수 있다. (CF-01-1)
- **FR-003**: 이메일은 이메일 형식이어야 한다. 앞뒤 공백은 지우고 대소문자는 구분하지 않는다. (CF-01-2)
- **FR-004**: 이미 가입된 이메일로는 가입할 수 없다. **인증번호를 보내기 전에** 검사해서, 이미 가입된 이메일에는 메일을 보내지 않는다. (CF-14-1)
- **FR-005**: 닉네임은 2~10자이고 한글, 영문, 숫자만 쓸 수 있다. 공백과 특수문자는 쓸 수 없고, 다른 회원과 같은 닉네임은 쓸 수 없다. 영문 대소문자는 같은 것으로 본다. (CF-01-3)
- **FR-006**: 비밀번호는 영문, 숫자, 특수문자를 각각 1개 이상 포함하고 8~20자여야 한다. 공백은 쓸 수 없고, 쓸 수 있는 특수문자는 `! @ # $ % ^ & * ( ) _ + - =` 이다. (CF-01-4)
- **FR-007**: 비밀번호와 비밀번호 확인이 같아야 한다. 다르면 확인칸 아래에 알려 준다. (CF-01-5)
- **FR-008**: 비밀번호를 입력하는 동안 규칙(글자 수, 영문, 숫자, 특수문자)을 충족했는지 칸 아래에 바로 보여 준다. (CF-01-6)
- **FR-009**: 규칙을 어긴 칸마다 이유를 칸 아래에 보여 주고, 맨 위의 어긴 칸으로 커서를 옮긴다. 다른 칸에 쓴 값은 지우지 않고, 비밀번호 칸은 비운다. (CF-01-7)
- **FR-010**: 비밀번호의 원문은 저장하지 않는다. 데이터, 로그, 오류 메시지 어디에도 남기지 않으며 운영자도 알 수 없다. (CF-01-8, NF-01)
- **FR-011**: 가입을 마치면 계정이 만들어져 바로 쓸 수 있고, 내 블로그가 함께 만들어진다. 가입을 마친 계정은 바로 로그인할 수 있다. (CF-01-9, CF-02-4)
- **FR-012**: `가입하기`를 연속으로 눌러도 한 번만 처리한다. (CF-01-10)

**이메일 인증**

- **FR-013**: 닉네임과 이메일이 형식에 맞으면 `인증번호 받기`를 누를 수 있고, 누르면 그 이메일 주소로 인증번호를 보낸다. 네이버, 구글 등 어떤 이메일 주소든 쓸 수 있다. (CF-01-11)
- **FR-014**: 인증번호는 영문 대문자와 숫자로 된 6자리 무작위 문자열이고, 헷갈리는 `O`, `0`, `I`, `1`은 쓰지 않는다. 메일에는 서비스 이름, 인증번호, 유효 시간, "본인이 요청하지 않았다면 이 메일을 무시해 주세요"가 들어간다. (CF-01-12)
- **FR-015**: 인증번호를 입력하고 `확인`을 누르면, 맞으면 "이메일 인증이 완료되었습니다"를 보여 주고 이메일 칸을 잠근다. 틀리면 "인증번호가 올바르지 않습니다"를 보여 준다. (CF-01-13)
- **FR-016**: 인증번호의 유효 시간은 10분이다. (CF-01-14)
- **FR-017**: 인증번호는 맞게 입력하는 순간 사라져서 다시 쓸 수 없다. 새로 받으면 이전 번호는 쓸 수 없다. (CF-01-15, NF-05)
- **FR-018**: 인증번호는 1분에 한 번, 하루 5번까지 다시 받을 수 있다. (CF-01-16)
- **FR-019**: 인증번호를 연속 5회 틀리면 그 번호는 더 쓸 수 없고 새로 받아야 한다. (CF-01-17)
- **FR-020**: 메일 발송에 실패하면 안내 문구를 보여 주고 다시 받기를 누를 수 있다. (CF-01-18)
- **FR-021**: 인증을 마친 뒤 이메일을 바꾸려면 `이메일 변경`을 눌러야 하고, 그러면 인증이 취소된다. (CF-01-19)
- **FR-022**: `가입하기`를 누르면 그 이메일의 인증이 아직 유효한지 다시 확인한다. 인증 후 30분 안에 가입해야 하며, 화면을 거치지 않은 요청도 같은 규칙으로 거절한다. (CF-01-20)
- **FR-023**: 인증하는 동안 다른 사람이 같은 이메일로 먼저 가입했다면 가입할 때 거절한다. (CF-01-21)

**로그인·로그아웃**

- **FR-024**: 로그인에는 이메일과 비밀번호가 모두 필요하다. (CF-02-1)
- **FR-025**: 로그인에 성공하면 로그인 전에 보던 화면으로 돌아가고, 로그인 화면에서 직접 왔다면 첫 화면으로 간다. (CF-02-2)
- **FR-026**: 이메일이 없거나 비밀번호가 틀려도 같은 문구를 보여 주며, 가입된 이메일인지는 알려 주지 않는다. (CF-02-3, CF-02-9, NF-06)
- **FR-027**: 같은 계정에서 연속 5회 로그인에 실패하면 그 계정을 10분 동안 잠그고, 이 동안에는 비밀번호가 맞아도 로그인할 수 없다. 남은 시간은 안내한다. (CF-02-5, CF-02-6)
- **FR-028**: 잠금 시간이 지나면 자동으로 풀리고 실패 횟수가 0이 된다. 로그인에 성공해도 0이 된다. (CF-02-7)
- **FR-029**: 몇 번 더 틀리면 잠기는지는 알려 주지 않는다. (CF-02-8)
- **FR-030**: 로그인한 회원은 마지막으로 사용한 때부터 7일 동안 다시 로그인하지 않아도 된다. 계속 쓰면 기간이 연장되고, 브라우저를 닫아도 유지된다. 다만 로그인한 때부터 30일이 지나면 계속 쓰고 있어도 다시 로그인해야 한다. `로그인 상태 유지` 체크박스는 두지 않고, 항상 이 규칙으로 유지한다. (CF-02-10)
- **FR-031**: 로그아웃을 누르면 바로 로그인 전 상태가 된다. 로그인이 필요한 화면에 있었다면 첫 화면으로 이동한다. (CF-02-11)
- **FR-032**: 로그인할 때마다 새로운 로그인 상태를 만든다. 로그인 전에 남이 알아낸 값으로는 로그인 상태를 얻을 수 없다. (NF-12)

**로그인 유도**

- **FR-033**: 로그인하지 않고 회원 전용 기능(글쓰기, 마이페이지, 댓글, 좋아요 등)을 누르면 로그인 창을 띄우고, 로그인하면 하려던 화면으로 돌아간다. (CF-16-1)

**공통**

- **FR-034**: 위의 모든 입력 규칙은 화면 검사와 상관없이, 화면을 거치지 않은 요청에도 똑같이 적용한다. (NF-02의 취지)
- **FR-035**: 오류 메시지는 계정이 있는지, 시스템 내부가 어떤지 드러내지 않는다. (NF-06)
- **FR-036**: 가입과 로그인은 암호화된 연결로 한다. (배포 시) (NF-04)

### Key Entities *(include if feature involves data)*

- **회원**: 서비스에 가입한 사람. 이메일(중복 불가), 닉네임(중복 불가), 비밀번호(원문은 저장하지 않음), 가입 시각, 연속 로그인 실패 횟수, 잠금 해제 시각을 가진다. 가입하면 블로그 하나가 함께 만들어진다.
- **이메일 인증**: 가입 전에 이메일 주소가 본인 것임을 확인한 기록. 이메일, 인증번호, 유효 시간, 틀린 횟수, 다시 받은 횟수, 인증 완료 여부를 가지며, 가입이 끝나면 쓸모가 없어진다.
- **로그인 상태**: 회원이 로그인해 있다는 기록. 마지막으로 사용한 시각을 기준으로 7일 동안 유지되고, 로그인한 때부터 최대 30일까지만 이어진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이메일 인증을 마치지 않고 만들어진 계정은 0개다. 인증 없이 가입을 시도한 경우는 모두 거절된다.
- **SC-002**: 같은 이메일 또는 같은 닉네임(대소문자 무시)으로 중복 가입된 계정은 0개다.
- **SC-003**: 로그인 실패 시 보이는 문구는 이메일이 없는 경우와 비밀번호가 틀린 경우에 100% 같다.
- **SC-004**: 같은 계정으로 연속 5회 실패하면 6번째 시도부터 올바른 비밀번호로도 로그인이 막히고, 10분 뒤에는 다시 로그인된다.
- **SC-005**: 마지막 사용 후 7일 안에 다시 방문하면 로그인 없이 쓸 수 있고, 7일이 지나면 로그인을 요구한다. 계속 사용하더라도 로그인한 지 30일이 지나면 로그인을 요구한다.
- **SC-006**: 처음 가입하는 사람이 가입 화면을 열어서 가입을 마칠 때까지 5분 안에 끝낸다. (제안값)
