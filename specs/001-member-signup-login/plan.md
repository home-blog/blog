## 쉬운 설명: 이 기능이 어떻게 돌아가나

```
[가입]
 닉네임·이메일 입력 ─▶ 서버: 가입된 이메일인지 확인 ─▶ 인증번호 6자리를 만들어 Redis에 저장(10분)
                       메일 발송(SMTP) ─▶ 사용자 메일함
 인증번호 입력 ─────▶ 서버: Redis의 번호와 비교 ─ 맞으면 번호 삭제 + "인증됨" 표시(30분)
 비밀번호 입력 [가입하기] ─▶ 서버: 모든 칸 다시 검사 + "인증됨" 표시 확인 + 중복 확인
                       비밀번호를 BCrypt로 해시 ─▶ PostgreSQL에 회원·블로그·"미분류"를 한 번에 저장

[로그인]
 이메일·비밀번호 ─▶ 서버: 잠겨 있는지 확인 ─▶ 해시 비교 ─ 틀리면 실패 횟수 +1 (5회면 10분 잠금)
                       맞으면 세션을 만들어 PostgreSQL에 저장, 세션 번호를 쿠키로 전달
 이후 모든 요청 ─▶ 쿠키의 세션 번호로 "누구인지" 확인 (마지막 사용 후 7일, 로그인 후 최대 30일)
```

## Summary

**주요 요구**: 이메일 인증을 마친 사람만 회원으로 가입하고(US1), 가입한 회원이 이메일·비밀번호로 로그인·로그아웃하며(US2), 연속 5회 실패하면 10분 동안 잠그고(US3), 로그인이 필요한 기능에서는 로그인으로 안내한다(US4).

**기술 방향**: 단일 서버(Spring Boot)가 규칙을 모두 검사한다. 로그인 상태는 서버 세션(PostgreSQL 저장)과 쿠키로 유지하고, 이메일 인증에 쓰는 짧은 값은 Redis에 시간제한을 걸어 둔다. 비밀번호는 BCrypt 해시로만 저장한다. 인증 메일은 SMTP로 보낸다.

### Source Code

코드는 이 문서 저장소가 아니라 **프로젝트 저장소**에 만든다. 폴더 이름은 프로젝트 저장소가 정해지면 맞추고, 안의 구조는 `기술스택-아키텍처.md` 3.A의 **기능별 모듈**(회원·인증은 `user`)을 따른다. (모두 `가안`)

```text
서버 (Spring Boot, 단일 서버)
└── user 모듈 (회원·인증)
    ├── 컨트롤러   # contracts/auth-api.md의 주소들
    ├── 서비스     # 가입, 이메일 인증, 로그인과 잠금 규칙

    ├── 메일       # 인증 메일 만들기와 보내기
    └── 설정       # 보안, 세션, 설정값 읽기

화면 (React + Vite)
└── 가입 화면, 로그인 화면과 로그인 창, 로그인 상태(처음 열 때 GET /api/auth/me)
```

**Structure Decision**: 화면과 서버를 나누는 **웹 애플리케이션** 구조이고, 서버는 기능별 모듈을 가진 **단일 서버**다. (확정: 단일 서버, 가안: 모듈 이름)
