# Data Model: 회원 가입과 로그인

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-10-07

> 명세의 `Key Entities`(회원, 이메일 인증, 로그인 상태)를 **어디에 어떤 모양으로 저장할지** 정리합니다. 모든 내용은 `가안`입니다. 팀 공통 ERD(`users`, `blog`, `category`)와 **맞춰야 하는 부분**은 `⚠`로 표시했고, 결정은 [research.md](research.md)의 `D-3`, `D-4`에 있습니다. (2026-10-07에 정했고, **팀 ERD에 반영해 달라고 요청해야 합니다.**)
> ERD 문법에는 MySQL(`COMMENT`)과 PostgreSQL(`TIMESTAMPTZ`)이 섞여 있습니다. 실제 DDL은 구현할 때 PostgreSQL 기준으로 정리합니다.

## 한눈에 보기

| 명세의 개념 | 저장 위치 | 오래 남나 | 종류 |
|---|---|---|---|
| 회원 | PostgreSQL `users` 표 | 영구 | 팀 ERD에 있음 (⚠ 칸 추가 필요) |
| 가입이 함께 만드는 블로그와 `미분류` 분류 | PostgreSQL `blog`, `category` 표 | 영구 | 팀 ERD에 있음 (`003`이 규칙을 가짐) |
| 이메일 인증 | Redis (키 5종) | 10분 ~ 24시간 후 자동 삭제 | 새로 정의 |
| 로그인 상태 | PostgreSQL 세션 표 (프레임워크가 만듦) | 마지막 사용 후 7일, 최대 30일 | 팀 ERD 밖 |

## 1. 회원 — PostgreSQL `users`

| 칸 | 팀 ERD의 지금 모양 | 이 기능이 필요한 것 | 관련 FR |
|---|---|---|---|
| `users_id` | BIGINT, 자동 증가, 기본키 | 그대로 | — |
| `email` | VARCHAR(255), NOT NULL, UNIQUE | **소문자로 맞춰 저장**한다. ⚠ 탈퇴하지 않은 회원에게만 중복 불가(`D-4`) | FR-003, FR-004, FR-023 |
| `password` | VARCHAR(255), NOT NULL, `BCrypt 해시` | BCrypt 결과를 저장한다. 원문은 어디에도 남기지 않는다 | FR-010 |
| `nickname` | VARCHAR(20), NOT NULL, UNIQUE | 길이 규칙 2~10자는 **서버가 검사**한다(칸 크기는 넉넉해도 된다). ⚠ 대소문자 무시 중복 불가가 필요(`D-4`) | FR-005 |
| `intro` | VARCHAR(100), NULL | `002`에서 쓴다. 가입 때는 비워 둔다 | — |
| `created_at` | TIMESTAMPTZ, NOT NULL | 가입 시각 | (Key Entities) |
| `deleted_at` | TIMESTAMPTZ, NULL (탈퇴 표시) | `002`에서 쓴다. 로그인과 중복 검사는 `deleted_at`이 비어 있는 회원만 대상으로 한다 | FR-004 |
| `failed_login_count` | **없음 ⚠** | INT, NOT NULL, 기본 0. **연속 로그인 실패 횟수** (`D-3` 결정) | FR-027, FR-028 |
| `locked_until` | **없음 ⚠** | TIMESTAMPTZ, NULL. **잠금이 풀리는 시각** (`D-3` 결정) | FR-027, FR-028 |

### 중복 불가 규칙 (⚠ `D-4` 결정)

- 이메일: 소문자로 맞춘 값이 같은 **탈퇴하지 않은** 회원은 둘 이상 없다.
- 닉네임: 소문자로 바꾼 값이 같은 **탈퇴하지 않은** 회원은 둘 이상 없다.
- 이 규칙은 **DB가 마지막 방어선**으로 지킨다. 서버 코드의 사전 검사(FR-004)에 빈틈이 있어도 중복 계정은 생기지 않는다. (SC-002)

### 검증 규칙 (서버가 검사, FR-034)

| 입력 | 규칙 | FR |
|---|---|---|
| 이메일 | 이메일 형식. 앞뒤 공백 제거, 소문자로 변환 | FR-003 |
| 닉네임 | 2~10자, 한글·영문·숫자만. 공백·특수문자 불가 | FR-005 |
| 비밀번호 | 영문·숫자·특수문자 각 1개 이상, 8~20자, 공백 불가. 허용 특수문자 `! @ # $ % ^ & * ( ) _ + - =` | FR-006 |
| 비밀번호 확인 | 비밀번호와 같을 것 | FR-007 |
| 인증번호 | 영문 대문자+숫자 6자리 (`O`, `0`, `I`, `1` 없음) | FR-014 |

값의 길이와 횟수는 [plan.md](plan.md)의 `설정값 목록`에서 바꿀 수 있게 한다. (NF-08)

### 로그인 잠금의 상태 변화 (FR-027 ~ FR-029)

```
정상(실패 0회) ──틀림──▶ 실패 1~4회 ──5번째 틀림──▶ 잠김(locked_until = 지금 + 10분)
      ▲                      │                          │
      └──── 로그인 성공 ──────┘                          │ 10분이 지난 뒤 다음 로그인 시도 때
      ▲                                                  │ "잠금 시각이 지났다"를 확인하고
      └──────────── 실패 횟수를 0으로 되돌림 ◀────────────┘ 정상으로 돌아감
```

- **잠금 풀기는 따로 돌리는 작업이 필요 없다.** 다음 로그인 시도 때 `locked_until`이 지났는지만 확인하면 된다. (`@Scheduled` 불필요)
- 잠겨 있는 동안은 비밀번호를 비교하지 않고 거절한다. 이 동안의 시도는 잠금 시간을 늘리지 않는다. (명세에 없어서 `가안`으로 해석)
- 가입되지 않은 이메일은 기록하지 않는다. (US3-4, CF-02-9)
- 실패 횟수 올리기는 **한 번에 한 건씩 정확히** 올라가야 한다. 동시에 여러 번 시도해도 5회를 넘기 전에 잠기도록, 읽고 쓰는 대신 DB에서 바로 `+1` 하는 방식을 쓴다.
- `002`의 비밀번호 변경·탈퇴에서 틀린 비밀번호도 같은 횟수에 합산한다. (상세/01) 이 부분은 `002`의 plan에서 다룬다.

## 2. 가입이 함께 만드는 것 — `blog`, `category` (규칙은 `003`)

FR-011은 "가입을 마치면 내 블로그가 함께 만들어진다"고 한다. 이 기능은 **한 번의 묶음 작업**으로 아래를 만든다. 하나라도 실패하면 모두 취소한다.

| 만드는 것 | 값 | 출처 |
|---|---|---|
| `users` 한 줄 | 위 1번 | FR-011 |
| `blog` 한 줄 | 이름 `{닉네임}의 블로그`, 소개 비어 있음 | `003` FR-002 |
| `category` 한 줄 | 이름 `미분류`, 기본 분류 표시(`is_default`)가 참 | `003` FR-003 |

- 닉네임은 10자까지이므로 `{닉네임}의 블로그`는 15자 이내이고, `blog.name`(30자)에 들어간다.
- `blog`, `category`의 칸과 규칙은 `003`의 plan에서 정한다. 이 기능은 **가입 때 한 번 만든다**는 것만 책임진다.

## 3. 이메일 인증 — Redis

> Redis는 "10분 뒤에 지워 줘"를 걸 수 있는 임시 저장소입니다. 아래 값은 **잃어도 사용자가 다시 하면 되는 값**이라 Redis에 둡니다. 이메일은 항상 **소문자로 맞춘 값**을 이름표로 씁니다.
> 키 이름은 `가안`입니다. Redis에 "인증번호 외의 값"을 두는 것이 헌법에 맞는지는 [research.md의 D-6](research.md)에서 확인을 요청합니다.

| 키 (가안) | 값 | 만료 | 만드는 때 | 지우는 때 | FR |
|---|---|---|---|---|---|
| `emailauth:code:{email}` | 인증번호 | **10분** | 인증번호 받기 성공 (이미 있으면 새 번호로 **덮어써서** 이전 번호가 무효가 된다) | 맞게 입력, 5회 틀림, 이메일 변경, 메일 발송 실패 | FR-014 ~ 017, 019 |
| `emailauth:fail:{email}` | 틀린 횟수 | 인증번호와 같은 10분 | 처음 틀릴 때 | 새 번호를 보낼 때 0으로 되돌림, 맞게 입력 | FR-019 |
| `emailauth:cooldown:{email}` | 표시만 | **60초** | 메일 발송에 **성공한 뒤** | 저절로 | FR-018 |
| `emailauth:daily:{email}` | 하루 보낸 횟수 | **24시간** (첫 발송부터) | 메일 발송에 **성공한 뒤** +1 | 저절로 | FR-018 |
| `emailauth:verified:{email}` | 인증됨 표시 | **30분** | 인증번호가 맞았을 때 | 가입 성공, 이메일 변경, 저절로 | FR-015, FR-021, FR-022 |

해석한 것 (명세에 없어서 `가안`):

- **"하루 5번"** 은 달력 날짜가 아니라 **첫 발송으로부터 24시간**으로 센다. (상세/01의 `만료 24시간`을 따름)
- 메일 발송이 **실패하면** 1분·하루 횟수에 넣지 않고 인증번호도 지운다. 그래야 "다시 받기를 누를 수 있다"(FR-020)가 지켜진다. (`D-2`)
- 인증번호 확인 요청이 **번호 없이** 오면(만료된 경우) "인증번호가 만료되었습니다"로 답한다. 번호가 있는데 틀리면 "인증번호가 올바르지 않습니다"다. 5회째 틀리면 "인증번호 입력 횟수를 초과했습니다"다.

### 이메일 인증의 상태 변화

```
(없음) ──인증번호 받기──▶ 발송됨 ──맞게 입력──▶ 인증됨 ──가입 성공──▶ 끝 (표시 삭제)
                          │  │                    │  │
                          │  └ 5회 틀림 → 번호 폐기  │  └ 이메일 변경 → (없음)
                          └ 10분 경과 → 만료          └ 30분 경과 → 인증 만료 (다시 인증)
```

## 4. 로그인 상태 — PostgreSQL 세션 표

- 세션 표는 Spring Session JDBC가 정해 둔 모양(세션 본체 표 하나와 속성 표 하나)으로 만든다. 정확한 이름과 칸, 자동으로 만드는 설정은 쓰는 버전을 따른다. (구현 때 확인) 팀 ERD에는 넣지 않는다.
- **회원을 찾는 이름표(principal)** 에 회원 식별값(`users_id`)을 넣어서, 회원 기준으로 세션을 찾아 지울 수 있게 한다. 이것이 `002`의 "비밀번호를 바꾸면 다른 기기 로그아웃"(상세/01, 확정)의 바탕이다.
- 세션에는 **로그인한 회원의 식별값만** 넣는다. 비밀번호나 해시는 넣지 않는다. (FR-010)
- 세션을 만든 시각이 남으므로 **"로그인한 때부터 30일"**(FR-030)을 확인할 수 있다.
- 만료된 세션은 프레임워크가 주기적으로 정리한다. (기본 동작인지 구현 때 확인)

## 5. 이 기능이 읽거나 쓰는 표 요약

| 표 | 읽기 | 쓰기 | 언제 |
|---|---|---|---|
| `users` | 이메일·닉네임 중복 확인, 로그인 | 가입, 실패 횟수와 잠금 시각 | 인증번호 받기, 가입, 로그인 |
| `blog`, `category` | — | 가입 때 한 줄씩 | 가입 |
| 세션 표 | 모든 로그인 요청 | 로그인, 로그아웃, 사용할 때마다 마지막 사용 시각 | 로그인 이후 |
| Redis | 인증번호 확인, 횟수 제한, 인증됨 확인 | 위 3번의 키 | 인증번호 받기, 확인, 가입 |
