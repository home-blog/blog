# 개발 환경 한 장

글결을 내 컴퓨터에서 켜고, 고치고, 확인하는 데 필요한 것을 한 장에 모았습니다.

## 1. 준비물

| 무엇 | 버전 | 확인 |
|---|---|---|
| Java (JDK) | 21 | `java -version` |
| Maven | 3.9 이상 | `mvn -v` |
| Node.js | 22 (22.22.2 이상 권장) | `node -v` |
| Docker | Docker Desktop 또는 Docker Engine + Compose | `docker compose version` |
| IntelliJ IDEA | 선택. 실행 설정(`.run/`)이 들어 있다 | |

## 2. 처음 한 번

```bash
git clone https://github.com/home-blog/blog && cd blog
cp .env.example .env          # 접속 정보 견본. git에 올라가지 않는다
```

`.env` 하나를 docker compose와 서버(개발 설정)가 같이 읽습니다. 값은 개발 전용입니다.

## 3. 켜기

| 순서 | 명령 | 주소 |
|---|---|---|
| 1. DB·Redis·MinIO | `docker compose up -d --wait` | PostgreSQL 5432, Redis 6379, MinIO 9000(관리 화면 http://localhost:9001) |
| 2. 서버 | `cd backend && mvn spring-boot:run` | http://localhost:8080 (상태 `/actuator/health`) |
| 3. 화면 | `cd frontend && npm install && npm run dev` | **http://localhost:5173** ← 브라우저는 여기로 |

- IntelliJ: 오른쪽 위 실행 목록에서 `1. DB·Redis·MinIO 켜기` → `MyBlog 전체 (서버+화면)`.
- 화면(5173)은 `/api`, `/oauth2`, RSS·사이트 지도 같은 요청을 서버(8080)로 넘깁니다(`frontend/vite.config.ts`). 그래서 브라우저는 5173 하나만 열면 됩니다.
- 모든 포트는 `127.0.0.1`에만 열려 있어 같은 와이파이의 다른 기기에서는 보이지 않습니다.
- 끄기: 서버·화면은 `Ctrl + C`, DB 등은 `docker compose stop`. 데이터까지 지우려면 `docker compose down -v`.

## 4. 개발 설정에서 다른 점

| 무엇 | 개발 | 배포 |
|---|---|---|
| 예시 데이터 | 처음 켤 때 블로거 12명, 글 108개를 넣는다 (`.env`의 `DEMO_SEED=false`로 끔) | Actions `예시 데이터` 작업으로만 |
| 인증 메일 | 보내지 않고 서버 로그의 `[개발용 메일]` 줄에 인증번호를 찍는다 | 서비스 전용 Gmail로 보낸다 |
| API 문서 | http://localhost:8080/swagger-ui.html | 꺼 둔다 |
| 로그인 쿠키 | http에서도 보낸다 | https에서만 (`SESSION_COOKIE_SECURE=true`) |

- 진짜 메일을 받아 보려면 `.env`에서 `MAIL_SENDER=smtp`와 `MAIL_HOST`, `MAIL_USERNAME`, `MAIL_PASSWORD`를 채우고 서버를 다시 켭니다. 적는 법은 `.env.example`에 있습니다.
- 소셜 로그인 버튼은 `.env`에 그 회사의 `SOCIAL_*_CLIENT_ID`·`SECRET`이 있을 때만 보입니다. 콜백 주소는 `http://localhost:5173/login/oauth2/code/{github|google|kakao|naver}`입니다. 앱 등록 순서는 [deploy/README.md](../deploy/README.md).

## 5. 확인하기 (push 전에)

```bash
cd backend && mvn verify                                   # 서버 테스트 + 커버리지 (DB·Redis가 떠 있어야 한다)
cd frontend && npm ci && npm run lint && npm test && npm run build
```

| 더 보고 싶을 때 | 명령 | 결과 |
|---|---|---|
| 서버 커버리지 | `mvn verify` 뒤 | `backend/target/site/jacoco/index.html` |
| 화면 커버리지 | `npm run test:coverage` | `frontend/coverage/` |
| REST Docs | `cd backend && mvn -Pdocs verify` | `backend/target/generated-docs/index.html` |
| 테스트 하나만 | `mvn -Dtest=SecurityAndCsrfTest test` / `npx vitest run src/auth` | |
| 화면 테스트를 고치면서 | `npx vitest` (저장할 때마다 다시 돈다) | |

## 6. 자주 막히는 것

| 증상 | 까닭과 해결 |
|---|---|
| 서버가 `Connection to localhost:5432 refused`로 안 켜짐 | DB가 꺼져 있다. `docker compose up -d --wait` |
| `password authentication failed` | DB 비밀번호는 DB를 처음 만들 때 정해진다. `.env`의 `DB_PASSWORD`를 바꿨다면 `docker compose down -v`로 DB를 지우고 다시 켠다(데이터도 지워진다) |
| `Port 8080(또는 5173) was already in use` | 이미 켠 서버·화면이 있다. 그 창을 끄거나 `lsof -i :8080`으로 찾아 끈다 |
| Flyway `checksum mismatch` | 이미 적용된 `V*.sql` 파일을 고쳤다. 고친 내용은 새 번호 파일로 만들고, 원래 파일은 되돌린다 |
| 화면에서 모든 요청이 403 | CSRF 토큰이 오래됐다. 새로고침하거나 로그인을 다시 한다 |
| 인증번호 메일이 안 옴 | 개발 설정은 메일 대신 서버 로그에 찍는다. 로그에서 `[개발용 메일]`을 찾는다 |
| 화면에 새 코드가 안 보임 | `develop`을 받은 뒤에는 서버를 다시 켜야 한다(화면은 저절로 바뀐다) |
| 테스트가 Docker 없이 실패 | 서버 테스트는 진짜 PostgreSQL·Redis로 돈다. 3절의 1번을 먼저 |
