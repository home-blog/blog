# 배포 참고: 팀원의 서버 배포 설명서 요약

> 원본: 팀원(원일)이 정리한 `서버 배포 설명서`(2026-10-08, PDF 4쪽). 사용자가 2026-10-08에 "배포할 때 참고하라"며 공유했다.
> **아직 우리 프로젝트의 배포 방식으로 정한 것은 아니다** (`specs/001` research D-5 `미정`). 배포를 시작할 때 이 문서와 아래 `우리 프로젝트와 다른 점`을 보고 사용자와 정한다.
> 비밀 값(비밀번호, 주소)은 이 문서에 적지 않는다. GitHub Secrets에만 넣는다.

## 설명서의 순서

| 단계 | 내용 |
|---|---|
| 1 | 프로젝트 **소스코드와 문서 폴더를 분리**한다 (배포는 소스코드 저장소에서) |
| 2 | 소스코드 저장소의 GitHub **Settings → Secrets and variables → Actions → Repository secrets**에 값을 넣는다. `.env`에 있던 API 키 같은 것도 여기에 넣는다 |
| 3 | 터미널에서 실습 서버에 SSH로 접속한다 (처음 물으면 `yes`) |
| 4 | Claude에게 "GitHub Actions로 **도커 이미지를 만들고**, SSH로 접속해 **그 이미지를 실행하는 셸 스크립트**"를 만들어 달라고 한다. 이미지가 쓸 포트는 **내 포트 범위의 첫 번호**. 오류가 나면 GitHub의 알림(inbox)에 온 오류를 그대로 Claude에게 준다. 시간이 오래 걸린다 |
| 5 | 기다리는 동안 서버에서 `~/nginx/<도메인>.conf`를 만든다: `server_name`을 내 도메인으로, `proxy_pass`의 포트를 내 포트로. `cat`으로 확인한 뒤 강사에게 적용을 요청한다 |

### 2단계에 넣는 Secrets 이름

| 묶음 | 이름 | 넣을 값 |
|---|---|---|
| DB (Crowfoot에서 발급받은 DB) | `DB_ADDRESS` | 주소에서 뒤의 `:숫자`를 뺀 것 |
| | `DB_PORT` | 주소 뒤의 숫자 |
| | `DB_NAME` | 데이터베이스 이름 |
| | `DB_USERNAME` | 계정 (설명서 표에는 `DB_NAME`이 두 번 나오지만 캡처 화면은 `DB_USERNAME`) |
| | `DB_PASSWORD` | 비밀번호 |
| | `DB_SCHEMA` | PostgreSQL만: Crowfoot 스키마 탭의 스키마 |
| SSH (aip 공통 인프라 문서) | `SSH_ADDRESS` | 학교 안이면 내부망 주소, 밖이면 외부 주소 |
| | `SSH_ID` | 내 학번 아이디 (`AIGJ_01_012`) |
| | `SSH_PASSWORD` | 공용 비밀번호 |
| | `SSH_PORT` | `8822` |

## 우리 프로젝트와 다른 점 (배포 때 정할 것)

| 항목 | 설명서 | 우리 프로젝트 지금 | 정할 것 |
|---|---|---|---|
| 저장소 | 소스코드와 문서를 나눈다 | `home-blog/myblog` 한 저장소에 문서(`docs/`, `specs/`)와 코드(`backend/`, `frontend/`)가 같이 있다. CLAUDE.md: 마지막에 코드를 `AIP-1/blog-basic-AIGJ_01_012-blog`로 옮긴다 | 배포 전에 코드를 AIP-1 저장소로 옮길지, 이 저장소에서 바로 배포할지 |
| DB | Crowfoot에서 발급받은 DB를 운영 DB로 쓴다 | Crowfoot DB(`cf_u6_d2`)는 **ERD 확인용**으로만 쓰기로 했다 (CLAUDE.md 5) | 운영 DB를 Crowfoot DB로 할지, 실습 서버에 PostgreSQL 컨테이너(내 포트 8415 가안)를 띄울지 |
| Redis | 없음 | 이메일 인증에 꼭 필요하다 | 아카데미 Redis(DB 번호 12, 키 앞 `myblog:`) 또는 내 컨테이너(8416 가안) |
| 비밀 값 | DB, SSH | 더 필요하다: `VERIFICATION_SECRET`(32자 이상, 없으면 서버가 안 켜짐), 메일(SMTP, `001` D-1 미정), Redis | Secrets 목록에 더한다 |
| 서버 이미지 | 도커 이미지 하나 | 서버(Spring)와 화면(React) 두 개. 화면은 빌드한 파일을 서버가 함께 내보내거나 Nginx 컨테이너로 | 한 이미지로 묶을지 |
| HTTPS | 언급 없음 | 배포에서 쿠키 `Secure`를 켠다 (`001` T041, NF-10) | 강사 Nginx가 HTTPS를 받는지 확인 |
