여러 사람이 각자 블로그를 쓰고 한곳에서 둘러보는 멀티 블로그 서비스 *글결* 의 서버 API입니다 (릴리스 {release}).

이 문서의 요청과 응답은 *테스트가 실제로 보내고 받은 것* 입니다 (Spring REST Docs, `ApiDocumentationTest`).
응답에 문서에 없는 칸이 생기거나 적은 칸이 사라지면 테스트가 실패하므로, 문서가 코드와 어긋나지 않습니다.
전체 API 목록(88개)은 개발 서버의 Swagger 화면(`/swagger-ui.html`)에 있고, 이 문서는 주요 흐름을 예시와 함께 설명합니다.

[[overview]]
== 공통 약속

=== 주소와 버전
모든 주소는 `/api/v1/…` 입니다. API 버전은 릴리스 번호와 따로 가서, 칸을 더하는 변경은 v1 그대로 두고 칸을 빼거나 뜻을 바꿀 때만 v2를 엽니다.

=== 로그인 (서버 세션)
로그인하면 세션 쿠키 `SESSION` 이 생기고, 세션은 PostgreSQL에 저장합니다 (JWT를 쓰지 않습니다).
정한 시간(`auth.session.idle-timeout`) 동안 쓰지 않으면 끝납니다. 로그인이 필요한 API를 로그인 없이 부르면 `401` 입니다.

=== CSRF
GET이 아닌 요청은 쿠키 `XSRF-TOKEN` 의 값을 머리글 `X-XSRF-TOKEN` 에 실어 보냅니다.
토큰은 <<auth-csrf>> 로 받고, 로그인하면 바뀌므로 로그인한 뒤 다시 받습니다.

=== 오류
모든 오류는 같은 모양입니다. 볼 권한이 없는 글·댓글·이미지는 있는지조차 알 수 없도록 없는 것과 같은 `404` 로 답합니다.

[cols="1,3"]
|===
| 상태 | 뜻

| `400` | 입력값이 규칙에 맞지 않음 (`fieldErrors` 에 칸마다 까닭)
| `401` | 로그인이 필요함
| `403` | CSRF 토큰이 없거나 틀림, 또는 할 수 없는 일
| `404` | 없거나 볼 수 없음
| `409` | 이미 있음 (예: 같은 이름의 분류)
| `429` | 너무 자주 보냄 (`retryAfterSeconds` 뒤에 다시)
|===

[[ai]]
== AI
빨간 펜 교정과 비슷한 글입니다. 빨간 펜은 기본이 서버 안의 무료 맞춤법 규칙 교정(`GET /api/v1/me/proofread` 의 `mode: rules`)이고, Claude 열쇠가 있으면 AI 교정(`mode: ai`)입니다. 비슷한 글은 Voyage 또는 내 서버의 Ollama(bge-m3) 임베딩으로 뜻이 가까운 글을, 둘 다 없으면 태그·주제가 겹치는 글을 보여 줍니다.

[[proofread]]
=== 빨간 펜 교정
교정기가 준 고칠 곳을 서버가 본문에서 다시 찾아, 본문에 실제로 있는 곳만 돌려줍니다. 코드 블록·인라인 코드·링크 주소 안은 고치지 않습니다.
AI 교정은 하루 20번까지이고(넘으면 429), 같은 본문은 앞 결과를 다시 써서 횟수에 넣지 않습니다. AI가 실패하면 503이고 횟수는 그대로입니다. 규칙 교정은 횟수를 세지 않습니다.
아래 예시는 AI 교정입니다.

받아 보는 블로그의 새 글은 `GET /api/v1/me/subscriptions/feed?page=`, 받아 보는 블로그 목록은 `GET /api/v1/me/subscriptions`입니다.

operation::subscription-put[snippets='path-parameters,request-headers,request-fields,http-request,http-response,response-fields']

[[notifications]]
=== 우편함
새 원고 소식은 글이 공개 분류의 공개 글로 **처음** 저장될 때 한 번만 옵니다. 소식은 글 저장이 끝난 뒤 따로 만들어집니다.
안 읽은 수만은 `GET /api/v1/me/notifications/unread-count`, 읽음은 `POST /api/v1/me/notifications/{id}/read`, 모두 읽음은 `POST /api/v1/me/notifications/read-all`(모두 204)입니다.
원고 편지의 그만 받기는 `POST /api/v1/newsletter/unsubscribe` `{ "token" }`(로그인 없이, 잘못된 값 400)입니다.

operation::board-list[snippets='query-parameters,http-request,http-response,response-fields']

[[board-write]]
=== 글쓰기
로그인이 필요합니다. 같은 회원은 1분 간격으로만 올립니다(429 `BOARD_POST_TOO_FAST`). 고치기는 쓴 사람만 `PUT` 같은 주소(남의 글 403), 지우기는 쓴 사람과 관리자가 `DELETE /api/v1/board/posts/{boardPostId}`(댓글도 함께)입니다.
댓글은 `POST /api/v1/board/posts/{boardPostId}/comments` `{ "content" }`(1~1,000자, 5초 간격), 지우기는 `DELETE /api/v1/board/comments/{boardCommentId}`입니다.

operation::board-write[snippets='request-headers,request-fields,http-request,http-response,response-fields']

[[board-accept]]
=== 채택
물음을 쓴 사람만(403), 이 물음에 다른 사람이 단 댓글만(400 `BOARD_ACCEPT_INVALID`) 채택합니다. 다른 댓글을 고르면 바뀌고, 거두기는 `DELETE` 같은 주소입니다. 채택된 댓글은 쓴 사람이 지울 수 없습니다(409 `BOARD_COMMENT_ACCEPTED`). 채택하면 댓글 쓴 사람의 우편함에 소식이 갑니다.

operation::board-accept[snippets='path-parameters,request-headers,request-fields,http-request,http-response,response-fields']

[[editorial-take-down]]
=== 내림
대기 신고를 모두 닫고 글을 비공개로 돌려 잠급니다. 잠긴 글은 주인이 공개로 바꿀 수 없습니다(400 `POST_LOCKED_BY_EDITOR`). 닫을 신고가 없으면 409 `REPORT_ALREADY_RESOLVED`.
반려는 `POST …/dismiss`, 잠금 풀기는 `POST …/unlock`, 글마당 글 지우기는 `POST /api/v1/editorial/board/{id}/remove` `{ "reason" }`입니다. 글마당 신고는 `POST /api/v1/board/posts/{id}/reports`(블로그 글 신고와 같은 규칙)입니다.

[[ai-connect]]
== AI 비서 연결 (MCP)

마이페이지에서 만든 **개인 열쇠**로 Claude 같은 AI 비서가 `POST /api/v1/mcp`(MCP Streamable HTTP, 상태 없음, JSON 한 번에 답)에 붙습니다.
도구는 `search_posts`(글 찾기), `search_passages`(단락 찾기 + 출처), `read_post`, `list_my_posts`, `my_blog_stats`, `save_draft`(초안 열쇠만, 발행하지 않음)입니다.
열쇠마다 1분에 60번까지(넘으면 429와 JSON-RPC 오류 `-32000`), 다른 사이트의 브라우저 요청(Origin)은 403입니다.

== 방명록
블로그에 들른 회원이 우표를 붙인 엽서를 남기고, 블로그 주인이 답장합니다. 비밀 엽서는 쓴 사람과 주인만 읽고, 남에게는 우표와 날짜만 보이는 봉한 엽서(`sealed`)로 갑니다 (0.16.0).

[[guestbook-write]]
=== 엽서 남기기
로그인이 필요합니다. 블로그 주인은 자기 방명록에 쓰지 못합니다(403 `GUESTBOOK_OWN_BLOG`). 같은 회원은 30초 간격으로만(429 `GUESTBOOK_TOO_FREQUENT`), 한 블로그에 하루 3장까지(429 `GUESTBOOK_DAILY_LIMIT`) 남깁니다.
엽서를 남기면 주인의 우편함에 `guestbook` 소식이 갑니다. 지우기는 쓴 사람과 주인이 `DELETE /api/v1/guestbook/{entryId}`(204)입니다.
답장은 주인만 `PUT /api/v1/guestbook/{entryId}/reply` `{ "body" }`(쓰기·고치기, 처음 쓸 때만 쓴 사람에게 `gb_reply` 소식), 지우기는 `DELETE` 같은 주소입니다. 주인이 아니면 404 `GUESTBOOK_ENTRY_NOT_FOUND`.

operation::guestbook-write[snippets='path-parameters,request-headers,request-fields,http-request,http-response,response-fields']

== AI 앱 연결 (OAuth, Claude 앱 커넥터)
Claude 앱의 **커스텀 커넥터**처럼 열쇠 칸이 없는 앱은 OAuth 2.1로 붙습니다 (0.17.0). 앱은 MCP 주소의 401 `WWW-Authenticate: Bearer resource_metadata="…"`를 보고
메타데이터를 읽은 뒤, 스스로 등록하고(동적 등록), 회원의 브라우저를 글결 **위임장**(`/connect/authorize`)으로 보냅니다.
회원이 허락하면 허락 코드를 PKCE(`S256`)와 함께 출입증(`go_…`, 1시간)·갱신 토큰(`gr_…`, 30일)으로 바꿉니다.
갱신 토큰은 쓸 때마다 바뀌고, 몇 대 전 것이든 이미 바뀐 갱신 토큰이나 이미 쓴 허락 코드를 같은 앱이 다시 보내면 그 연결을 끊습니다(바로 전 갱신 토큰은 바뀐 지 60초 안이면 거절만). 오류는 RFC 6749 모양 `{ "error", "error_description" }`입니다.

[[oauth-authorize]]
=== 인가
모르는 앱이나 등록하지 않은 돌아갈 주소면 앱으로 돌려보내지 않고 `/connect/authorize?error=invalid_client`로 보냅니다.
앱과 돌아갈 주소를 확인한 뒤의 잘못(범위, PKCE 등)도 앱으로 바로 보내지 않고 `/connect/authorize?error=…&back=…` 오류 화면으로 보냅니다.
오류 화면은 `GET /api/v1/oauth/errors/{errorId}`(로그인 없이, 10분)로 서버가 만든 돌아갈 주소(`error`·`state`·`iss`를 붙인 것)를 읽고, 회원이 "앱으로 돌아가기"를 눌러야 앱으로 갑니다.
맞으면 `/connect/authorize?request=…`(위임장)으로 보냅니다.

operation::oauth-authorize[snippets='query-parameters,http-request,http-response']
